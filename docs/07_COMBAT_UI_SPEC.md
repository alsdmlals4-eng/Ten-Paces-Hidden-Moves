## 1. UI 목표

플레이어가 **상대와의 거리, 자원, 현재 묶음, 잠금 여부, 전조, 행동 종류, 합·방어·회피·필중, 효과·중단·잔여타**를 오독 없이 읽을 수 있어야 한다. UI는 전투 계산을 새로 만들지 않고 현재 전투 정본의 결정론적 판정만 표현한다.

`예상`이라는 말은 현재 공개 정보로 확정 가능한 결정론적 결과를 뜻한다. 프로젝트에는 `예상 명중률` 또는 `% 명중률` 시스템이 없다.

## 2. 화면 구조

- 준비 화면은 상단 약 20%, 정면 결투 중단 약 50%, 계획·선택 하단 약 30%의 독립 표면으로 분리한다. 하단은 풍경의 연장이 아니라 별도 수묵·종이 UI surface다.
- 상단: 양측의 독립 상태 HUD 프레임. 체력·기력·내력과 `현재/최대`는 플레이어만 숫자로 보이며, 적은 같은 게이지·기세 5칸·상태칸 구조를 쓰되 자원 숫자를 보이지 않는다.
- 중앙: 같은 바닥선에 접지한 두 전투원의 원거리 정면 대치 + 중앙 `거리 N` 배지. 거리0은 `[밀착]`.
- 하단 상부: 현재 묶음 하나만 보이는 3/3/4 행동 슬롯과 단일 `행동 실행` CTA.
- 하단: `기본 / 무공 / 절초` 행동 선택과 하나의 공통 5×2 카드 격자. 세 출처 모두 승인된 카드 삽화를 같은 카드 shell 안에서 사용한다.
- 하단 우측: 선택·hover한 행동의 상세 프레임과 상대 관찰의 유형 전용 프레임. 관찰은 기술명·피해·방향·비용을 표시하지 않는다.
- 전투 공개 화면: 상단과 중단만 남기고, 하단 행동계획·카드·상세·관찰 선택 표면은 숨긴다. 한 수의 행동 호출·결과·모션을 끝낸 뒤에만 다음 수로 진행한다.
- 기본 절초 목록 3종은 시작부터 표시하고, 무공 10성 절초는 해금 뒤 같은 목록에 추가한다.

### 2.1 거리 표현

논리 전장은 10칸 규칙을 유지하지만 기본 전투 화면에 1~10 번호 발판 칸을 상시 그리지 않는다. 플레이어는 두 인물의 상대적 간격과 `거리 N`으로 거리를 읽는다.

```text
검객 A  ─────────  거리 2  ─────────  검객 B
```

전투 시작 공개 거리는 `2`다.

```text
거리 2 → 시작
거리 1 → 근접
거리 0 → [밀착]
```

현재 Godot 런타임의 플레이어4/상대7 시작 좌표는 `IMPLEMENTED_LEGACY`다. 확정된 구현 방향은 HUD·접근성 이름·전투 기록까지 시작 공개 거리 `2`를 도메인 상태와 동일하게 표현하는 것이다. 새 절대 좌표는 Build 승인 뒤 단일 implementation binding에서 경계·점유·회귀 검증과 함께 확정한다.

## 3. 시각 자산

현재 수묵 자산 계보와 폴백 도형·텍스트를 유지한다. 자산이 없어도 핵심 정보를 읽을 수 있어야 한다.

- 장식보다 정보 위계가 우선이다.
- 번호 발판 줄을 장식 요소로 되살리지 않는다.
- 거리 배지는 색만이 아니라 텍스트 `거리 N`으로 읽힌다.
- 현재 생성 시안은 기획 참고일 뿐 제품 자산으로 자동 승격하지 않는다.
- 사용자가 현재 이미지 생성을 중단했으므로 추가 exploration 생성은 재승인 전 진행하지 않는다.

## 4. 상단 HUD

- 현재/최대 자원과 확정 가능한 변화량을 구분한다.
- 방어도는 누적·적용을 숫자로 표시한다.
- 회피는 남은 횟수와 유효 수 범위를 표시한다.
- `[강건]`은 “피해 방지”가 아니라 “다음 중단 1회 방지”로 설명한다.
- `[강화]`는 현재 승인된 다음 행동 강화 내용을 설명한다.
- `[기절]`은 승인 태그가 아니므로 표시하지 않는다.

## 5. 행동 슬롯

`[전조]`, 실제 실행 행동 종류, `[절초 예약]`, `타격 1/3`, `중단 취소`, `전투 불능 취소`를 구분한다. 다중 슬롯 비용은 첫 전조에서 이미 지불됐음을 보여 준다.

### 5.1 다중 슬롯 표시

2슬롯 행동의 내부 단계는 `[전조] → [실행]`이다. 계획판에서는 최종 실행 수에 실제 행동 종류와 기술명을 표시한다.

예시용 가상 기술 `비연검`:

```text
1수 `[전조]` → 2수 `[공격] 비연검
```

위 `비연검`은 표기 형식 예시일 뿐 제품 콘텐츠 승인 이름이 아니다.

3슬롯 공격 예:

```text
1수 `[전조]` → 2수 `[전조]` → 3수 `[공격] 기술명`
```

다중 슬롯 행동 전체는 하나의 연결 블록이며 일부 슬롯만 독립적으로 제거·이동하지 않는다.

### 5.2 단일 행동 실행 CTA

현재 묶음의 계획이 유효하면 플레이어는 다음 한 조작으로 확정한다.

```text
[행동 실행]
```

별도의 `행동계획 잠금`은 player-facing 버튼/화면이 아니다. 실행 전에는 현재 묶음의 행동 제거·재배치·이동 의도 수정을 허용하고, `행동 실행`을 누르면 유효성 확인 뒤 즉시 전투 공개·해결 애니메이션으로 전환한다. 실행 뒤 해당 묶음은 편집하지 않는다. 적 계획은 `[관찰]` 공개 전에 잠긴다. 포커스 이름과 tooltip은 “현재 행동계획 실행”의 전체 의미를 보존한다. 기존 lock → `N수 실행`은 현재 product runtime의 `IMPLEMENTED_LEGACY`다.

## 6. 카드 본체와 상세 정보 위계

### 6.1 카드 본체 — 항상 표시

- 행동명
- 출처 + 행동 종류
- 슬롯 수
- 실제 자원 비용 또는 `비용 없음`
- 핵심 효과

### 6.2 카드 본체 — 조건부 표시

- 공격 행동에만 `사거리`를 표시한다.
- 비공격 행동에는 `사거리` 항목 자체를 만들지 않는다.
- 실제 조건이 있는 행동에만 `조건`을 표시한다.
- 내부 밸런스 틱은 표시하지 않는다.
- 적용되지 않는 필드를 `-`로 채워 카드 높이를 낭비하지 않는다.

### 6.3 무공·절초 행동 카드 — `COMMON_CARD_SHELL_WITH_APPROVED_ILLUSTRATION`

`TEN-DEC-20260831-ACTION-CARD-ILLUSTRATION-EXTENSION-01`에 따라 보유 무공서와 선택된 무공 기술 목록은 승인된 삽화를 보조 신호로 사용하는 전술 카드다. 무공·절초 선택 카드는 기초와 같은 카드 골격으로 읽는다. 이 범위는 `MartialActionPanel`의 `source: martial_manual`, `source_kind: martial` 기술 선택과 `UltimateActionPanel`의 절초 선택에 적용한다.

- 무공서명·현재 성수, 기술명, 행동 수, 기력/내력 비용, 잠금/해금 성수, 행동 종류/효과 태그를 우선 표시한다.
- 공격일 때만 사거리, 실제 조건이 있을 때만 조건/상세 효과를 표시한다.
- 무공·절초 선택 카드는 승인된 `MARTIAL_AND_ULTIMATE_CARD_ILLUSTRATION_ATLAS_01`의 정해진 region만 보조 삽화로 사용한다. 이름·비용·사거리·효과·잠금은 여전히 UI/data binding이 소유한다.
- 선택·hover·keyboard focus·잠금은 종이 면·테두리·텍스트·accessibility name으로 구분하며 색만으로 전달하지 않는다.
- 기초 카드의 승인 `TEN_BASIC_TECHNIQUE_INK_ATLAS_01`, 전장/대치 인물, 전투 중 `VS` 공개와 필살기 연출은 이 카드 삽화 규칙과 별도의 consumer다.

### 6.4 대상 선택 — 의미 카드

플레이어가 보거나 누르는 대상 선택 surface에는 1~10 타일·좌/우 방향·목적지 번호를 표시하지 않는다. 이동만 `접근 N칸` 또는 `후퇴 N칸` 의미 카드로 확정한다. 공격·반격·절초는 공개된 상대를 자동 대상으로 하므로 별도 방향·노림 선택을 열지 않는다. 10칸 논리 전장과 resolver의 내부 부호·목적지 계산은 호환 경계에만 남기며, 공개 화면은 두 인물과 `거리 N`을 계속 우선한다.

#### 예시 — 이동

```text
[기초] [이동]     1수
이동
비용 없음
[이동] 1
```

`사거리` 행 없음.

#### 예시 — 회피

```text
[기초] [회피]     1수
회피
기력 1
[회피] 1
```

`사거리` 행 없음.

#### 예시 — 관찰

```text
[기초] [관찰]     1수
관찰
비용 없음
[관찰] 1
```

`사거리` 행 없음.

#### 예시 — 속공, 외공4

```text
[기초] [공격]     1수
속공
기력 1
사거리 1
공격 5
```

카드 본체는 현재 계산값을 우선 읽게 할 수 있고, 상세에서 `floor(3 + 외공 × 0.50)` 공식을 확인한다.

### 6.3 상세창

상세창은 적용되는 정보만 확장한다.

- 정확한 공식과 스테이터스 참조
- 대상·선택한 의도
- 전체 효과
- trigger/scope
- 연격·전조·실행·중단 규칙
- 실제 조건
- `[공격]` 행동의 사거리

예: 이동 상세에는 `[이동] 1`과 이동 규칙은 있지만 `사거리`가 없다. 속공 상세에는 `사거리 1`과 피해 공식이 있다.

## 7. `[관찰]` 표시

`[관찰] 1`은 관찰량1을 얻는다. 상대는 먼저 다음 적용 대상 묶음을 잠그고, 그 뒤 축적 관찰량만큼 앞 수부터 **행동 종류만** 공개한다.

현재 공개 종류:

- `[전조]`
- `[이동]`
- `[공격]`
- `[방어]`
- `[회피]`
- `[준비]`
- `[자원]`
- `[관찰]`

기술명·무공서명·정확한 비용·방향·이동 거리·공격 사거리·피해·대상·AI 가중치는 숨긴다.

예: 상대의 실제 잠금이 `비연검(2슬롯) → 이동`이라고 가정한다.

```text
관찰량 0: ?       / ?       / ?
관찰량 1: [전조]  / ?       / ?
관찰량 2: [전조]  / [공격]  / ?
관찰량 3: [전조]  / [공격]  / [이동]
```

관찰량이 현재 묶음보다 많으면 남은 양은 다음 묶음으로 이월한다.

## 8. 합·대응·중단 결과 UI

### 순차 합

각 타격에 원인과 결과를 순서대로 표시한다.

```text
1타: A 8 vs B 5 → A 합 승리 → 차이 원피해3
방어도2 적용 → 체력 피해1
B 중단 → B 2·3타 취소
A 2·3타 → 단독 잔여타
```

### 효과

- `PER_HIT`은 발동한 타격마다 별도 로그.
- `ONCE_PER_ACTION`은 최초 발동 뒤 행동당 1회 소비를 표시.
- `ON_ACTION_START/RESOLVE`, `ON_CLASH_WIN`, `ON_EVADE_SUCCESS`, `ON_HIT/ON_HEALTH_DAMAGE`, `ON_ACTION_END`를 사건 시점과 함께 구분.

### 기세

여러 합을 이겨도 승인된 행동당 획득 상한을 요약한다.

### 필중 스택

- 남은 `[필중]` 스택을 숫자로 표시한다.
- 실제 존재하는 회피를 우회할 때만 `필중 -1` 사건을 표시한다.
- 합 취소·중단·대상 부재·사거리 실패·회피 부재에는 미소비 원인을 로그에 남긴다.

## 9. 결정론적 결과와 금지 표현

프로젝트에는 명중 확률 판정이 없다.

금지:

- `예상 명중률 78%`
- `% 명중률`
- 확률 게이지로 적중 여부 추측
- 승인되지 않은 `[기절]`
- 현행 기초 행동에 없는 임의 카드 `연결`, `기합`

허용:

- `사거리 실패`
- `예측 빗나감`
- `회피 가능/불가`
- `방어도 적용 후 체력 피해 N`
- `적중`이라는 결정론적 사건/트리거

## 10. 입력·접근성

- 명시적 포커스와 키보드·게임패드 동등 입력.
- 색 외에 아이콘·형태·텍스트·로그를 함께 사용.
- `행동 실행`은 포커스와 실행 전/해결 중 상태를 텍스트로 식별하며, 접근성 이름은 현재 행동계획 실행의 전체 의미를 제공한다.
- 모션 감소·빠른 재생·즉시 완료가 결과를 바꾸지 않는다.
- 타격 연출을 건너뛰어도 판정 순서와 원인을 텍스트로 보존한다.
- Windows와 Android에서 동일한 핵심 정보 필드를 유지하고 배치만 반응형으로 바꾼다.

## 11. 성장·지도 PoC UI

- 시작 무공 6개에서 4개 선택.
- 기술 카드에는 현재 승인된 슬롯·실제 자원 비용·핵심 효과를 표시하고 상세에서 성장/공식을 확장한다.
- 전투 후 등급 차원과 공개 적별 과제를 설명.
- 네 구간 경로 노드 위험·보상을 선택 전에 비교.
- 분산 투자와 주요 비무5 전 10성 가능 집중 경로의 예상 수련포인트를 구분하고 가능성을 보장처럼 표시하지 않는다.

## 11.1 보상·재도전 UI

- 주요 비무 보상 선택 화면은 `자유6`, `지정5+자유3`, `문파 무공3성`의 총량과 제한 범위를 비교한다.
- 첫 5전 패배 화면은 실제 원인 1~3개, 전투 직전 복원 범위, 남은 **1회 무료 동일-seed 재도전** `0/1`을 표시한다. CTA는 `다시 비무하기`이며, 첫 패배에서만 활성화한다.
- 무료 재도전 뒤에는 같은 상대·같은 seed·전투 직전 RunState로 돌아가며, 피해·임시 자원·임시 상태·미획득 보상·노드 진행이 복원됨을 설명한다.
- 두 번째 패배에는 재도전 CTA를 비활성화하고 `회차 종료`와 `타이틀로`만 제공한다. 패배 Result에는 보상 선택·Route 이동이 없다.
- `[영구재화]` 비용1/2/3, 잔액, 결제, 잔액 부족은 첫 5전 UI 범위 밖의 `DEFERRED_POST_SLICE_EXTENSION`이다. 이를 현재 Slice의 버튼·텍스트·접근성 이름으로 만들지 않는다.

## 12. UI·UX 에셋 제작 순서

UI·UX는 에셋을 먼저 고르고 화면을 맞추지 않는다.

```text
컨셉·정보 요구 정의
→ 화면·상태별 asset gap map
→ 에셋 스토어·라이브러리 검색
→ 라이선스·스타일·Godot 적합성 평가
→ ADOPT / ADAPT / GENERATE / REJECT / DEFER
→ 부족분만 생성
→ Godot 통합
→ 가독성·접근성·성능·사람 검증
```

현재 사용자의 명시적 지시에 따라 TEN-IMG-001 추가 생성은 `PAUSED_BY_USER`; 채팅 기반 정본 검토를 우선한다.

### 12.1 컨셉 기준

- 수묵 기반 무협 분위기와 현재 자산 계보 유지.
- 장식보다 전투 정보 위계와 판독성 우선.
- 화면·아이콘·VFX가 없어도 텍스트·도형 폴백으로 기능.
- 외부 에셋 때문에 거리·3/3/4·합·중단·필중·관찰 정보 구조를 변경하지 않는다.

### 12.2 검색·평가 기준

에셋 후보마다 출처·제작자·버전·가격·취득일·상업 이용·수정·표기·재배포 조건을 기록한다. Godot 4 import 형식, 해상도, 확장성, 편집 가능성, 스타일 일관성, 접근성, 성능과 파일 크기도 비교한다.

### 12.3 생성 기준

재생성이 다시 승인될 때만 크기·비율·상태·투명 배경·파일 형식·포커스·접근성 폴백을 먼저 명세하고 prompt·원본·편집본·도구 provenance를 기록한다. 생성 결과는 별도 검수 전 `NOT_AN_ASSET`이다.

## 13. 현재 검증 상태

- 새 정보 위계: `CURRENT_APPROVED_PLANNING`.
- Godot 제품 UI 반영: `IMPLEMENTED / MACHINE_VERIFIED`, Windows-visible 준비 화면은 실제 제품 시작 경로에서 관측했다. 잠금 뒤 행동 공개의 인간 판독성·완전한 전투 시퀀스와 Android/접근성 사용자 검증은 별도다.
- 현재 런타임 내부 시작 좌표: `4/6`; 플레이어-facing 공개 시작 거리는 `2`.
