# 십보강호 전투 UI·아트 명세

> 책임: 최신 전투 규칙의 입력·예상·결과·복기·접근성 표현  
> 판정 원본: `docs/02_COMBAT_RULES.md`

## 1. UI 목표

플레이어가 위치·거리·자원·현재 묶음·전조·타격 번호·합·방어·회피·효과·중단·잔여타·성장 결과를 한 화면과 복기에서 설명할 수 있어야 한다. `합·방어·회피·필중`의 적용 순서를 다시 계산하지 않고 읽게 한다.

## 2. 화면 구조

- 상단: 양측 체력·기력·내력·기세·방어도·회피 횟수·`[필중]` 스택·`[강화]`·`[강건]`.
- 중앙: 10칸 전장·거리·밀착.
- 하단: 3/3/4 슬롯, 항상 사용 가능한 행동·해금 기술.
- 오버레이: 상세, 전투 기록, 결정적 복기.
- 기본 절초 목록 3종은 시작부터 표시하고, 무공 10성 절초는 해당 무공 도달 뒤 같은 목록에 추가한다.

## 3. 시각 자산

현재 수묵 자산과 폴백 도형·텍스트를 유지한다. 자산이 없어도 모든 핵심 정보를 읽을 수 있어야 한다.

## 4. 상단 HUD

- 현재/최대 자원과 예상값을 구분.
- 방어도는 누적·소모를 숫자로 표시.
- 회피는 남은 횟수와 유효 수 범위를 표시.
- `[강건]`은 “피해 방지”가 아니라 “다음 중단 1회 방지”로 설명.
- `[강화]`는 다음 공격 ×1.5와 선소모 시점을 표시.

## 5. 행동 슬롯

`[전조]`, `[실행]`, `[절초 예약]`, `타격 1/3`, `중단 취소`, `전투 불능 취소`를 구분한다. 다중 슬롯 비용은 첫 전조에서 이미 지불됐음을 보여 준다.

## 6. 합·대응·중단 결과 UI

### 순차 합

각 타격에 다음을 표시한다.

```text
1타: A 8 vs B 5 → A 합 승리 → 차이 원피해3
방어도2 흡수 → 체력 피해1
B 중단 → B 2·3타 취소
A 2·3타 → 단독 잔여타
```

### 효과

- `PER_HIT`은 발동한 타격마다 별도 로그.
- `ONCE_PER_ACTION`은 최초 발동 뒤 “행동당 1회 소비” 표시.
- `ON_ACTION_START/RESOLVE`, `ON_CLASH_WIN`, `ON_EVADE_SUCCESS`, `ON_HIT/ON_HEALTH_DAMAGE`, `ON_ACTION_END`를 사건 시점과 함께 구분.

### 기세

여러 합을 이겨도 행동당 +1임을 요약한다.

### 필중 스택

- 남은 `[필중]` 스택을 숫자로 표시한다.
- 유효 타격이 회피를 실제로 무시할 때만 `필중 -1` 사건을 표시한다.
- 합 취소·중단·대상 부재·사거리 실패·회피 부재에는 “미소비” 원인을 로그에 남긴다.

## 7. 입력·접근성

- 명시적 포커스와 키보드 동등 입력.
- 색 외에 아이콘·형태·텍스트·로그를 함께 사용.
- 모션 감소·빠른 재생·즉시 완료가 결과를 바꾸지 않음.
- 타격 연출 건너뛰기 시에도 순서와 원인을 텍스트로 보존.

## 8. 성장·지도 PoC UI

- 시작 무공 6개에서 4개 선택.
- 기술 카드에 슬롯·자원·타격·scope/trigger·예산 상태 표시.
- 전투 후 등급 차원과 공개 적별 과제를 설명.
- 네 구간의 경로 노드 위험·보상을 선택 전에 비교.
- 분산 투자와 “주요 비무 5 전 10성 가능” 집중 경로의 예상 수련포인트를 구분하고, 가능성을 보장처럼 표시하지 않는다.

## 8.1 보상·재도전 UI

- 주요 비무 보상 선택 화면은 `자유6`, `지정5+자유3`, `문파 무공3성`의 총량과 제한 범위를 동시에 비교한다.
- 패배 화면은 전투 직전 복원 범위, 현재 같은 전투 재도전 횟수, 다음 `[영구재화]` 비용 1/2/3, 보유 잔액을 표시한다.
- 재도전 결제 후 피해·임시 자원은 복원되고 영구재화만 감소했다는 결과를 설명한다.
- 잔액 부족 시 비활성 재도전 버튼과 회차 포기·타이틀 복귀 선택지를 제공한다.

## 9. UI·UX 에셋 제작 순서

UI·UX는 에셋을 먼저 선택한 뒤 화면을 맞추지 않는다. 다음 순서를 고정한다.

```text
컨셉·정보 요구 정의
→ 화면·상태별 asset gap map
→ 에셋 스토어·라이브러리 최신 검색
→ 라이선스·스타일·Godot 적합성 평가
→ ADOPT / ADAPT / GENERATE / REJECT / DEFER
→ 부족분만 생성
→ Godot 통합
→ 가독성·접근성·성능·사람 검증
```

### 9.1 컨셉 기준

- 수묵 기반 무협 분위기와 현재 자산 계보를 유지한다.
- 장식보다 전투 정보 위계와 판독성을 우선한다.
- 화면·아이콘·VFX가 없어도 텍스트·도형 폴백으로 기능해야 한다.
- 외부 에셋 때문에 위치·거리·3/3/4·합·중단·필중·성장 설명 구조를 변경하지 않는다.

### 9.2 검색·평가 기준

에셋 후보마다 출처·제작자·버전·가격·취득일·상업 이용·수정·표기·재배포 조건을 기록한다. Godot 4 import 형식, 해상도, 벡터·확장 가능성, 편집 가능성, 스타일 일관성, 접근성, 성능과 파일 크기도 비교한다. 라이선스나 원본 출처가 불명확한 후보는 사용하지 않는다.

### 9.3 생성 기준

검색과 gap 판정 뒤에도 적합한 후보가 없을 때만 생성한다. 생성 전 크기·비율·상태·투명 배경·파일 형식·포커스·접근성 폴백을 명세하고, 프롬프트·원본·편집본·사용 도구를 기록한다. 생성 결과도 외부 에셋과 동일한 검증을 통과해야 한다.

상세 파이프라인 원본은 `docs/superpowers/specs/2026-07-26-ui-ux-audio-asset-pipeline-design.md`다.

## 10. 현재 검증 상태

기존 T0 UI에는 기술 증거가 있으나 새 규칙 UI는 미구현이다. 실제 에셋 스토어 조사·취득·생성·Godot 통합도 `NOT_STARTED`다. `HUMAN_NOT_RUN`, 접근성 사용자·목표 플랫폼 성능은 `UNVERIFIED`다.
