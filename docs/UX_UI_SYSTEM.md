## 1. 플레이어 경험 약속

플레이어는 제한된 계획 슬롯 안에서 적의 의도를 읽고 거리·자원·합을 계산해 무공을 배치한 뒤, 결과를 다음 수읽기로 연결해야 한다.

```text
적 의도 단서 확인
→ 거리·자원·행동 슬롯 확인
→ 3/3/4 계획 안에서 카드 비교·배치
→ 실행 전 충돌·중단·예상 결과 확인
→ 합과 결과 관찰
→ 왜 성공/실패했는지 복기
```

핵심 경험은 **상대의 수를 읽는 긴장**, **제한된 슬롯 안에서 최선의 연계를 만드는 고민**, **합의 인과를 이해하는 만족감**이다.

## 2. 범위와 보호 대상

포함:

- 적 의도·거리·3/3/4 계획 슬롯·기력/내력/행동 비용
- 카드 선택·대상·사거리·실행 전 예상 결과
- 합·중단·반격·상태 변화의 인과와 복기
- 키보드·마우스·게임패드 탐색
- 상세 효과의 점진 공개

제외:

- 전투·거리·무공·AI·상태이상·피해 수치 변경
- 카드 데이터·Scene·script·asset 수정
- HTML 기획 대시보드

UI는 전투 판정을 재계산하지 않고 권위 상태와 예상 결과 데이터를 표시한다.

## 3. 화면 중심 질문

| 단계 | 중심 질문 | 첫 시선 | 핵심 행동 | 결과·복귀 |
|---|---|---|---|---|
| 의도 확인 | 상대가 무엇을 노리는가 | 적 의도 단서·거리 | 대응 방향 선택 | 카드 계획으로 이동 |
| 카드 탐색 | 어떤 수가 현재 상황에 맞는가 | 카드 핵심 효과·비용·사거리 | 카드 선택 | 유효 대상·예상 결과 표시 |
| 3/3/4 계획 | 어떤 순서와 슬롯이 최적인가 | 슬롯·자원·충돌 | 배치·교체·취소 | 전체 계획 검토 |
| 실행 전 | 무엇이 확정되고 무엇이 불확실한가 | 비용·충돌·중단 위험 | 실행/취소 | 전투 연출로 이동 |
| 합/결과 | 어떤 수가 무엇을 이겼는가 | 사건 순서·핵심 충돌 | 제한된 개입/관찰 | 복기 로그 축적 |
| 복기 | 다음에는 무엇을 바꿀 것인가 | 의도→계획→합→결과 | 다음 전투/재설계 | 계획 맥락 복귀 |

## 5. 카드·계획 정보 계층

### L0 상시 필수

- 현재 체력·핵심 자원·거리·행동 단계
- 적의 확인된 의도와 임박 위험
- 3/3/4 슬롯 사용 상태

### L1 현재 선택 판단

- 무공 이름·문파·종류·비용·사거리·핵심 효과
- 유효 대상·예상 피해/방어·충돌 가능성

### L2 결과·복기

- 실제 발동 순서·중단·반격·상태 변화·자원 소비
- 예상과 실제가 달라진 원인

### L3 선택 상세

- 전체 효과 문구·조건·용어 설명·관련 무공/시너지

## 6. 입력·포커스·취소

- 카드 선택과 슬롯 배치는 `selected`와 `focused`를 별도 표현한다.
- 실행 전에는 카드·슬롯·대상을 취소하고 이전 의미 위치로 돌아갈 수 있다.
- 사거리/대상 없음은 `-` 또는 명확한 자기 대상 표현을 사용한다.
- 게임패드 포커스는 화면 배치와 같은 순서로 이동한다.
- 상세 팝업을 닫으면 해당 카드로 복귀한다.
- 불가능한 행동은 입력을 무시하지 않고 원인과 해결 행동을 표시한다.

## 7. Godot 구현 경계

```text
전투·무공·AI 권위 상태
→ 카드/계획 View Data와 예상 결과
→ Control/Container/Theme 표시
→ 카드·슬롯·대상·실행 요청 Signal
→ 전투 도메인 처리
→ 전투 Event와 결과 상태
→ 합 연출·로그·복기 UI
```

금지:

- 카드 UI가 피해·상태·합 승패를 재계산
- 연출 완료를 전투 판정 시점으로 사용
- 표시용 카드 정렬이 권위 실행 순서를 변경
- UX 개선 명목으로 3/3/4 코어·거리·자원 규칙 변경

## 8. 접근성·폴백

- 문파·종류·유효/무효·위험을 색만으로 구분하지 않는다.
- 합 연출을 줄이거나 건너뛰어도 사건 순서와 결과 원인이 남는다.
- 음향을 꺼도 중단·반격·상태 변화가 텍스트·아이콘·로그로 보인다.
- 긴 한국어 효과·최대 수치에서도 비용·사거리·핵심 효과가 잘리지 않는다.
- 키보드·마우스·게임패드 중 선언한 경로로 계획→실행→복기를 완주한다.
