## 2026-09-13 메뉴·안내·완주 복기 연결

타이틀과 비전투·전투 화면의 `메뉴 · Esc` 또는 Esc로 잠시 쉬어가기를 연다. 배경 명령은 차단하고 현재 배치를 유지한다. 돌아가기로 닫으면 이전 조작 위치로 복귀하며 창 자체가 중단된 상태는 별도로 유지한다.
메뉴에서 소리·효과음 음량·모션 감소를 첫 전투 전에 조절하고 현재 전투에도 즉시 적용한다. 쓰기 실패는 이번 실행 적용과 디스크 저장 실패를 구분해 알린다. `비무 안내 보기`는 거리·3/3/4·공개 추론·행로·이어하기를 선택적으로 다시 읽는 스크롤 안내다.
완주 복기는 내부 원인 ID 대신 CombatReviewSummaryBuilder의 한국어 설명과 실제 횟수를 표시한다. 긴 10전 기록은 세로 스크롤로 끝까지 읽고, 저장된 원인 코드와 집계는 그대로 보존한다.
실행 계획·검증·한계: `docs/operations/2026-09-13_PLAYABLE_FLOW_IMPROVEMENT.md`. 실제 Windows 메뉴60개 검사와 3개 화면 크기를 확인했다. Human/Android/실물 게임패드·음향 장치 검증은 NOT_RUN이다.


## 2026-09-12 전투 연출 조절 복원

현재 전투 화면은 준비 영역 바로 위에 `소리: 켬/끔`, 효과음 음량, `모션 감소: 켬/끔`을 표시한다.
Enter로 소리를 전환하고 음량 슬라이더에서 좌우 화살표로 조절한다. 결과 텍스트·공개 정보·전투 판정은 그대로 유지한다.
전투 조절부는 기존 버튼·슬라이더·효과음 플레이어·포커스 링을 재사용한다. 2026-09-13 후속 구현은 같은 설정 owner를 아래 공용 메뉴에도 연결했다. 추가 오디오 채널은 없다.
복기 문장과 조절 요소는 서로 다른 영역을 사용한다. 720p에서는 플랫폼별 글꼴 높이로 두 행 카드가 잘리지 않도록
준비 영역에 최소296px를 확보한다(통상60% 경계에서 최대8px 조정). 실행 후 같은 경계로 복귀한다.
2026-09-13부터 실제 게임 진입점인 VerticalSliceShell이 `user://presentation_settings.cfg`를 먼저 읽어 전투 화면에 전달한다.
소리 켜기/끄기, 효과음 음량, 모션 감소는 다음 전투·타이틀 재진입·앱 재실행 후에도 유지한다.
기본값은 소리 켬, 음량65%, 모션 감소 끔이다. 설정은 여정 진행 저장과 분리되며 v1/v2 Schema를 바꾸지 않는다.
누락/손상 파일은 기본값으로 시작한다. 쓰기 실패 시 현재 실행에는 적용하고 컨트롤 도움말에 저장 실패를 표시하며 다음 조작에서 재시도한다.
독립 전투 preview와 경로를 지정하지 않은 스크립트 검증은 임시 설정만 사용한다.

## 1. 플레이어 경험 약속

플레이어는 제한된 계획 슬롯 안에서 적의 의도를 읽고 거리·자원·합을 계산해 무공을 배치한 뒤, 결과를 다음 수읽기로 연결해야 한다.

```text
적 의도 단서 확인
→ 거리·자원·행동 슬롯 확인
→ 3/3/4 계획 안에서 카드 비교·배치
→ 실행 전 충돌·중단·예상 결과 확인
→ 합과 결과 관찰
→ 현재 결과 strip과 종료 요약에서 왜 성공/실패했는지 읽기
```

핵심 경험은 **상대의 수를 읽는 긴장**, **제한된 슬롯 안에서 최선의 연계를 만드는 고민**, **합의 인과를 이해하는 만족감**이다.

## 2. 범위와 보호 대상

포함:

- 적 의도·거리·3/3/4 계획 슬롯·기력/내력/행동 비용
- 카드 선택·대상·사거리·실행 전 예상 결과
- 합·중단·반격·상태 변화의 인과와 복기
- 키보드·마우스·게임패드 탐색
- 상세 효과의 점진 공개

제외:

- 전투·거리·무공·AI·상태이상·피해 수치 변경
- 카드 데이터·Scene·script·asset 수정
- HTML 기획 대시보드

UI는 전투 판정을 재계산하지 않고 권위 상태와 예상 결과 데이터를 표시한다.

## 5. 카드·계획 정보 계층

### L0 상시 필수

- 현재 체력·핵심 자원·거리·행동 단계
- 적의 확인된 의도와 임박 위험
- 3/3/4 슬롯 사용 상태

### L1 현재 선택 판단

- 무공 이름·문파·종류·비용·사거리·핵심 효과
- 유효 대상·예상 피해/방어·충돌 가능성

### L2 결과·인과 요약

- 실제 발동 순서·중단·반격·상태 변화·자원 소비
- 예상과 실제가 달라진 원인

### L3 선택 상세

- 전체 효과 문구·조건·용어 설명·관련 무공/시너지

## 6. 입력·포커스·취소

- 카드 선택과 슬롯 배치는 `selected`와 `focused`를 별도 표현한다.
- 실행 전에는 카드·슬롯·대상을 취소하고 이전 의미 위치로 돌아갈 수 있다.
- 사거리/대상 없음은 `-` 또는 명확한 자기 대상 표현을 사용한다.
- 게임패드 포커스는 화면 배치와 같은 순서로 이동한다.
- 상세 팝업을 닫으면 해당 카드로 복귀한다.
- 불가능한 행동은 입력을 무시하지 않고 원인과 해결 행동을 표시한다.

## 7. Godot 구현 경계

```text
전투·무공·AI 권위 상태
→ 카드/계획 View Data와 예상 결과
→ Control/Container/Theme 표시
→ 카드·슬롯·대상·실행 요청 Signal
→ 전투 도메인 처리
→ 전투 Event와 결과 상태
→ 합 연출·로그·현재 결과 strip/종료 요약 UI
```

금지:

- 카드 UI가 피해·상태·합 승패를 재계산
- 연출 완료를 전투 판정 시점으로 사용
- 표시용 카드 정렬이 권위 실행 순서를 변경
- UX 개선 명목으로 3/3/4 코어·거리·자원 규칙 변경

## 8. 접근성·폴백

- 문파·종류·유효/무효·위험을 색만으로 구분하지 않는다.
- 합 연출을 줄이거나 건너뛰어도 사건 순서와 결과 원인이 남는다.
- 음향을 꺼도 중단·반격·상태 변화가 텍스트·아이콘·로그로 보인다.
- 긴 한국어 효과·최대 수치에서도 비용·사거리·핵심 효과가 잘리지 않는다.
- 키보드·마우스·게임패드 중 선언한 경로로 계획→행동 실행→결과 요약을 완주한다.

## 8A. UI 모션·중단·반복 계약

UI 모션은 다음 상태를 명확하게 표현하되 전투 결과를 소유하지 않는다.

```text
입력 접수
→ 처리 중
→ 도메인 결과 확정
→ 결과 표현
```

- 카드 선택·슬롯 배치·상세 팝업·합 연출은 입력 중단과 즉시 완료 경로를 가진다.
- 빠른 반복 입력과 재진입에서 중복 배치·중복 비용·중복 보상·transform drift가 발생하지 않아야 한다.
- `Reduced Motion`은 핵심 상태·사건 순서·결과 원인을 보존하며, `mute`와 `haptic-off`에서도 텍스트·아이콘·로그로 동등한 정보를 제공한다.
- `AnimationPlayer`·`Tween` 완료 signal은 전투 판정·자원 소비·저장·보상의 권위 시점이 아니다.
- 모션이 취소되거나 건너뛰어져도 CombatState와 결과 로그는 동일해야 한다.

검증되지 않은 실제 화면 반복 피로·Windows 성능·사람 이해는 `NOT_RUN` 또는 `HUMAN_NOT_RUN`으로 유지한다.
