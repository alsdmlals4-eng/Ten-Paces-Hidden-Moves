# 십보강호 테스트 체크리스트

> 책임: 최신 승인 기획의 정적·자동·Godot·Windows·접근성·네트워크·사람 증거와 완료 주장  
> 태그·상태: `docs/00_TAG_STATUS_REGISTRY.md`  
> 규칙 원본: `docs/02_COMBAT_RULES.md`  
> PoC 범위: `docs/05_COMBAT_POC_SPEC.md`  
> 성장 원본: `docs/06_STARTING_FACTION_MASTERY_DATA.md`

## 1. 검증 상태

검증 종류마다 아래 값을 따로 기록한다.

- `PASS`
- `PARTIAL`
- `FAIL`
- `NOT_RUN`
- `BLOCKED`
- `UNVERIFIED`

파일 존재·정적 검사·자동 테스트·Godot·Windows·접근성·네트워크·사람 이해는 서로 대체하지 않는다.

## 2. 현재 증거 요약

```yaml
legacy_t0_runtime:
  implementation_status: IMPLEMENTED_LEGACY
  automated_validation: PASS
latest_planning_contract:
  authority_status: CURRENT_APPROVED_PLANNING
  implementation_status: NOT_STARTED
action_selection_dock:
  implementation_status: IMPLEMENTED_CURRENT
  automated_validation: PASS
  windows_validation: NOT_RUN
  human_validation: NOT_RUN
app_flow_shell:
  implementation_status: NOT_STARTED
ranked_online:
  scope_status: FUTURE_ONLINE
  implementation_status: BLOCKED_NOT_AUTHORIZED
  network_validation: NOT_RUN
human_step14: NOT_RUN
```

기존 T0의 체력·공격력·방어력·방어도 소모 수치는 최신 기획 검증 기준이 아니다. 레거시 회귀 검사는 별도 fixture로 유지하되 신규 완료 기준과 섞지 않는다.

## 3. 정본·태그·범위

- [ ] 최신 Decision ID가 `docs/01~08`, Active Context, Roadmap, planning JSON, Google Sheet에 일치한다.
- [ ] 플레이어 노출 행동 종류는 `[전조] [이동] [공격] [방어] [회피] [태세] [자원] [관찰]`만 사용한다.
- [ ] 개발용 AI archetype·fixture 태그가 사용자 화면에 노출되지 않는다.
- [ ] 권위·범위·구현·검증 상태를 한 문자열로 합치지 않는다.
- [ ] `덱빌딩`, `카드 배틀러`, `PvP 중심`을 제품 핵심 태그로 오인하지 않는다.
- [ ] 기획 승인만으로 구현·사람 검증 완료를 주장하지 않는다.

## 4. 전장·거리·점유

- [ ] 전장 1~10, 플레이어 4, 상대 7.
- [ ] 같은 칸 거리 0은 `[밀착]`.
- [ ] 공동 빈 목적지와 정지 상대 칸 진입 허용.
- [ ] 자리 교환·상대 통과·전장 밖 이동 금지.
- [ ] 방향·사거리·목적지 실패 이유가 구조화 이벤트와 UI에 남는다.

## 5. 라운드·계획 잠금

- [ ] 한 라운드가 `3수 → 3수 → 4수`로 분할된다.
- [ ] 현재 묶음만 편집할 수 있다.
- [ ] `[진행]` 뒤 현재 묶음 입력이 잠긴다.
- [ ] 다중 수 행동은 앞 슬롯 `[전조]`, 마지막 슬롯 `[실행]`으로 표시된다.
- [ ] 첫 전조에서 비용을 선지불하고 중단돼도 환불하지 않는다.
- [ ] 적은 현재 묶음만 계획하며 미래 묶음을 미리 생성하지 않는다.
- [ ] 적 계획은 관찰 공개 전에 확정·잠금된다.
- [ ] 공개 뒤 적이 더 유리한 행동으로 교체하지 않는다.
- [ ] 적 AI 입력에 플레이어 미확정 슬롯·대상·방향·UI 상태가 포함되지 않는다.

## 6. `[관찰]`

- [ ] 본편 기본 `[관찰]` 1회가 관찰량 1을 제공한다.
- [ ] 관찰량 저장·획득 상한이 없다.
- [ ] 현재 묶음 길이를 초과한 관찰량이 다음 묶음·다음 라운드로 이월된다.
- [ ] 아직 계획되지 않은 미래 묶음을 관찰 때문에 미리 생성하지 않는다.
- [ ] 공개는 앞 수부터 적용된다.
- [ ] 복합 기술은 실제 구성 종류를 모두 표시한다.
- [ ] 기술명·무공서명·비용·방향·거리·피해·사거리·대상·AI 가중치를 누출하지 않는다.
- [ ] 적 AI는 `[관찰]`을 사용하지 않는다.

## 7. 스테이터스·파생값

- [ ] 영구 전투 스테이터스는 외공·근골·신법·내공·심안 5종이다.
- [ ] 주요 운용 범위 1~15를 데이터·UI·검증에서 일치시킨다.
- [ ] 신규 기술이 `attack_power`·`defense`를 독립 영구 스테이터스로 사용하지 않는다.
- [ ] 기술마다 고정 효과와 허용된 스테이터스 참조를 명시한다.
- [ ] 피해·방어도·체력·내력·회복은 연속 보정 가능하다.
- [ ] 이동 거리·사거리·관찰량·행동 슬롯·회피 횟수·전조 수는 임계 효과로만 변경된다.
- [ ] 반올림·최솟값·최댓값·상한이 중앙 데이터와 일치한다.

## 8. 기초 행동·자원

- [ ] 이동, 보법, 막기, 회피, 속공, 강공, 관찰, 명상, 태세의 슬롯·비용·대상이 정본과 일치한다.
- [ ] 기력은 라운드 시작 +1, 내력은 자연 회복하지 않는다.
- [ ] 비용 부족·연속 슬롯 부족·대상 부재가 진행 전에 설명된다.
- [ ] UI가 비용·피해·방어·회복을 독립 계산하지 않는다.

기초 행동 수가 레거시 문서의 “8종” 표현과 충돌할 수 있으므로 실제 catalog와 UI 출처를 구현 전에 재조회한다. `[관찰]`·`[태세]` 포함 여부를 숫자만으로 판정하지 않는다.

## 9. `[합]`·연격

- [ ] `[연격 N]`이 총피해를 N개 피해 단위로 분할한다.
- [ ] 같은 수의 유효 공격이 현재 순번 피해 단위끼리 순차 `[합]`한다.
- [ ] 비교값은 방어·회피 전 원공격력이다.
- [ ] 합 패배·동점은 현재 피해 단위만 취소·상쇄한다.
- [ ] 합 결과만으로 미실행 후속타 전체를 자동 취소하지 않는다.
- [ ] 체력 피해 중단 뒤에만 미실행 후속타가 취소된다.
- [ ] 한쪽 타격 목록 종료 뒤 상대 잔여타가 정상 단독 실행된다.
- [ ] 합 승리 기세는 공격 행동당 전투원별 최대 +1이다.

## 10. 방어도·회피·`[필중]`

- [ ] 방어도는 피해 단위마다 고정 감산한다.
- [ ] 피격으로 방어도가 소모되지 않는다.
- [ ] 방어도는 라운드 종료 시 0이 된다.
- [ ] 방어도로 체력 피해가 0이면 피해 기반 중단이 발생하지 않는다.
- [ ] 회피 횟수 1이 피해 단위 1회를 회피한다.
- [ ] `[필중]`은 실제 회피를 무시한 유효 타격에만 1스택 소비한다.
- [ ] 합 취소·중단 취소·대상 부재·사거리 실패·회피 부재에는 필중을 소비하지 않는다.
- [ ] 필중으로 무시된 회피 횟수는 소비하지 않는다.

## 11. 중단·`[강건]`·효과

- [ ] 현재 피해 단위 효과와 체력 피해 정산 뒤 중단을 판정한다.
- [ ] 체력 피해 1 이상이면 대상의 진행 중 공격 행동 미실행 후속타가 취소된다.
- [ ] `[강건]`은 중단 1회만 방지한다.
- [ ] 강건은 피해·효과를 되돌리거나 KO를 막지 않는다.
- [ ] 효과 scope·trigger·condition의 정상·중복·취소 경계를 검사한다.
- [ ] 합 패배·상쇄·회피·중단으로 취소된 타격의 효과가 발동하지 않는다.
- [ ] `ON_HIT`와 `ON_HEALTH_DAMAGE`가 체력 피해 0에서 구분된다.

## 12. 결착 압력·종료

- [ ] 라운드 1~3에는 결착 피해가 없다.
- [ ] 라운드 4 종료부터 양측 동시 필중 피해가 적용된다.
- [ ] 피해가 `최대 체력×10% + 5×(라운드-3)`과 일치한다.
- [ ] 방어·회피·피해 감소·무적·일반 반격을 무시한다.
- [ ] 3묶음 해결→상태 정산→승리 판정→결착 피해→승리 판정 순서다.
- [ ] 동시 KO는 결착 직전 체력 비율→해당 라운드 유효 체력 피해→무승부 순서로 판정한다.

## 13. 무공서·성장

- [ ] 무공서는 1~10성, 시작 무공은 3성이다.
- [ ] 3→10 비용 2/3/4/5/6/8/10, 총 38을 재계산한다.
- [ ] 2·4·6·8성 고정 스테이터스 보너스가 무공별로 고정된다.
- [ ] 3·7성 신규 기술, 5·9성 기본 강화+임계, 10성 절초 구조가 일치한다.
- [ ] 기술별 별도 수련도·수련포인트가 없다.
- [ ] 신규 기술 요구 스테이터스가 최대 2종이다.
- [ ] 성이 올라도 스테이터스 미달 기술만 잠기고 수련은 계속된다.
- [ ] 조건 충족 시 추가 비용 없이 자동 활성화된다.
- [ ] 전투 중 임시 스테이터스 감소가 이미 익힌 기술을 재잠금하지 않는다.
- [ ] 5·9성 기본 강화와 임계 효과가 분리된다.
- [ ] 집중 경로에서 주요 비무 5 전 10성 도달 가능성을 검증한다.

## 14. 강호행로·콘텐츠

- [ ] 데모 주요 비무 5슬롯, 슬롯당 후보 3명이다.
- [ ] 첫 비무는 후보 3명 중 1명 seed 선정이다.
- [ ] 이후는 후보 3명 중 2명을 경로 종착점으로 제시한다.
- [ ] 각 구간 실제 방문 노드가 정확히 2개다.
- [ ] 네 구간 중간 노드 총 8개다.
- [ ] 같은 seed가 같은 후보·노드 그래프를 재현한다.
- [ ] 노드가 다음 비무 계획을 바꿀 회복·성장·정보·위험을 제공한다.
- [ ] 5번째 비무 뒤 데모 결과 화면으로 종료한다.
- [ ] 15~22분 목표와 피로·이탈을 기록한다.

## 15. 패배·재도전·저장

- [ ] 패배 시 전투 직전 `RunState`와 같은 seed를 복원한다.
- [ ] 같은 전투 재도전 비용 1→2→3, 3 상한이다.
- [ ] 다른 전투 진입 시 비용 단계가 초기화된다.
- [ ] 피해·임시 자원·미획득 보상은 롤백된다.
- [ ] `[영구재화]` 지불은 롤백되지 않는다.
- [ ] 잔액 부족 시 회차 포기·타이틀 복귀를 제공한다.
- [ ] 보상·저장·재도전 transaction이 이중 commit되지 않는다.
- [ ] 구버전·손상 저장·중단 복구 경로가 있다.

## 16. App Flow Shell

- [ ] BOOT→MAIN→RUN_SETUP→ROUTE→NODE→BRIEFING→COMBAT→REVIEW→RESULT→REWARD/RETRY 흐름.
- [ ] App Root가 화면 전환과 입력 잠금을 소유한다.
- [ ] `RunSession`과 `SaveService` 책임이 분리된다.
- [ ] `CombatState`는 Combat Scene이 소유한다.
- [ ] 시작 무공 6중4 선택의 취소·확정·불가 이유가 명확하다.
- [ ] Route·Node·Briefing에서 빈 데이터·죽은 경로·seed 불일치를 복구한다.
- [ ] Combat 진입·복귀가 회차 상태를 중복 적용하지 않는다.
- [ ] 키보드·마우스·게임패드 focus가 복원된다.
- [ ] 1280×800·1440×900·16:9 safe area를 확인한다.

## 17. ActionSelectionDock 회귀

- [ ] `[기초] [무공] [절초]` 출처가 분리된다.
- [ ] 무공서는 직접 배치하지 않고 현재 해금 기술만 배치한다.
- [ ] 가장 앞 유효 연속 수 자동 배치.
- [ ] 연결 블록 이동·제거·재배치.
- [ ] 절초기세 예약·진행 전 환불·진행 뒤 무환불.
- [ ] 자원 부족·잠금·무효 Drop·대상 미지정이 원래 계획을 파괴하지 않는다.
- [ ] hover 없이 키보드·게임패드로 동일 기능을 사용할 수 있다.

## 18. 천하제일인·챔피언 배틀 기획 검증

구현 전 정적 계약만 검사한다.

- [ ] 주요 비무 10전 뒤 후보 2명을 처음 공개하고 1명을 선택한다.
- [ ] 회차 중 후보를 미리 예고하지 않는다.
- [ ] 천하제일인 승리 시 고정 `Champion Build Snapshot`을 만든다.
- [ ] 등록 AI는 해당 천하제일인전 한 경기만 학습하고 고정된다.
- [ ] 공식 랭킹전 양측 `[관찰]`이 비활성화된다.
- [ ] 관찰 의존 효과에 동일·공개·버전 고정 공식 변환표를 적용한다.
- [ ] 등록 스냅샷 원본을 수정하지 않는다.
- [ ] 정보 공개·상대별 가변 보정·AI 전용 특혜·숨은 승률 보정이 없다.
- [ ] 변환 항목 누락·버전 불일치는 공식 랭킹 진입을 fail closed한다.
- [ ] 자기 등록본 대전·친선전은 공식 평점에 반영하지 않는다.
- [ ] 동일 상대 반복 대전 제한과 부정행위 위험을 검토한다.

정확한 변환 수치·평점 공식·시즌 길이·매칭·서버·보안은 별도 승인 전 `NOT_RUN / BLOCKED_NOT_AUTHORIZED`다.
