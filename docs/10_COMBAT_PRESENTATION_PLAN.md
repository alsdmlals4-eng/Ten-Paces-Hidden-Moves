# 십보강호 전투 연출 기획서

> 책임: 최신 전투의 시선 흐름·수별 타격·합·중단·인과 요약·접근성 폴백
> 규칙 원본: `docs/02_COMBAT_RULES.md`
> 첫 5전 패배·재도전 scope: `docs/decisions/2026-08-28_FIRST_FIVE_DEFEAT_RETRY_SCOPE_DECISION.md` (`TEN-DEC-20260828-FIRST_FIVE-DEFEAT-RETRY-SCOPE-01`)

## 1. 연출 목표

2026-09-10 음향 후속: 기존 확정 사건과 12개 큐 ID를 유지한다. 금속 합/방어는 비정수 배음·짧은 접촉음, 검풍/회피는 대역 제한 바람의 상승과 감쇠로 구분하는 자체 PCM 합성을 사용한다. 장치 출력과 청감 최종 검수는 별도이며 실사 금속 녹음으로 표기하지 않는다. 캐시·진폭 여유·시작/끝 클릭 억제는 자동 검사하고 도메인 RNG는 사용하지 않는다.

화려함보다 “어떤 타격이 왜 살아남고 어떤 후속타가 왜 취소됐는가”를 우선한다. 모션·자산·음향이 없어도 같은 결과를 읽어야 한다.

## 2. 첫 시선

```text
10칸 전장·거리
→ 양측 자원·상태
→ 현재 3/3/4 묶음
→ 전조·실행 슬롯
→ 사용 가능 행동·기술
→ 진행 가능 이유
```

## 3. 현재 전투 흐름

계획·대상·예상 자원 → **행동 실행** → 현재 수 카드 `VS` 공개·효과 비교 → 그 수의 확정 사건 연출 → 현재 결과 strip → 다음 묶음 또는 비무 종료. 승리 뒤에는 보상 확인을 거쳐 강호행로로 가며, 합·회피·절초 연출에서 강호행로로 직접 돌아가지 않는다. 실제 도메인 순서는 `docs/02_COMBAT_RULES.md`가 소유하고 화면이 다시 계산하지 않는다.

별도 `Combat Review` overlay/scene은 최신 사용자-facing 화면 경계가 아니다. 복기의 인과 정보는 보존하되 현재 수 결과 strip과 전투 종료의 실제 원인 1~3개로 흡수한다. 기존 overlay 구현은 `IMPLEMENTED_LEGACY`다. PR331의 inline 결과·현재 카드 rail 구현/검증은 `docs/operations/2026-09-08_INLINE_COMBAT_RESULTS_EXECUTION_REPORT.md`에서 확인한다. 이를 다시 미착수로 표시하지 않으며, 그 자동/native 증거를 Human 최종 가독성 승인으로 확대하지 않는다.

## 4. 수별 판정 표현

같은 수 공격군의 합을 공격 행동 단위로 묶고, 내부 타격을 번호로 순차 표현한다.

```text
행동 시작
→ 1타 합/단독
→ 회피·방어도 차감·체력 피해
→ 효과
→ 중단·강건
→ 양측 공격 유지 시 다음 타격 합
→ 한쪽만 남으면 잔여 단독 타격
→ 행동 종료
```

현행 반환 토큰: `timing_results`; UI는 `presentation_events`를 재생한다.

## 5. 합 연출

- 양측 행동명과 `1타/3타`.
- 현재 순번 원공격력과 차이 원피해.
- 상쇄·승리·패배.
- 체력 피해·중단·강건 뒤 다음 순번 합 지속 여부.
- 최종 피해와 방어도 변화.
- 공격 행동당 절초기세 +1 획득 여부.
- 중단된 공격의 후속타 취소와 유지된 공격의 잔여 단독타 전환.

### 5.1 정면 접지 모션 계약

- 공격은 공격자가 상대 쪽으로 짧게 전진한 뒤 같은 발 앵커로 복귀한다.
- 회피와 피격은 상대 반대쪽으로 짧게 이동한 뒤 복귀하고, 막기는 같은 자리에서 방어 자세·복귀를 보인다.
- 절초는 긴 전조·강조·복귀와 기존 승인 VFX를 사용한다.
- `[합]`은 중앙 `clash_anchor`를 무기 접촉 기준으로 사용한다. 몸/발까지 같은 위치에 모으지 않고 각자의 측면 간격을 보존한 뒤 원래 발 앵커로 돌아온다.
- 이 변환은 presentation-only다. 거리·자원·피해·잠금 계획·AI·저장값을 바꾸지 않으며, 모션 감소에서는 변환을 건너뛰되 결과 텍스트와 정지 VFX는 남긴다.

## 6. 중단·강건 연출

`피해1 → 중단 시도 → [강건] 소비 → 공격 유지·다음 순번 합` 또는 `피해1 → 중단 → 남은 2타 취소`를 분리한다. `[강건]`은 피해를 막는 방패처럼 표현하지 않는다.

## 7. 효과 연출

현재 실제 소비자는 `CombatBoardPreview._present_timing_duel`과 `_present_resolved_event_feedback`이며, `CombatPresentationProfile.for_event`가 actor-owned 정의와 확정 사건을 표현으로 분류한다. 이전 문서의 `CombatPresentationController._consume_effects`는 실제 구현 클래스/함수가 아니었으므로 현재 API로 요구하지 않는다. 화면과 순수 profile은 피해·자원·상태·합 승패를 재계산하지 않는다. 아래 효과별 인과 표현은 목표 계약이며, 모든 조건부 무공이 실제 도메인에 연결됐다는 완료 표시는 아니다.

- `PER_HIT`: 각 타격 아래 효과 아이콘·문구.
- `ONCE_PER_ACTION`: 최초 발동 뒤 잠금 표식.
- `ON_ACTION_START`: 현재 공격을 바꾸는 선적용 표식.
- `ON_ACTION_RESOLVE`: 비공격 행동 실행 결과.
- `ON_CLASH_WIN`·`ON_EVADE_SUCCESS`: 해당 판정 사건과 연결.
- `ON_HIT`: 적중 표시.
- `ON_HEALTH_DAMAGE`: 실제 체력 감소 수치와 연결.
- `ON_ACTION_END`: 행동이 완주된 뒤 발생하며 중단 시 미발동 표시.
- 취소·회피된 타격의 적중 효과가 나타나면 실패다.
- `[필중]`은 남은 스택과 실제 회피 우회 시 `-1`을 표시한다. 취소·중단·대상 부재·사거리 실패·회피 부재에는 스택을 소모하지 않는다.

## 8. 절초 연출

기본 절초 3종은 시작부터 표시하고 기존 예약·취소·기세 선소모 계약을 유지한다. 무공 10성 절초는 성급 도달 순간 목록에 추가하며, 주요 비무 5 승리 전역 해금 연출은 사용하지 않는다. 집중 경로의 “5전 전 10성 가능”은 예상치로 표시하고 보장 표식을 금지한다.

`TEN-DEC-20260909-COMBAT-FEEDBACK-CORRECTION-01`은 절초 identity와 실행 성공을 구분한다. 전조는 카드 공개만 유지하고 성공 발동 VFX·소리를 내지 않는다. 실제 실행의 합·실패·대상 회피/막기(`sure_hit_block` 포함)가 성공 절초 강조보다 우선한다. 회복형은 자기 위치, 실제 피해를 준 공격/반격형은 타격 위치에 기존 승인 VFX를 사용한다. 고유 program 없이 기본 방어로 처리된 무공을 성공 반격으로 포장하지 않는다.

## 9. 종료·재시작 연출과 첫 5전 재도전

마지막 타격쌍·동시 효과를 끝낸 뒤 승패·무승부를 표시한다. 첫 패배에서는 Review가 실제 원인 1~3개를 먼저 설명하고, Failure Result가 전투 직전 복원 범위와 남은 무료 동일-seed 재도전 `0/1`을 보여 준다. `다시 비무하기`는 첫 패배에서만 활성화하며, 재도전 뒤 패배하면 회차 종료·타이틀 복귀만 제시한다. 패배 흐름에는 보상·Route·영구재화 변화가 없다. 현행 T0 `결전 다시 시작`은 개발용 완전 초기화로 별도 표기한다.

`[영구재화]` 1/2/3 비용, 보유 잔액, 결제·잔액 부족 연출은 `DEFERRED_POST_SLICE_EXTENSION`이며, 첫 5전 Presentation/Audio cue 요구사항이 아니다.

## 10. 접근성 폴백

2026-09-10 타격감 보강은 기존 확정 사건의 표현만 변경한다. 일반 적중 3.5px,
막기 2px, 합 5px, 피해가 발생한 공격 절초 7px을 기준으로 120~180ms 감쇠하는
전장 전용 흔들림을 적용한다. 수치는 가역적 연출 조정값이지 게임 규칙/피해값이 아니다.
HUD와 입력 영역·논리 좌표는 고정하고 캠페인 난수를 소비하지 않는다.
캐릭터 자세/Tween만 일반 35ms, 합·공격 절초 65ms 유지한다. 전역 시간배율과
판정·저장·UI 처리는 멈추지 않는다. 회피·실패·전조·회복에는 타격 충격을 만들지 않는다.
하단 `모션 감소` 버튼으로 흔들림·타격 정지를 끌 수 있으며 skip/정리에서도 즉시 해제한다.
현재는 로컬 구현·집중 회귀/렌더 증거이며 전체 시각 개선·Human 승인·병합 완료는 아니다.

- 모든 핵심 사건에 텍스트 로그와 접근성 이름.
- 색·모션·음향을 단독 정보 채널로 사용하지 않음.
- 빠른 재생·즉시 완료·모션 감소에서 동일 이벤트 순서.
- 명시적 포커스와 결과 요약으로 타격 수가 많아도 탐색 가능.

## 11. 사운드 컨셉과 사건 구조

사운드는 수묵 무협 분위기와 타격의 긴장감을 보조하되, 판정 정보를 사운드만으로 전달하지 않는다. 에셋 검색 전에 다음 사건별 요구를 먼저 작성한다.

- 전조·예약·commit.
- 단독 적중·합 승리·합 상쇄·합 패배.
- 방어도 흡수·회피·체력 피해.
- 중단·강건 소비·필중 소비.
- 효과 발동·행동 종료.
- 기본 절초·10성 절초.
- 보상 선택·성장·경고·첫 패배 재도전 가능/소진·회차 종료.
- 전투·지도·결과 화면 ambience와 BGM 전환.

사건 ID와 소리 파일을 분리해, 에셋 교체가 전투 판정을 변경하지 않게 한다.

## 12. 사운드 에셋 제작 순서

```text
사운드 컨셉·event matrix
→ 필요한 cue·BGM·ambience gap map
→ 에셋 스토어·라이브러리 최신 검색
→ 라이선스·길이·루프·Godot import·스타일 평가
→ ADOPT / ADAPT / GENERATE / REJECT / DEFER
→ 부족분만 생성·편집
→ audio bus·사건 ID 통합
→ 피로·겹침·접근성·성능 검증
```

### 12.1 검색·평가

후보마다 출처·제작자·가격·취득일·상업 이용·수정·표기·재배포 조건을 기록한다. 파일 형식, 샘플레이트, 길이, 루프 가능성, 무협 컨셉 적합성, 다른 cue와의 일관성, 다타격 동시 재생 위험, 성능과 파일 크기를 비교한다. 출처나 라이선스가 불명확한 파일은 사용하지 않는다.

### 12.2 생성·보정

적합한 후보가 없을 때만 생성한다. 생성·편집 전 사건 역할, 최대 길이, 어택과 릴리즈, 루프 지점, 동시 재생 수, 필요한 변형 수를 명시한다. 생성 프롬프트·원본·편집본·도구와 적용 사건 ID를 기록한다.

### 12.3 믹싱 원칙

- 판정 순서가 중요한 cue가 장식음보다 우선한다.
- 다타격에서는 각 타격이 뭉개지지 않도록 간격·우선순위·동시 재생 상한을 둔다.
- BGM·ambience가 경고·합·중단·재도전 cue를 가리지 않게 한다.
- 음소거에서도 텍스트·아이콘·로그가 같은 정보를 제공한다.
- UI음·타격음·환경음·음악은 분리된 bus로 제어할 수 있어야 한다.

상세 파이프라인 원본은 `docs/superpowers/specs/2026-07-26-ui-ux-audio-asset-pipeline-design.md`다.

## 13. 현재 상태

현행 연출은 `timing_results`와 `presentation_events`를 기반으로 한 수씩 공개한다. `TEN-DEC-20260903-MODULAR-DUEL-UI-AND-PRESENTATION-MOTION-01`의 presentation-only 모션과 PR331의 inline 결과를 보존한다. 현재 feedback 교정은 `TEN-DEC-20260909-COMBAT-FEEDBACK-CORRECTION-01`과 Active Context에서 추적한다. `CombatSoundBank`의 기존 원본 합성음 9개와 새 승리·무승부·절초 발동 cue 3개는 코드에서 제작하고 기존 cache/두 audio player/음소거 경로를 소비한다. 외부 음원 취득, 별도 music/ambience, 다중 audio bus 완성은 이 사실과 별개이며 미완료다.

무공별 고유 대응과 일반/무공 공통 방어 해결은 `docs/reviews/2026-09-09_MARTIAL_DOMAIN_INTEGRATION_PREFLIGHT.md`의 실제 결함으로 남아 있다. 모든 10성 정의를 분류하는 검사와 10종 고유 전투 효과가 완성됐다는 주장을 구분한다. 현재 화면은 승인 아틀라스에 비해 인물·카드 크기와 빈 공간 활용 개선이 필요하다. 인간 플레이의 읽기성·피로도·사운드 선호는 `HUMAN_NOT_RUN`이며 Android 실기기·접근성 사용자·출시 검증은 `NOT_RUN`이다.
