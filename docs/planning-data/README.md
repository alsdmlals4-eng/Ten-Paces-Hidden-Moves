# PoC 기획 데이터 편집 안내

이 디렉터리는 Godot 런타임이 직접 읽지 않는 `NON_RUNTIME_POC_PLANNING` 데이터다. 기획 완료 뒤 Codex가 실제 런타임 Schema로 옮길 때 명시적인 입력을 제공한다.

## 주요 파일

- `poc_balance_budget.json`: 슬롯 예산·효과 가격·태그/고정치/능력치 배수·변경 정책.
- `poc_martial_arts.json`: 시작 무공 후보와 1~10성 기술 표본. 현재 절대 원공격력 표본은 `POC_HYPOTHESIS`다.
- `poc_enemy_duels.json`: 공개 상태 AI 계약, 주요 비무 10개, PoC 1~5 범위.
- `poc_map_rewards.json`: 튜토리얼·스테이지·구간별 정확히 2개 중간 노드·보상·`[의료]`.
- `poc_run_state_contract.json`: `RunState`/`CombatState`, 전투 전후 commit, 영구재화 재도전.
- `poc_sanity_model.json`: 비런타임 수치 sanity model.
- `approved_*.json`: 사용자 승인 Decision의 구조화 계약.

## 현재 캠페인 편집 계약

- 데모: 주요 비무 1~5.
- 정식 후반: 주요 비무 6~10.
- 주요 비무 10전 이후 별도의 선택형 천하제일인전.
- 각 주요 비무 슬롯은 후보 3명.
- 첫 비무는 후보 3명 중 1명 seed 선정, 이후는 3명 중 2명 제시.
- 연속 주요 비무 사이 실제 방문 중간 노드: 정확히 2개.
- PoC 중간 노드 총 8개, 주요 비무 포함 총 방문 노드 13개.
- 전체 주요 비무 10전 구간 중간 노드 총 18개.
- 기본 절초 3종은 시작부터 사용 가능.
- 주요 비무 보상은 자유6 / 지정5+자유3 / 문파 무공3성.
- 집중 경로는 주요 비무1~4에서 32 + 중간 노드 최소6 = 38.
- 패배 재도전은 전투 직전 `RunState` 복원과 `[영구재화]` 1→2→3 결제를 사용.

## 전투·기술 작성 계약

- 최신 기초 행동은 이동·보법·막기·회피·속공·강공·관찰·명상·준비·장풍 10종.
- 현재 런타임 8종과 최신 기획 10종을 구분한다.
- `[전조]`는 강화 없는 점유·표시 단계이며 `[준비]`가 고정 강화 행동이다.
- 연격은 첫 피해 단위만 합에 참여하며 첫 합 실패 시 후속 피해 단위가 취소된다.
- 기술 작성 순서는 `구조/비용 → 태그 → 고정 기본치 → 주/보조 능력치 배수 → 5/9성 patch·임계`다.
- 관찰·이동·회피·준비 기본 효과는 고정 전용이다.
- 그 외 연속 수치 효과는 최소 1개 능력치 참조를 가진다.
- 태그·고정치·능력치 배수·조건·비용은 별도 ledger 행이다.

능력치 배수 가격:

```text
balance_reference_stat = 4
coefficient_snap_step = 0.25
coefficient_ticks = ceil(effect_unit_tick_price × coefficient × 4)
runtime_value = floor(fixed_base_value + Σ(current_stat × coefficient))
```

- 주·보조 능력치는 같은 가격이며 보조 할인은 없다.
- 스테이터스 1·4·15에서 sanity 검사한다.
- 중앙 가격·배수 단위 변경은 기존 기술을 자동 수정하지 않는다.

## 편집 순서

1. 안정된 주요 비무·무공·기술 ID를 유지한다.
2. 행동 구조·비용과 태그를 먼저 확정한다.
3. 고정 기본치와 능력치 참조 배수를 분리한다.
4. 모든 요소를 `price_id × quantity` ledger로 재계산한다.
5. 5·9성 patch는 기본 강화와 스테이터스 임계 효과를 분리한다.
6. 기술 예산은 목표 20/50/80틱, 기본 허용 편차 ±5틱이다.
7. 효과 scope/trigger/condition과 대상·판정 phase·이동 시점을 구조화한다.
8. 스테이지·노드·후보 수를 바꾸면 연결 합계와 seed 계약을 함께 수정한다.
9. 중앙 가격 변경 시 기존 기술을 자동 보정하지 않고 편차 보고를 만든다.
10. JSON은 UTF-8, 2칸 들여쓰기, 안정 key 순서와 마지막 개행을 유지한다.
11. 정적 검사와 관련 단위 테스트를 fresh run한다.

## 상태

- `CURRENT_APPROVED_PLANNING`: 사용자 승인 규칙.
- `POC_HYPOTHESIS`: 비교·편집용 임시 숫자·콘텐츠.
- `IMPLEMENTED_LEGACY`: 작동하지만 최신 승인 기획과 다름.
- `NOT_RUN / UNVERIFIED`: 해당 실행 증거 없음.

이 데이터의 존재는 구현 완료·밸런스 검증·사람 검증을 뜻하지 않는다.
