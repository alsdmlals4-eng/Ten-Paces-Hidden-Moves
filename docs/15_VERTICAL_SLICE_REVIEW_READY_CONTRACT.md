## 1. 후보 난이도 바인딩 원칙

### 1.1 절대 난이도보다 슬롯 간 상승

첫 Slice는 숫자 인플레이션이 아니라 다음 순서로 어려워진다.

```text
Slot 1: 한 가지 습관을 읽는다
Slot 2: 버티기/자원 때문에 순서를 바꾼다
Slot 3: 거리까지 계획에 넣는다
Slot 4: 내 반복 습관도 위험해진다
Slot 5: 여러 행동의 순서·중단·잔여타를 함께 읽는다
```

따라서 HP/피해량만 올려 난도를 만들지 않는다.

### 1.2 영구 스테이터스 총량 Seed

플레이어 시작 최종 총합20·평균4 계약을 기준점으로 한다.

| 슬롯 | 상대 최종 영구 스테이터스 총량 Seed | 의도 |
|---|---:|---|
| 1 | 20 | 시작 플레이어와 같은 총량; 읽기 학습 우선 |
| 2 | 22 | 방어/자원 역할이 체감될 최소 상승 |
| 3 | 24 | 거리전에서 한두 실수를 버틸 압박 |
| 4 | 26 | 플레이어의 성장과 대응해 반복 패턴을 시험 |
| 5 | 28 | 종합전이되 HP sponge는 금지 |

`REVERSIBLE_DIFFICULTY_SEED`이며 밸런스 PASS가 아니다.

### 1.3 분배 규칙

각 후보의 최종 표시 스테이터스는:

- 시그니처 무공의 주 능력치 = 슬롯 내 최고값.
- 보조 능력치 = 두 번째 높은 값.
- 나머지 3개는 특정 시작 빌드를 무효화하지 않을 정도로 분산.
- 같은 슬롯 후보 3명의 **총량은 동일**하게 시작한다.
- 후보 차이는 총량보다 분배·기술·행동 성향에서 만든다.

후속 시뮬레이션에서 특정 후보만 지나치게 강하면 총량을 먼저 올리거나 내리지 않고 원인 태그·기술·행동 정책을 먼저 본다.

## 2. 무공 성급 Seed

| 슬롯 | 기본 시그니처 무공 성급 | 예외 |
|---|---:|---|
| 1 | 3성 | 첫 기술만으로 정체성을 보여준다 |
| 2 | 7성 | 기술2까지 사용 가능; 묵진/석무/단소 역할 차이 표현 |
| 3 | 7성 | 비연은 4성으로 제한 |
| 4 | 7성 | 회피/반격/전조 응용 사용 |
| 5 | 9성 | 9성 단일 강화까지 포함해 종합 흐름 검증 |

### 비연 예외

사천당문 천기암기록은 5성 효과가 플레이어 전용 `[관찰]`과 충돌하므로 비연은 4성 Seed로 제한한다.

- 허용: 3성 `추혼표` + 4성까지의 영구 스테이터스 성장.
- 금지: 적에게 5성 `비성추혼` 관찰 효과 활성화.
- 난이도 부족은 숨은 규칙이 아니라 Slot 3 총 스테이터스 총량과 기초 이동/보법/회피 정책으로 보정한다.

### 성급과 최종 스탯 중복 금지

위 총량 Seed는 **무공 성급 보너스를 적용한 최종 표시 총량**이다. 성급 보너스를 총량 위에 다시 더하지 않는다.

## 3. 후보 AI 공개행동 정책

숫자 가중치는 아직 확정하지 않는다. 각 후보는 `LOW / MEDIUM / HIGH` 수준의 정성 선호만 기획 정본에 가진다.

### AI가 읽어도 되는 것

- 현재 공개 거리.
- 자기 체력/기력/내력/방어/회피/상태.
- 플레이어 현재 공개 체력/자원/상태.
- 이미 해결된 플레이어 행동 이력.
- 이미 공개된/사용된 기술과 무공.
- 전투 중 실제 발생한 합·회피·중단·사거리 실패 사건.
- deterministic seed.

### 읽으면 안 되는 것

- 현재 묶음에서 플레이어가 아직 잠그지 않은 행동.
- UI hover/focus.
- 미확정 대상/방향/슬롯.
- 미래 묶음의 입력.
- 사용자가 Route에서 어떤 정보를 골랐는지를 근거로 적을 강화하는 보상성 재계획.

### 슬롯별 정책

| 슬롯 | HIGH 선호 | MEDIUM 선호 | 의도적 반례 |
|---|---|---|---|
| 1 | 자기 안전거리의 즉각 공격 | 막기/이동 | 같은 거리에서도 대기·방어 |
| 2 | 방어/자원 안정 뒤 반격 | 큰 전조 대응 | 자원 우위에서 먼저 공격 |
| 3 | 시그니처 사거리 유지 | 이동/보법 | 추격 예상 시 역진입/맞교환 |
| 4 | 과거 반복 성공 패턴에 합법적 대응 | 회피/반격 | 자원 부족 시 정면 대응 |
| 5 | 시그니처 연계가 살아남는 순서 | 중단 위험 완화 | 첫 수 불리 시 단독 안전 행동 혼합 |

후보별 구체화는 `docs/13...`의 readable habit/counterexample을 따른다.

## 4. 정적 밸런스 검증 계약

제품 구현 전에 데이터 바인딩 패키지가 만족해야 할 정적 Gate다.

### LOADOUT_LEGALITY

- 모든 기술명이 10권 카탈로그 또는 기초 행동에 존재.
- 요구 성급 이하 기술만 사용.
- 비연에게 적 `[관찰]` 효과 없음.
- 적 전용 신규 태그/상태 없음.

### RESOURCE_PAYABILITY

- 후보가 계획할 수 있는 3/3/4 묶음이 현재 최대 자원에서 실제 지불 가능.
- 비용 선지불·중단 무환불 규칙과 충돌 없음.
- 자원 부족 시 AI가 불가능한 행동을 선택하지 않음.

### SLOT_LEARNING_FIT

- Slot 1이 거리/연격 최종시험으로 변하지 않음.
- Slot 2는 세게 치기 외의 순서/방어/자원 대응이 실제 유효.
- Slot 3은 사거리 실패가 관찰 가능하지만 한 특정 이동기 필수가 아님.
- Slot 4는 미확정 계획을 보지 않고도 플레이어 반복을 대응 가능.
- Slot 5는 최소 2개 규칙이 자연스럽게 겹치지만 모든 규칙을 한 번씩 강제하는 체크리스트가 아님.

### BUILD_DIVERSITY

시작 6중4의 어떤 합법 조합도 특정 슬롯 진입 자체가 막히면 안 된다.

- 특정 무공 1권을 선택해야만 정상 공략 가능 → FAIL.
- 특정 대응 원리(거리 조절/막기/회피/순서 수정)가 유리함 → 허용.
- Route 정보 없이도 승리 가능하되 정보가 계획의 질을 높여야 함.

### ROUTE_BUDGET

- 집중 Route 합계 최소6.
- 자유 Route 합계 최소14.
- 회복은 cap을 넘지 않음.
- 회복 선택이 성장도 동시에 지급하지 않음.
- 정보 선택이 성장/회복 수치를 몰래 지급하지 않음.

## 5. 시뮬레이션 사전 검증 계약

현재는 계약만 확정하며 실제 대량 시뮬레이션 결과를 주장하지 않는다.

### 최소 시나리오

후보 15명 × 다음 6개 플레이어 원형:

1. 공격 압박형.
2. 방어 안정형.
3. 거리 통제형.
4. 회피/반격형.
5. 자원 안정형.
6. 혼합형.

각 조합은 deterministic seed 묶음으로 반복한다.

### 확인 지표

- 승률 분포.
- 평균 라운드 수.
- 체력 손실 분포.
- 합 승/패 횟수.
- 사거리 실패 횟수.
- 중단 횟수.
- 회피 성공 횟수.
- 자원 부족으로 계획 불가 횟수.
- 특정 후보/빌드의 지배적 또는 붕괴 조합.
- Route 회복/집중/자유 선택 이후 다음 전투 생존·성장 차이.

### 초기 경고선 — 가역

- 같은 슬롯 후보 간 승률 차이 > 15%p → 원인 검토.
- 어떤 합법 시작 원형이 한 슬롯 후보군 전체에서 승률 < 25% → 하드 카운터 위험.
- 어떤 원형이 모든 후보에서 > 80% → 지배 빌드 위험.
- Slot 1 평균 라운드가 Slot 5보다 길어짐 → 학습곡선 회귀 검토.
- 회복 Route가 모든 조건에서 성장 Route보다 생존과 승률을 동시에 압도 → 회복 과대.
- 성장 Route가 체력 손실 상태와 무관하게 항상 최선 → 회복 과소.

이 경고선은 자동 FAIL 공식이 아니라 조사 트리거다.

## 6. 15~22분 데모 시간 예산 재검산

### 발견된 충돌

선행 문서의 개별 상한을 모두 더하면:

```text
도입 최대 60초
Briefing 최대 30초 × 5 = 150초
Review+Result 최대 45초 × 5 = 225초
Route 최대 40초 × 8 = 320초
합계 = 755초 = 12분35초
```

비전투만 12분35초가 될 수 있으므로 15~22분 전체 데모·비전투 35~40% 목표와 함께 사용할 수 없다.

### 수정 원칙

개별 상한은 접근성/초회 읽기 허용치이지 **모든 화면이 동시에 상한을 써도 된다는 예산이 아니다**.

회차 전체 aggregate budget을 우선한다.

### 첫 회차 목표

| 구간 | 권장 목표 |
|---|---:|
| 첫 도입 | 45~50초 |
| Briefing | 평균 12~18초 ×5 |
| Review+Result | 평균 20~30초 ×5 |
| Route | 평균 15~25초 ×8 |
| 비전투 총량 | **약 5분25초~8분10초** |

### 페이스별 페어링

- 빠른 15~17분 완주: 비전투 **5분30초 이하** 목표.
- 일반 18~22분 완주: 비전투 **6분30초~8분00초** 목표.
- `8분30초 초과`는 첫 회차 UX 재검토 트리거.

빠른 플레이어는 Briefing/Route도 빠르게 읽는다는 상관관계를 전제로 하므로 `전체 15분 + 모든 비전투 화면 최대치`를 동시에 목표로 하지 않는다.

### 반복 회차

- 도입/반복 인물 대사 빠른 진행.
- 이미 본 설명 기본 접기.
- 전투에 필요한 공개 정보는 스킵 금지.
- 비전투 비중 목표 25~30%를 유지.

## 8. 5회 최종 적대적 검토

### Final Loop 1 · 게임의 가장 기억나는 것이 Route인가

공격: 13개의 비전투/전투 방문과 15명 후보 때문에 로그라이트 지도/수집이 코어를 먹을 수 있다.  
판정: Route는 전투 없이 2노드, 각 3선택, 목적은 회복/성장/정보로 제한.  
보강: aggregate 비전투 시간 예산 추가.  
재검사: **PASS**.

### Final Loop 2 · 상대 읽기가 사실상 공략 암기인가

공격: 반복 후보의 습관을 외우면 심리전이 사라질 수 있다.  
판정: 각 후보는 readable habit + counterexample을 필수로 갖고 확률/정답은 공개하지 않음.  
보강: candidate preference는 qualitative이며 deterministic always-rule 금지.  
재검사: **PASS**.

### Final Loop 3 · 랜덤 후보가 정보 선택을 무효화하는가

공격: 상대가 Route 뒤 결정되면 정보가 무의미하다.  
판정: Result에서 next_candidate_id 선잠금.  
재검사: **PASS**.

### Final Loop 4 · 성장 경로가 사실상 10성 rush 정답인가

공격: 38점 도달 가능성을 보장하면 모든 플레이어가 집중 성장만 택할 수 있다.  
판정: 38은 `가능 경로`이지 무공 절초의 능력치 요구까지 자동 충족하지 않고, 회복/분산의 생존 가치가 존재.  
보강: simulation warning에 route dominance 비교 추가.  
재검사: **PASS_CONTRACT / EVIDENCE_NOT_RUN**.

### Final Loop 5 · 기획완료를 자동검증 완료로 세탁하는가

공격: 문서가 정리됐다는 이유로 재미/밸런스/Windows/Android/Human PASS를 주장할 위험.  
판정: 상태를 `PLANNING_REVIEW_READY_NOT_USER_COMPLETE`; simulation/Human/runtime evidence 명시 NOT_RUN/PENDING.  
재검사: **PASS**.

### Clean-exit reattack

새로운 기획 P0/P1은 발견되지 않았다.

다만 다음은 명시적으로 남는다.

- 회복 Seed의 실제 적정성.
- 후보별 정확한 숫자 스탯 배열과 AI numeric weights.
- 시뮬레이션 결과.
- 실제 Wire/아트/오디오 화면에서의 시간·가독성·몰입.
- 사람 플레이 재미 증거.

이것들은 이번 텍스트 기획의 숨은 누락이 아니라 다음 실행/검증 단계의 입력이다.

`MUST_FIX_REMAINING: 0` for planning-review-ready scope.

## 9. 사용자 다음 결정 Gate

현재 텍스트 기획은 **최종 검토 가능한 상태**다.

사용자가 이후 명시적으로 `기획 완료`를 승인하면 다음 순서를 사용한다.

```text
기획 완료 승인
→ Visual/UX 시안 필요 항목 선정
→ 사용자가 그림 생성을 명시적으로 요청한 항목만 이미지 제작
→ 승인 자산/화면 구조를 사용한 release-near Vertical Slice 구현 계약
→ 구현/자동 검증
→ 실제 화면/입력/사람 플레이 검증
```

사용자가 아직 `기획 완료`를 말하지 않았으므로 현재 제품 구현 권한은 계속 `false`다.
