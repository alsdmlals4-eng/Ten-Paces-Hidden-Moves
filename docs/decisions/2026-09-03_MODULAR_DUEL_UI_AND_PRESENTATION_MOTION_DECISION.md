## 작업 전 문제

기존 정면 결투 화면은 상·중·하단 분리와 현재 묶음 1개만의 표시는 구현했지만, 상태·현재 행동 묶음·상세정보·관찰 정보를 각기 독립된 재사용 프레임으로 묶지 못했다. 또한 공격 이외의 방어·회피·피격·절초 표현이 명시적 모션 계약으로 검증되지 않았고, `[합]`은 양측이 공통 충돌 지점으로 모여 만나는 표현을 보장하지 않았다.

## 채택 구조

### 1. 확정 자산과 동적 정보의 분리

다음 네 원화는 사용자 최종확정 뒤에만 정본·런타임으로 등록한다. 이미지에는 수치·행동명·관찰 결과를 굽지 않고, Godot가 정본 전투 상태에서 동적 텍스트와 게이지를 올린다.

| 모듈 | 역할 | 화면 소비처 |
| --- | --- | --- |
| 상태 HUD 프레임 | 초상, 체력·기력·내력, 기세 5칸, 상태칸의 공통 틀 | 준비·전투 상단의 양측 상태 |
| 현재 행동 묶음 프레임 | 현재 3/3/4 행동 수의 개별 슬롯 틀 | 준비 화면의 현재 행동 묶음 |
| 상세정보 프레임 | 기술명·소모값·행동 수·효과의 동적 상세 표면 | 준비 화면의 hover/click 상세 |
| 관찰 프레임 | 상대 잠금 행동의 허용된 유형만 표시하는 표면 | 준비·다음 묶음 준비 상태 |

플레이어와 적은 이미 `USER_FINAL_LOCKED`인 `player_wanderer_battler_rgba_v2.png`와 `enemy_masked_battler_rgba_v2.png`를 그대로 쓴다. 신규 포즈 시트나 기존 승인 원본의 덮어쓰기는 범위 밖이다.

### 2. 화면과 정보 보호

- 준비 화면은 상단 상태 HUD, 중단 원거리 정면 결투, 하단 현재 행동 묶음·`기초 / 무공 / 절초` 카드와 상세·관찰 표면으로 구성한다.
- 체력·기력·내력은 플레이어만 `현재/최대` 숫자를 보이고, 적은 같은 게이지·상태 구조를 보되 숫자를 보이지 않는다.
- 양측 기세는 5칸이며, 상태칸은 현재 전투 상태만 표시한다.
- 카드에는 이름, 행동 수, 핵심 태그, 실제 소모값과 효과를 표시한다. `사거리`는 공격·사거리 제약 행동에만 표시하며, 자기 대상 행동에 가짜 사거리 문구를 만들지 않는다.
- 상세정보는 `기술명 / 소모값(기력·내력·행동 수) / 효과`를 실제 정의에서 읽는다.
- 관찰은 `[전조] [이동] [공격] [방어] [회피] [준비] [자원] [관찰]` 중 실제 공개된 **유형**만 표시한다. 기술명, 목표, 피해, 방향, 비용, 숨은 계획, AI 내부 상태는 표시하지 않는다.
- 행동 잠금 뒤와 한 수씩 해결되는 전투 화면은 상단·중단만 보이고, 하단 행동계획·선택 카드·상세 선택 표면은 숨긴다. 다음 수는 공개하지 않는다.

### 3. 표현 모션 계약

- 공격: 공격자가 짧게 상대 쪽으로 나갔다가 원래 발 앵커로 돌아온다.
- 회피: 대상이 상대 반대 방향으로 짧게 물러나는 시각 동작 후 같은 논리 발 앵커로 복귀한다.
- 막기: 대상이 짧은 방어 자세·축소/복귀를 보인다.
- 피격: 대상이 상대 반대 방향으로 반동한 뒤 복귀한다.
- 절초: 공격보다 긴 준비·강조·복귀와 기존 승인 절초 VFX를 함께 보인다.
- `[합]`: 양측은 동일한 `clash_anchor`를 향해 수평으로 접근해 검선/실루엣이 중앙에서 겹치고, 충돌 VFX 뒤 각각의 원래 발 앵커로 되돌아간다.

모든 모션은 `presentation-only`다. resolver 결과, 거리 타일, 체력·기력·내력·기세, 저장 데이터, AI 입력, 잠금된 계획을 변경하지 않는다. 중간 이동에서도 두 캐릭터의 발 y는 공동 바닥선에서 벗어나지 않으며, 모션 감소 설정에서는 읽을 수 있는 결과 텍스트·VFX 정지표현만 남긴다.

## 조사·비교 재사용 판정

`TEN-RES-20260901-FRONTAL-DUEL-REVEAL-CARD-BENCHMARK-01`은 정면 공유 바닥, 현재 3/3/4 묶음, 한 수씩 공개, 통합 카드 표면이라는 동일 판단축을 10개 사례로 다시 확인했다. 이번 변경은 그 축의 가독성·표현만 강화하며, 새 행동 경제·완전한 상대 의도 공개·공격 방향 선택·실시간 반응·저장 구조를 추가하지 않는다. 따라서 2026-08-30의 12종 역공학과 2026-09-01의 정면 결투 보강을 `REUSED_BOUNDED_CONTINUATION`으로 사용한다.

## 기대 효과

- 준비 단계에서는 수치·카드·상세·관찰의 책임 위치가 분리돼, 풍경 위에 UI가 떠 보이지 않는다.
- 해결 단계에서는 하단 선택 정보가 사라지고 현재 한 수·인물 동작·중앙 충돌만 남아 수읽기 결과가 더 명확해진다.
- 표현은 실제 원본의 접지와 정보 규칙을 보존하므로, 시각 개선이 규칙 오류나 숨은 정보 누설을 만들지 않는다.

정적·자동·Godot runtime capture는 이 결정의 기계 검증 증거다. 사람 플레이, 최종 미학 승인, 접근성 사용자, Android 실기기, 출시 성능, 자산 권리는 별도 증거가 없으면 `NOT_RUN`이다.
