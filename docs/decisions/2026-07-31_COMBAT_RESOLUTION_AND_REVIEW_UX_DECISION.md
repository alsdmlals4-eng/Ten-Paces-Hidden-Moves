# 전투 해결·복기 UX 결정

> Decision ID: `TEN-DEC-20260731-COMBAT-REVIEW-01`  
> 상태: `APPROVED_PLANNING`  
> Work Mode: `PLAN`  
> 런타임 권한: `NONE`

## 1. 목적

1대1 진검승부에서 계획한 1수·2수·3수가 실제로 어떻게 해결됐는지, 플레이어가 판정 순서와 실패 원인을 즉시 이해하도록 한다.

핵심 원칙은 다음과 같다.

> 전투 결과를 화려하게만 보여주지 않고, 계획과 실제 판정의 차이를 수별로 납득시킨다.

## 2. 해결 단계 정본

각 수는 다음 순서로 해결한다.

```text
현재 수 시작
→ 양측 행동 유효성 확인
→ 이동·준비 단계
→ 공격 사거리·대상 확인
→ 같은 수 공격이면 현재 순번 피해 단위끼리 `[합]`
→ 회피
→ 방어도 고정 감산
→ 체력 피해
→ 적중·피해 효과
→ `[중단]`·`[강건]`
→ 전투 불능
→ 연격 후속 피해 단위 또는 다음 수
```

- `[연격 N]`끼리 충돌하면 현재 순번 피해 단위끼리 순차 `[합]`한다.
- 합 패배·동점은 현재 타격만 취소·상쇄한다.
- 방어도 적용 후 체력 피해가 1 이상이면 `[중단]`이 발생한다.
- 연격 중 중단되면 아직 실행되지 않은 모든 후속타를 취소한다.
- 방어도가 피해를 전부 막아 체력 피해가 0이면 중단하지 않는다.
- `[강건]`은 피해를 유지한 채 중단 이벤트 1회만 방지한다.

## 3. 화면 표시 계층

### 중앙 전장 오버레이

짧고 큰 결과만 표시한다.

- `합`
- `합 승리`
- `합 패배`
- `상쇄`
- `사거리 부족`
- `회피`
- `방어`
- `강건`
- `중단`
- `전투 불능`

### 계획 슬롯

각 슬롯은 계획과 실제 결과를 함께 보존한다.

```text
1수 유운보 — 실행 완료
2수 태극권 — 합 패배 / 체력 피해 2
3수 후퇴 — 중단으로 취소
```

취소된 수를 화면에서 제거하지 않는다.

### 전투 로그

판정 사건을 발생 순서대로 기록한다.

```text
[2수] 양측 공격이 충돌했다.
[2수] 태극권 6 대 설영일섬 8 — 합 패배.
[2수] 플레이어 방어도 1 적용.
[2수] 최종 체력 피해 1.
[2수] 플레이어 행동 중단.
[3수] 후퇴가 중단으로 취소됐다.
```

## 4. 연출 속도

- 기본 속도에서도 판정 사건 순서를 구분할 수 있어야 한다.
- 빠른 재생·즉시 완료·모션 감소는 같은 사건 목록을 공유한다.
- 속도 변경은 판정 결과와 사건 순서를 바꾸지 않는다.
- 중앙 키워드는 동시에 여러 개를 겹치지 않고 중요도 순으로 표시한다.

우선순위:

```text
전투 불능 > 중단 > 합 결과 > 회피·방어·강건 > 사거리 실패 > 일반 이동
```

## 5. 묶음 복기

한 묶음의 모든 수가 해결된 뒤 동일 Combat Scene 위에 `CombatReviewPanel`을 연다.

복기는 다음 네 영역으로 구성한다.

1. 계획: 플레이어가 배치한 1수·2수·3수
2. 실제: 각 수의 실행·취소·결과
3. 결정점: 계획이 무너지거나 성공한 첫 핵심 사건
4. 다음 판단: 다음 묶음에서 검토할 거리·자원·전조

### 결정점 선정 우선순위

```text
전투 불능
→ 중단으로 후속수 취소
→ 합 승패
→ 사거리 실패
→ 회피·방어 완전 감산
→ 자원 부족으로 행동 실패
→ 일반 위치 변화
```

복기는 정답 행동을 제안하지 않는다. 원인과 가능한 재검토 지점만 제시한다.

## 6. 복기 문구 계약

좋은 문구:

- `2수에서 체력 피해를 받아 3수 후퇴가 중단되었습니다.`
- `상대가 후퇴해 거리 2 공격이 사거리 부족으로 실패했습니다.`
- `방어도가 피해를 전부 막아 연격 후속타가 계속됐습니다.`
- `1타 합 패배 후 체력 피해가 발생해 남은 연격이 취소됐습니다.`

금지 문구:

- `운이 나빴습니다.`
- `잘못된 선택입니다.`
- `이 카드를 사용했어야 합니다.`
- 실제 공개되지 않은 상대 AI 내부 가중치·미래 계획

## 7. 다음 상태 전환

```text
묶음 복기
├─ 전투 지속 → 다음 묶음 계획
├─ 상대 전투 불능 → 승리 결과·보상
└─ 플레이어 전투 불능 → 패배·재도전
```

복기 패널을 닫기 전 다음 묶음 편집을 허용하지 않는다.

## 8. Godot 경계

- 판정 엔진은 `ResolvedActionEvent` 목록을 생성한다.
- 연출 계층은 사건을 재생하지만 판정을 재계산하지 않는다.
- 로그와 복기는 같은 사건 목록을 서로 다른 View Data로 변환한다.
- `CombatReviewPanel`은 전투 상태를 수정하지 않는다.

권장 구성:

```text
CombatScreen
├─ BattlefieldPresentation
├─ PlanTimelineView
├─ ResolutionPresentationController
├─ CombatLogPanel
└─ CombatReviewPanel
```

## 9. 완료 기준

- 계획과 실제 결과를 수별로 비교할 수 있다.
- 중단된 후속수와 연격 후속타가 취소된 이유를 구분한다.
- 방어 완전 감산 시 중단이 없다는 사실을 화면과 로그에서 확인할 수 있다.
- 빠른 재생·모션 감소에서도 사건 순서와 결과가 동일하다.
- 플레이어가 복기 후 실패 원인을 설명할 수 있다.
