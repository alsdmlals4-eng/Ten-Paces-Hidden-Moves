# 10초 행동 시간축과 출사표 도입

Decision: TEN-DEC-20260925-FRAME-TIMELINE-PROLOGUE-01 / USER_APPROVED_BUILD

최신 승인: “좋아 잘 이해했어 지금걸로 맞춰서 만들자. 실제 게임데이터 구현,html 연결까지 진행해줘”. 직전 검토 시안과 출사표 도입 설명 전체를 구현 대상으로 삼는다. 기존3수·3수·4수 코어는 새 게임에서10초 시간축으로 대체한다.0.1초 논리 눈금과 렌더링 프레임은 분리한다.

- 새 게임: 메인 → 출사표 → 삽화 무공6중4/3성 → 규칙 안내 → 비전투 행로1회 → 브리핑 → 첫 비무.
- 이후 기존 비무/성장/행로 자료를 재사용한다. 새 자원이나 무공별 별도 모션을 도입하지 않는다.
- 한 계획 창은100논리 틱/10초. 기술은 선딜·발동·후딜을 점유한다. 완료가 창을 넘으면 잔여 동작을 다음 창에 이월하며 비용/타격을 중복 적용하지 않는다.
- 공격은 실제 거리와 유효 구간으로 합·방어·회피·중단을 판정한다. 현재 해금한 모든 기술을 삽화로 선택한다. 덱/드로우/장착 제한은 없다.
- 관찰 완료 시점부터 단계×30틱(1/2/3단계=3/6/9초)의 확인된 적 행동만 공개한다. 적의 계획은 내 편집 중 계획을 읽지 않고 먼저 확정되며 관찰 뒤 바뀌지 않는다.
- 확정 뒤 연출은 같은 사건 기록의 인물 동작·먹 VFX·시간축·크게 보이는 하단 결과를 표시한다. 복기 재생은 판정이나 보상을 다시 실행하지 않는다.
- 메인 인물2명 제거. 노드형 행로에서 상황 설명과 능력치/확률 선택지로 진입. 결과와 복기는 분리하고 브리핑은 내 상태/대치/공개 상대 정보와 삽화 제약 선택으로 구성한다.
- 저장은 버전과 규칙을 식별한다. 기존 저장 bytes와 이미 지급한 보상을 보호한다. 구형 전투 체크포인트를 새10초 판정으로 무검증 변환하지 않는다. 신규 저장은 도입 진행·계획·확정·해결 경계를 검증한다.
- 승인한7개 시안을 시각 기준으로 사용하되 텍스트/수치/버튼은 실제 데이터와 조작으로 구현한다. 그림에 박힌 예시 수치는 실제 결과 근거가 아니다.

근거: 최신 사용자 지시, ACTIVE_CONTEXT, 실제 시작/전투/저장 consumer, 승인 수묵 화풍 owner. 시간 처리와 입력은 Godot4.7.1 실제 기능 및 공식 Control/processing 문서를 대조한다. 신규 외부 게임 설계는 이 승인에 포함하지 않는다.

완료 기준: 새 게임부터 출사표·무공·규칙·첫행로·첫비무·결과·복기·이어하기를 실제 실행. 시간축 경계/겹침/비용/공개 정보/관찰/결정성/재생 중복 방지 회귀 통과. HTML 구조도·규칙·자산·실제 화면/영상 갱신 및 링크/재생 확인. Windows 실행본 전달. 사람 재미·Android·출시 검증은 별도 증거가 없으면 NOT_RUN.
