## 1. 승인 결론

2026-08-11 사용자 승인에 따라 전투 화면의 플레이어 노출 정보 위계를 다음과 같이 고정한다.

1. 10칸 논리 전장은 유지하지만 플레이어 화면 아래에 1~10 번호 발판 칸을 직접 늘어놓지 않는다.
2. 두 전투원의 공간적 간격과 중앙 `거리 N` 배지를 주 거리 표현으로 사용한다.
3. 전투 시작 공개 거리는 `거리 2`다. 거리 0은 `[밀착]`이다.
4. 현재 묶음 확정 조작은 플레이어에게 `행동계획 잠금`으로 표시한다.
5. 카드와 상세창에서 `사거리`는 `[공격]`을 포함한 행동에만 표시한다. 이를 구조화 값으로 `ATTACK_ACTIONS_ONLY`라 한다.
6. 비공격 행동에는 `사거리 -` 같은 빈 행도 만들지 않는다.
7. `[관찰]`은 상대가 이미 잠근 다음 적용 대상 묶음의 앞 수부터 **행동 종류만** 공개한다.
8. 2슬롯 행동은 `1수 [전조] → 2수 [실행]` 구조를 가지며, 공격 행동의 실제 계획판 최종 슬롯은 `[공격] 기술명`처럼 실제 행동 종류를 표시한다.
9. `[기절]`은 현재 프로젝트 승인 태그가 아니므로 전투 UI에서 만들거나 표시하지 않는다.
10. `예상 명중률`, `% 명중률` 같은 확률 개념은 사용하지 않는다. 이 프로젝트의 `적중`은 결정론적 판정 사건이며 명중 확률과 다른 개념이다.

이 Decision은 기존 3/3/4, 현재 묶음 편집, 연결 다중 슬롯 블록, 기초/무공/절초 계층과 실제 자원 비용 분리 규칙을 보존한다.

## 2. 전장과 거리 표시

논리 규칙의 10칸 전장은 유지한다. 다만 플레이어의 기본 전투 화면은 절대 칸 번호가 아니라 상대적 거리 읽기를 우선한다.

```text
검객 A  ─────────  거리 2  ─────────  검객 B
```

거리 0 예:

```text
검객 A / 검객 B
      [밀착]
```

- 플레이어 화면에 1~10 번호 발판 줄을 상시 표시하지 않는다.
- 시작 공개 거리는 `2`다.
- 정확한 새 절대 시작 좌표는 이번 UI 기획 승인으로 임의 확정하지 않는다.
- 현재 Godot 런타임의 플레이어4/상대7 시작 좌표는 기존 구현 증거이며 새 시작 거리2 기획과 다른 `IMPLEMENTED_LEGACY`다.
- 새 절대 좌표·경계 배치는 별도 Build/implementation binding에서 결정한다.

## 3. 행동계획 잠금

현재 묶음만 편집하는 기존 규칙을 유지하되, 플레이어가 확정 행위를 분명히 이해하도록 조작명을 `행동계획 잠금`으로 사용한다.

예:

```text
1수 [이동] 이동
2수 [방어] 막기
3수 [공격] 속공

[행동계획 잠금]
```

잠금 뒤에는 해당 묶음의 행동 제거·재배치·대상/방향 편집을 할 수 없다. 적 계획은 관찰 공개 전에 먼저 잠긴다.

## 4. 카드 본체 정보

### 4.1 항상 표시

카드 본체는 다음만 기본 표시한다.

- 행동명
- 출처 + 행동 종류
- 슬롯 수
- 실제 자원 비용 또는 `비용 없음`
- 핵심 효과

정보가 없거나 적용되지 않는 행을 채우기 위해 `-`, `없음`을 반복하지 않는다.

### 4.2 조건부 표시

- `사거리`: `[공격]`을 포함한 행동만 표시한다. `range_visibility: ATTACK_ACTIONS_ONLY`.
- `조건`: 실제 조건이 있을 때만 표시한다.
- 내부 밸런스 틱은 플레이어에게 표시하지 않는다.

### 4.3 카드 예시

이동:

```text
[기초] [이동]     1수
이동
비용 없음
[이동] 1
```

회피:

```text
[기초] [회피]     1수
회피
기력 1
[회피] 1
```

관찰:

```text
[기초] [관찰]     1수
관찰
비용 없음
[관찰] 1
```

속공, 외공4 예:

```text
[기초] [공격]     1수
속공
기력 1
사거리 1
공격 5
```

속공의 정확한 공식 `floor(3 + 외공 × 0.50)`은 상세에서 확인한다.

## 5. 상세창 정보

상세창은 카드 본체보다 더 많은 설명을 제공하되, 적용되지 않는 필드는 만들지 않는다.

- 정확한 피해·방어·회복 공식과 스테이터스 참조
- 대상·방향이 있는 경우 그 규칙
- 전체 효과 설명
- trigger/scope
- 연격·전조·실행·중단 규칙
- 실제 조건이 있을 때만 조건
- `[공격]` 행동에만 사거리

예를 들어 `이동` 상세에는 `사거리`가 없고 `[이동] 1`과 이동 규칙을 설명한다. `속공` 상세에는 `사거리 1`과 피해 공식을 함께 표시한다.

## 6. `[관찰]` 공개

`[관찰] 1`은 관찰량1을 얻는다. 관찰량은 다음에 상대가 해당 묶음 계획을 확정·잠근 뒤 앞 수부터 행동 종류를 공개한다.

공개 가능한 종류는 현재 태그 정본을 따른다.

- `[전조]`
- `[이동]`
- `[공격]`
- `[방어]`
- `[회피]`
- `[준비]`
- `[자원]`
- `[관찰]`

기술명·무공서명·정확한 비용·방향·이동 거리·공격 사거리·피해·대상·AI 가중치는 공개하지 않는다.

예: 상대의 실제 잠금 계획이 `비연검(2슬롯) → 이동`이라고 가정한다. `비연검`은 이 문서의 **표기 예시용 이름**이며 제품 콘텐츠 승인 이름이 아니다.

```text
관찰량 0: ?       / ?       / ?
관찰량 1: [전조]  / ?       / ?
관찰량 2: [전조]  / [공격]  / ?
관찰량 3: [전조]  / [공격]  / [이동]
```

관찰량이 현재 묶음 길이를 넘으면 기존 규칙대로 다음 묶음으로 이월한다.

## 7. 다중 슬롯 행동

다중 슬롯 행동은 독립 카드 여러 장이 아니라 하나의 연결 행동 블록이다.

2슬롯 공격 예:

```text
1수 [전조] → 2수 [공격] 비연검
```

내부 단계 의미는 `[전조] → [실행]`이며, 플레이어 계획판의 실행 수에는 실제 행동 종류를 보여 준다.

3슬롯 공격 예:

```text
1수 [전조] → 2수 [전조] → 3수 [공격] 기술명
```

전조 중 실제 체력 피해로 중단되고 `[강건]`이 막지 못하면 기존 전투 규칙대로 연결된 후속 실행을 취소한다.

## 8. 금지·오인 방지

- `[기절]`: 현재 승인 태그가 아니므로 생성·표시 금지.
- `예상 명중률`, `% 명중률`: 시스템 자체가 없으므로 생성·표시 금지.
- `적중`: 사거리·방향·회피 등 결정론적 판정을 통과한 사건을 뜻하는 기존 용어로 유지한다.
- `연결`, `기합`: 현행 기초 행동 10종에 없는 임의 카드명으로 추가하지 않는다.
- 비공격 행동에 `사거리 -`를 표시하지 않는다.
- `[관찰]` 결과에 기술명을 노출하지 않는다.

## 9. 외부 비교와 프로젝트 경계

외부 전술 게임의 적 의도 전보 사례는 많은 공개 정보가 있어도 전술적 판단을 만들 수 있음을 보여 준다. 십보강호는 이를 완전 정보 구조로 복제하지 않고 `[관찰]` 투자량만큼 **행동 종류**를 제한적으로 읽고 나머지 세부 정보를 숨기는 불완전 정보 수읽기를 유지한다. 외부 사례는 참고일 뿐 본 Decision의 권위가 아니다.

참고 품질 기준: Subset Games의 *Into the Breach* 공식 설명과 GDC 2019 Design Postmortem을 업계 비교 자료로 사용했으며, 프로젝트 정본과 충돌하면 본 Decision이 우선한다.
