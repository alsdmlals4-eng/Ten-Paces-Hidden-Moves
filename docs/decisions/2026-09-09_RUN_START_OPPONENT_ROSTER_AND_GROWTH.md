## 채택 구조

`적 인물/타입 정의 + 해당 비무 단계의 성장 정의 → 새 회차의 확정 상대 10건 → 저장 → 각 화면이 같은 확정 상대를 소비`

| 확정 상대 | 만남 식별자, 인물/타입, 단계, 별호, 최종 스탯, 보유 무공·수련도, 생성 규칙 버전 | UI가 재계산한 피해·보상, 전체 미래 행동 |
| 회차 저장 | 확정 상대 10건, 생성 시드/버전, 진행 위치, 기존 공개 정보·전투 저장 | 이어하기 때의 재추첨 |

이름과 별호는 분리한다. 예컨대 같은 검객의 초출/숙련/대성 별호를 성장에 맞춰 바꾸되, 예시 명칭을 기존 인물의 확정 세계관으로 자동 승격하지 않는다. 별호 표시 여부/시점은 기존 상대 소개·정탐 정책을 따른다. 미래 10명 목록을 UI나 AI 의도 입력으로 공개하지 않는다.

반복 인물은 새 인물로 복제하지 않는다. 인물 ID와 만남 ID를 구분하여 이전 만남의 체력·정탐 수치·보상 처리 상태가 나중 만남에 섞이지 않게 한다. 같은 인물이 더 높은 단계에 나와도 이전 패배를 사망/부활로 각색하지 않는다.

**무작위 중복 정책은 상세 튜닝 항목**이다. 균등 독립 추첨은 같은 타입의 연속 출현이 가능하다. 사용자 목적에 맞는 타입 편중 완화안을 비교하되, “무작위”를 “10명 전부 강제 고유”로 조용히 바꾸지 않는다. 결정적 시드 재현과 확정 roster 저장이 먼저다.

도겸을 검객으로 재정의하지 않는다. 채령/석무/진려 등의 묘사와 대표 무공 사이 불일치는 이름만 보고 무기를 정하지 않고 실제 기술과 책임 기획을 대조한 뒤 별도 교정한다.

공유 대상은 애니메이션 상태·타이밍 인터페이스·발 기준·효과 연결·중단/감소 모션 처리다. 대기·옷/머리의 작은 움직임은 분할 원화가 준비됐을 때 제한적으로 재사용할 수 있다. 손·무기 접촉·큰 회전·창/맨손 특유 자세는 키프레임을 별도 제작한다. 기존 통짜 PNG가 자동으로 리깅 가능한 파츠 원화는 아니다.

2026-09-09 직접 열람한 Godot 공식 문서: [Cutout animation](https://docs.godotengine.org/en/stable/tutorials/animation/cutout_animation.html), [2D skeletons](https://docs.godotengine.org/en/stable/tutorials/animation/2d_skeletons.html), [SpriteFrames](https://docs.godotengine.org/en/stable/classes/class_spriteframes.html). 파츠/피벗과 프레임 애니메이션 혼합은 제작 후보로 ADAPT한다. 문서 일부는 현재 엔진에 대한 갱신 경고가 있으므로 exact Godot 4.7.1 성공 증거로 쓰지 않는다. 광역 리깅 시스템 선행 구축은 실제 승인 파츠가 없어 DEFER한다.

기존 `docs/reviews/2026-09-09_COMBAT_FEEDBACK_BENCHMARK.md`의 10게임 비교는 확정 사건의 피드백 원칙만 재사용한다. **이번 새로운 적 생성/성장/별호 설계의 10게임 역공학 packet은 아직 완료하지 않았다.** 자료를 열었다는 이유만으로 새 decision dimension의 비교 완료를 주장하지 않는다. 새 제품 mutation 전에 이 요구에 맞는 비교와 수치·저장 호환 명세를 완료한다. 사용자 승인 방향과 조사/상세 명세의 완료 상태를 분리한다.
