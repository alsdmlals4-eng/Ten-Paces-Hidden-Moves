## 1. 목적과 권위

이 Decision은 새 전투 규칙을 창작하지 않는다. 현재 승인된 전투·행동·무공서 Decision을 전투 계획 화면에서 일관되게 읽히도록 하나의 UI 표시 계약으로 수렴한다.

필드 충돌 시 이 문서의 임의 재해석이 아니라 아래 최신 분야 Decision을 따른다.

- `TEN-DEC-20260801-MARTIAL-TECHNIQUE-UX-01`: 기초/무공/절초, 10수·3/3/4, 다중수 연결 블록
- `TEN-DEC-20260802-BASIC-ACTIONS-PALM-CLASH-01`: 최신 기초 행동 10종과 전조/준비 분리
- `TEN-DEC-20260802-BASIC-PALM-DAMAGE-GROWTH-01`: 장풍 피해 공식
- `TEN-DEC-20260804-EXISTING-ACTIONS-REPRICE-01`: 기존 행동의 최신 유효 비용·슬롯 오버레이
- `TEN-DEC-20260804-RESOURCE-SATURATION-INTERNAL-RECOVERY-01`: 묶음 전환 내력 자동 회복 0
- `TEN-DEC-20260806-TEN-RECOGNIZABLE-MARTIAL-MANUALS-FULL-GROWTH-01`: 현재 무공서 10권과 3/5/7/9/10성 성장

## 2. 10수 계획과 슬라이드 타임라인

- 한 라운드는 총 `10수`다.
- 묶음은 `1~3 / 4~6 / 7~10`, 즉 `3 + 3 + 4`다.
- 현재 묶음만 편집하고 `[진행]` 뒤 잠근다.
- 빈 슬롯은 `[대기]`로 취급한다.
- 2수·3수 행동은 같은 묶음 안의 연속 슬롯을 점유하고 하나의 연결 블록으로 표시한다.
- 다중수 행동은 `[전조]`와 `[실행]`을 독립 카드 여러 장처럼 보이지 않게 한다.
- 실행이 끝난 수는 좌측으로 빠지고 예정 수는 우측에서 들어오는 수평 슬라이드/스크롤 표현을 허용한다.
- 좁은 화면에서는 10칸 모두를 같은 크기로 동시에 노출할 의무가 없다. 대신 전체 논리 범위가 10수임을 알 수 있는 묶음 라벨·진행 위치·`3|3|4` 경계를 항상 식별 가능하게 유지한다.
- Windows wide 화면에서는 전체 10수를 동시에 보여 주는 표현도 허용한다.

이 항목은 `TEN-DEC-20260801-MARTIAL-TECHNIQUE-UX-01`의 “전체 10수를 동시에 표시” 문구를 반응형 화면에서 **논리적 전체 10수 인지 + 현재 주변 수 viewport**로 부분 대체한다. `현재 행동묶음만 편집` 규칙은 유지한다.

## 3. 묶음 경계와 회복 표시

묶음 전환은 전투 최초 1묶음 시작이 아니라 `1→2`, `2→3`, `3→다음 라운드1`에 적용한다.

현재 승인 표시값:

```yaml
stamina_gain: 1
internal_gain: 0
ultimate_momentum_gain: 1
```

타임라인은 묶음 경계를 단순 장식이 아니라 규칙 전환 지점으로 읽을 수 있게 표시할 수 있다. 색만으로 의미를 전달하지 않고 선·간격·아이콘·텍스트 중 비색상 신호를 함께 사용한다.

`docs/02_COMBAT_RULES.md`에 남아 있는 `내력 +1`은 구형 요약값이며 UI 권위로 사용하지 않는다. `TEN-DEC-20260804-RESOURCE-SATURATION-INTERNAL-RECOVERY-01`의 `내력 +0`이 현행 필드 권위다.

## 4. 카드 정보 계약

플레이어 카드의 비용은 하나의 추상 숫자로 합치지 않는다. 행동별로 존재하는 정보만 다음 독립 필드로 표시한다.

1. 행동 슬롯: `1수 / 2수 / 3수`
2. 사거리
3. 기력 비용
4. 내력 비용
5. 절초기세 비용 또는 예약량 — 해당 행동에 있을 때만
6. 핵심 효과
7. 다중수 행동의 `[전조] → [실행]` 등 점유 구조

내부 밸런스 `틱`은 플레이어 지불 비용 UI로 노출하지 않는다.

확인된 예:

- 장풍: `2수`, `내력1`, `사거리1~3`, `[전조]→[실행]`, 피해 `floor(3 + 내공 × 0.75)`; 기준 내공4 피해6.
- 관찰: 공용 최신 기초 10종 중 플레이어 전용 1수 행동, 관찰량1 획득. 별도 승인 비용 오버레이가 생기기 전 현재 기본 비용 없음.
- 강공: 최신 유효 비용은 `2수·기력1·내력2`다.

`docs/02_COMBAT_RULES.md`의 강공 `기력1·내력1`은 구형 값이며 `TEN-DEC-20260804-EXISTING-ACTIONS-REPRICE-01`이 `내력2`로 대체한다.

전체 기초 행동의 세부 슬롯·비용·사거리·효과를 새로 추정해서 채우지 않는다. 기존 승인 원본과 최신 오버레이에서 확인되지 않은 필드는 `미확정/정본 조회 필요`로 남긴다.

## 5. 기초 / 무공 / 절초 분류

행동 선택 진입점은 다음 세 계층을 유지한다.

- `기초`: 모든 플레이어가 쓰는 공통 전투 문법
- `무공`: 현재 보유 무공서에서 해금된 기술
- `절초`: 10성에서 해금되는 무공서 대표 절초 등 승인된 절초 진입점

현재 기초 행동 10종은 정확히 다음이다.

`이동 · 보법 · 막기 · 회피 · 속공 · 강공 · 관찰 · 명상 · 준비 · 장풍`

`전조`는 기초 행동이 아니라 다중수 행동의 실행 전 점유 단계다. `준비`는 독립 1수 기초 행동이다.

현재 기획 10종과 런타임의 레거시 8종을 혼동하지 않는다. 이 Decision은 누락된 관찰·장풍의 런타임 구현 권한을 부여하지 않는다.

## 6. 무공서 성장과 카드 노출

성장 구조는 다음을 유지한다.

```text
3성 기술1
→ 5성 기술1 강화
→ 7성 기술2
→ 9성 기술2 완성 강화
→ 10성 절초
```

5성·9성은 새 독립 카드를 추가하는 단계가 아니라 기존 기술에 적용되는 승인된 강화/overlay로 표현한다.

현재 표시명 기준 10권과 절초:

| 문파·유파 | 무공서 | 주/보조 | 10성 절초 |
|---|---|---|---|
| 화산파 | 매화검결 | 신법/외공 | 이십사수매화검법 |
| 소림사 | 나한금강공 | 외공/내공 | 여래신장 |
| 무당파 | 태극검결 | 심안/내공 | 태극혜검 |
| 양가 | 양가창결 | 외공/신법 | 회마창 |
| 화산파 | 자하심법 | 내공/근골 | 자하신공 |
| 소요파 | 소요보결 | 신법/심안 | 능파미보 |
| 개방 | 강룡장결 | 내공/근골 | 항룡십팔장 |
| 사천당문 | 천기암기록 | 심안/신법 | 만천화우 |
| 하북팽가 | 팽가도결 | 근골/외공 | 오호단문도 |
| 남궁세가 | 창궁무애검법 | 내공/심안 | 제왕검형 |

구형 무공서 이름이나 시안용 가상 기술명은 현재 제품 표시명으로 사용하지 않는다.

## 7. 자원 HUD와 전장

현재 파생 최대치:

```text
최대 체력 = 26 + 근골
최대 기력 = 4 + floor(신법 / 4)
최대 내력 = 3 + floor(내공 / 4)
절초기세 = 0..5
```

기준 능력치4의 예시는 `체력30 / 기력5 / 내력4`이나 모든 캐릭터의 고정값으로 표시하지 않는다. 최대치 증가가 현재 자원을 자동 충전한다는 표현도 금지한다.

전장은 `1~10`의 일자형 10칸이며 플레이어·상대 위치와 거리 판단을 읽을 수 있어야 한다. `아군 진영`, `적군 진영` 같은 불필요한 진영 문구는 사용하지 않는다.

## 8. 접근성·반응형 원칙

- Windows와 Android에서 같은 정보·행동 의미를 유지한다.
- 색 단독 의미 전달을 금지한다.
- hover 또는 drag만 가능한 조작을 금지한다.
- 카드 핵심 비용은 일관된 위치와 아이콘/텍스트 조합으로 읽히게 한다.
- 좁은 화면에서는 타임라인을 슬라이드/스크롤해도 `현재 수`, `현재 묶음`, `전체 10수 중 위치`를 잃지 않는다.
- 생성 시안의 텍스트와 숫자는 제품 정본이 아니며, 정본에서 확인된 값만 제품 UI에 사용한다.

## 9. 미확정·금지

- 확인되지 않은 기초 10종의 세부 비용·효과를 빈칸 대신 임의 숫자로 채우기 금지.
- `틱`을 카드 비용처럼 표시 금지.
- 무공서를 직접 수 슬롯에 배치하는 표현 금지.
- 무공 기술을 덱·손패·드로우 카드게임으로 표현 금지.
- 시안용 가상 무공·기술명을 제품 이름으로 승격 금지.
- 이 Decision을 런타임 10종 구현 완료, Godot UI 완료, Windows/Android 사람 검증 완료의 증거로 사용 금지.
