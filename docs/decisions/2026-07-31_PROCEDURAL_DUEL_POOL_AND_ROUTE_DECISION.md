## 1. 승인 결정

- 주요 비무의 **학습 역할과 난이도 단계는 고정**한다.
- 실제 비무 상대는 각 단계의 **후보 3명 풀**에서 선정한다.
- 첫 비무는 해당 슬롯 후보 3명 중 1명을 `run_seed`로 무작위 선정한다.
- 두 번째 비무부터는 다음 슬롯 후보 3명 중 2명을 무작위 제시하고, 플레이어가 경로를 선택해 최종 상대를 결정한다.
- 비무 사이에는 기존 결정대로 정확히 노드 2개를 방문한다.
- 노드 종류, 노드 배치, 연결선, 다음 비무 후보는 `run_seed`와 `gap_index`로 재현 가능해야 한다.
- 완전 무작위가 아니라 `학습 역할 슬롯 + 후보 풀 + 생성 안전장치` 방식을 사용한다.

## 2. 비무 슬롯 계약

| 슬롯 | 고정 학습 역할 | 후보 수 | 무작위 요소 |
|---:|---|---:|---|
| 1 | 공개 전조·거리 1·기본 `[합]` | 3 | 인물·무공 표현·AI 가중치 |
| 2 | 방어도·체력 피해 중단·`[강건]` | 3 | 방어 방식·전조·강공 운용 |
| 3 | 거리·보법·사거리 실패 | 3 | 무기·거리 유지 방식 |
| 4 | 대응·회피·반격 | 3 | 반격 조건·유인 방식 |
| 5 | 연격·순차 합·후속타 취소 | 3 | 연격 형태·중단 대응 |
| 6~10 | 복합 검증 | 각 3 | 문파·무공 조합·복합 AI |

후보가 달라도 해당 슬롯의 필수 학습 목표와 난이도 예산은 변하지 않는다.

## 3. 후보 선정 계약

```yaml
first_duel:
  eligible_candidates: 3
  offered_candidates: 1
  selection: deterministic_weighted_random

later_duels:
  eligible_candidates_per_slot: 3
  offered_destinations: 2
  selection: sample_without_replacement
  player_selects_route_and_opponent: true
```

- 같은 회차에서 동일 인물은 중복 등장하지 않는다.
- 직전 회차에서 만난 후보는 다음 회차 가중치를 낮출 수 있다.
- 같은 문파·무기 계열이 3회 연속 등장하지 않도록 생성 단계에서 보정한다.
- 현재 슬롯 난이도 예산을 벗어난 후보는 추첨 대상에서 제외한다.
- 모든 후보는 플레이어의 미확정 계획이 아니라 공개 상태만 읽는다.

## 4. 경로 생성 계약

```text
현재 비무 승리
→ 다음 슬롯 후보 3명 중 2명 제시
→ 1차 노드층에서 1개 방문
→ 2차 노드층에서 1개 방문
→ 선택 경로의 주요 비무 상대와 대결
```

### 생성 단위

- 1차 노드층: 회복·성장·일반 사건 중심
- 2차 노드층: 선택 가능한 다음 상대의 정보·대비 중심
- 각 층 후보 노드: 2~3개
- 실제 방문: 층마다 1개, 구간당 총 2개
- 모든 경로는 제시된 후보 상대 중 하나로 연결
- 죽은 경로·되돌아가기 금지

### 생성 안전장치

- 각 제시 상대에게 도달하는 경로가 최소 1개 존재한다.
- 각 제시 상대 경로 중 최소 1개에는 회복 또는 안전 성장 기회가 존재한다.
- 각 제시 상대 경로 중 최소 1개에는 해당 상대와 연결된 정보 또는 대비 기회가 존재한다.
- 낮은 체력 상태에서는 접근 가능한 회복 경로를 최소 1개 보장한다.
- 정보 노드를 선택하지 않아도 핵심 규칙은 항상 공개된다.
- 같은 노드와 같은 사건은 한 회차에서 중복 생성하지 않는다.
- 동일 유형 노드 3회 연속 방문을 방지한다.
- 제시되지 않은 상대 전용 정보 노드는 생성하지 않는다.
- 생성 결과는 `run_seed`, `gap_index`, `slot_id`로 재현 가능해야 한다.

## 5. 초기 후보 풀

### 슬롯 1 — 합·거리 입문

1. **연교 — 사문검객**: 정석적인 이동·속공·막기 운용.

3. **진무백 — 철선문도**: 막기로 흐름을 늦춘 뒤 짧은 속공으로 합을 유도.

### 슬롯 2 — 방어도·중단 입문

1. **묵진 — 철벽승**: 방어도·강건·강공의 정석 순환.
2. **하진강 — 진산권객**: 낮은 이동성 대신 방어도 상한 접근과 묵직한 권격을 선호.
3. **위청람 — 현문도객**: 방어도 만료 시점과 강공 타이밍을 교차해 운영.

이름·이명·대표 행동은 콘텐츠 기획 기준이며 정확한 수치와 전용 무공은 후속 밸런스 검토 대상이다.

## 7. 제작 범위 안전장치

첫 데모 5개 슬롯에 후보 3명을 모두 두면 총 15명의 상대가 필요하다. 1인 개발 범위를 보호하기 위해 다음을 적용한다.

- 슬롯별 공통 AI 역할 템플릿을 공유한다.
- 후보마다 고유 차이는 `전조 세트`, `행동 가중치`, `대표 무공 1개`, `외형·서사` 중심으로 제한한다.
- 모든 후보가 완전히 별개의 시스템 규칙을 추가하지 않는다.
- 데모 제작 중 후보 완성도가 부족하면 슬롯별 3명 구조는 유지하되 일부 후보는 공용 애니메이션·효과를 공유할 수 있다.
