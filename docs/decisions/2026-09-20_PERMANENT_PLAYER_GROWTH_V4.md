# 시작 능력과 영구 성장 v4

Decision: TEN-DEC-20260920-PERMANENT-PLAYER-GROWTH-V4-01
상태: 사용자 승인 명세 P03 구현 / PR342 작업 branch / Human·출시 미검증

사용자는 main 정합성→P03 시작 배분·영구 성장→첫 성장 구간 검증의 권장 순서를 “작업진행해”로 승인했다. 실행 기준 f6bdebb7은 main e5ec55e6과 기존 P01/P02의 병합이며 영구 current pin이 아니다.

- 기존 승인된 5능력 기본2씩 + 자유6점(각0~4) + 시작4권의2성 주능력1씩 = 시작 총20. 추천 배분은 선택한 무공의 첫 기술 요구치를 충족하되 사용자가 자유롭게 바꿀 수 있다. 미사용 포인트가 있으면 출발하지 않는다.
- 짝수성 최초 도달의 증분은2성(주1/부0),4성(주1/부1),6성(주2/부1),8성(주3/부2). 현재10권 registry의 주/부 능력 매핑을 사용한다. 수련·전수 이력 검증 후 보유/성수에서 순수 계산하며 로드할 때 별도 가산하지 않는다.
- 기술3/7/10성은 성수와 영구 주능력4/8/12를 함께 확인한다. 수련 자체는 능력이 부족해도 가능하다. 임시 전투 약화는 영구 해금을 되돌리지 않는다. 상대와 기존 여정의 규칙은 유지한다.
- 새 여정만 `ten-duel-stats-v4` / schema4. 시작 배분은 이 버전의 run DTO에만 들어간다. v1/v2/v3 content identity와 당시 고정 능력·원문 저장을 유지한다. v3에서 v4로 암묵 승격하지 않고 명시적인 새 여정 교체에서만 새 generation을 쓴다.
- `player_growth_state.gd`와 `data/run/player_growth_rules.json`은 계산/데이터 owner. RunState·수련 미리보기·전투 engine·bridge·checkpoint·setup UI가 이를 소비한다. 전투 binding 영구 능력은 검증된 run의 계산 결과와 반드시 일치한다.
- HP/기력/내력 최대치, P06 행로 능력 보상 공급량, 보상 수치, AI 비공개 정보 경계, 엔진, 승인 원화는 바꾸지 않는다. P03을 비무10승·재미·밸런스·모션 final lock으로 확대하지 않는다.

근거 재사용: 승인된 시작20/짝수성 증분/현재10권 규칙과 남은 명세 §7·§20. 비교 차원은 성장 선택이 실제 행동 선택을 바꾸는가이다. 동일 설계를 연결하는 작업이므로 새 장르 quota나 추가 외부 조사는 필요하지 않다. 공식 Godot API를 새로 채택하지 않고 기존 versioned codec/transaction/Control 패턴을 재사용한다.

재미 가설: 배분·수련의 결과가 능력과 기술 선택에 일관되게 보이면 플레이어가 다음 비무에 필요한 성장을 설명하고 고를 수 있다. 반례는 성수만 올라도 무조건 열리는 UI, 저장 후 중복 보너스, 능력은 바뀌지만 전투 선택은 그대로인 상태다. 자동/native 검증은 이 연결의 정합성을 확인하며 사람의 이해·선호 관찰은 NOT_RUN이다.

계획·변경·검증·교정은 기존 실행 기록 `docs/operations/2026-09-14_TRAINING_ALLOCATION_IMPLEMENTATION.md`의9월20일 절에 누적한다. 개별 날짜별 PDF를 새로 발행하지 않는다.
