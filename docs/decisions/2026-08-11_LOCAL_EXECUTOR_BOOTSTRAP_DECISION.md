## Decision

For local PowerShell implementation/review work, Ten Paces must bootstrap its dedicated local execution environment before game BUILD work:

```text
dedicated Godot self-contained
→ HiGodot/Godot AI on project ports HTTP 8003 / WS 9503
→ Hera v1.0.0 exact-project live QA instance discovery/readiness
→ project-scoped CODEX_HOME
→ Codex from the exact Ten Paces project root
→ fresh HiGodot + Hera project/session/readiness receipts before implementation proceeds
```

The launcher is provided as one copy/paste PowerShell block. Every invocation assumes the previous PowerShell window has been closed, so shell-scoped state such as `CODEX_HOME` and the project-scoped Hera token environment must be recreated each time.

If the dedicated environment does not exist, bootstrap creates it first from an exact Godot `4.7.1-stable` source. If exact project/editor/profile/HiGodot-port ownership cannot be established, bootstrap fails closed. It does not use destructive recovery, does not kill unrelated processes, does not silently change ports, and does not treat a listening port/process launch as live readiness proof.

Hera is part of the active local workflow. No new blanket Hera prohibition is introduced by this Decision. Current use includes live QA, status, diagnostics, scene/game inspection, screenshots, and other approved observability/QA work.

```yaml
hera_version: 1.0.0
hera_bind_host: 127.0.0.1

codex_home: C:\Users\user\.codex-ten-paces
codex_sandbox: workspace-write

```

Hera's current addon does not require one globally fixed port. It binds the first available localhost port in `8770-8785` and publishes a heartbeat containing PID, actual port, exact `project_path`, Godot version, and scene. The bootstrap therefore resolves Hera by exact Ten Paces project identity rather than assuming port `8770`. The launcher keeps its Hera shared token beside the dedicated Godot installation and exports it as `HERA_AGENT_GODOT_TOKEN`; token material is never printed or committed.

`CODEX_HOME` also isolates Codex local state. The launcher does not copy a global `auth.json`. It checks the project-specific Codex login state and, only when needed, enters the official interactive Codex login flow for `C:\Users\user\.codex-ten-paces` before continuing.

Codex MCP configuration is generated by the project's current Godot AI 3.1.4 `McpClientConfigurator`, not by a separately guessed `codex mcp add` command. This keeps the generated attach command, HTTP/WS ports, and current plugin transport contract aligned with the repository source.
