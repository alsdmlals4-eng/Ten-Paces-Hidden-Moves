# 십보강호 태그·상태 정본 등록부

> 책임: 제품 포지셔닝 태그, 플레이어 노출 규칙 태그, 내부 기획·범위·구현·검증 상태의 이름과 사용 경계  
> 게임 정체성: `docs/01_GAME_DESIGN.md`  
> 전투 태그 의미: `docs/02_COMBAT_RULES.md`  
> 콘텐츠 범위: `docs/03_CONTENT_CATALOG.md`  
> 검증 판정: `docs/08_TEST_CHECKLIST.md`

이 문서는 새 규칙을 만들지 않는다. 승인된 이름과 상태값을 모아 문서·JSON·Google Sheet·UI 사이의 의미 드리프트를 막는다.

## 1. 제품 포지셔닝 태그

핵심: `무협`, `1대1 결투`, `턴제 전술`, `심리전·수읽기`, `불완전 정보`, `로그라이트`.

보조: `거리·위치 전술`, `동시 계획`, `결정론적 판정`, `전투 복기`, `무공 성장`, `절차형 상대·경로`.

후속 콘텐츠: `천하제일인전`, `비동기 챔피언 배틀`, `시즌 랭킹`.

오인 방지를 위해 `덱빌딩`, `카드 배틀러`, `실시간 격투`, `완전 정보 퍼즐`, `PvP 중심`, `방치형 성장`을 핵심 장르·상점 태그로 사용하지 않는다.

## 2. 랭크·랭킹 용어

- `전투 랭크` 또는 `전투 종료 등급`: 한 번의 전투 종료 후 산정하는 `S / A / B / C` 성과 평가.
- `시즌 랭킹`: 비동기 챔피언 배틀의 시즌 평점·순위.
- 사용자 문맥에서 단독 `랭크`가 전투 결과를 가리키면 전투 종료 등급으로 해석한다.
- 정본에서는 `전투 종료 등급`과 `시즌 랭킹`을 완전한 이름으로 쓴다.

## 3. 관찰 공개 행동 종류

`[관찰]`이 공개하는 종류는 아래 8종이다.

- `[전조]`
- `[이동]`
- `[공격]`
- `[방어]`
- `[회피]`
- `[준비]`
- `[자원]`
- `[관찰]`

`[태세]`는 현재 사용자 표시 용어가 아니다. 2026-07-24 승인 Decision에 따라 `basic_stance`의 표시명은 `[준비]`다. 내부 호환 ID와 `action_stage=preparation`은 유지할 수 있다.

복합 기술은 `[이동+공격]`처럼 실제 발생 종류를 모두 표시한다. 기술명·무공서명·정확한 비용·방향·거리·사거리·피해·대상·AI 가중치·정답 파훼법은 공개하지 않는다.

## 4. 전투 규칙 키워드

| 태그 | 책임 의미 |
|---|---|
| `[밀착]` | 거리 0, 같은 칸 상태 |
| `[합]` | 같은 수의 양측 공격에서 현재 순번 피해 단위를 비교하고, 양측 공격이 유지되면 다음 순번에도 반복되는 충돌 판정 |
| `[연격 N]` | 한 공격 행동의 최종 총피해를 N개 피해 단위로 분할 |
| `[필중]` | 회피만 무시하는 공격 효과 또는 예약 스택 |
| `[강화]` | 다음 행동 또는 기술이 정의한 효과 증폭 상태 |
| `[강건]` | 유효 중단 1회를 방지하는 상태 |
| `[의료]` | 전투 후 회복에 사용하는 0~4 계획 값 |
| `[전조]` | 다중 수 행동의 실행 전 점유 수이며 강화 효과 없음 |
| `[실행]` | 다중 수 행동의 최종 발동 수 |
| `[영구재화]` | 재도전 등에 쓰는 메타 자원 자리표시자 |
| `절초기세` | 0~5의 절초 자원; 합 승리 등으로 획득 |

연격 대 연격에서는 현재 순번 피해 단위의 합을 완전히 정산한다. 양측 체력 피해가 0이고 두 공격 행동이 모두 유지되며 양쪽에 다음 피해 단위가 있으면 다음 순번도 다시 합한다. 체력 피해로 한쪽 공격이 중단되면 그쪽 후속 피해 단위는 취소되고, 상대의 유지된 잔여 피해 단위는 단독 타격으로 이어진다. `[강건]` 등 명시적 중단 방지가 공격을 유지시키면 다음 합을 계속할 수 있다.

정확한 수치·판정 순서는 `docs/02_COMBAT_RULES.md`와 최신 Decision이 소유한다.

## 5. 행동 출처와 기초 행동 정본

행동 출처:

- `[기초]`: 항상 사용할 수 있는 공용 행동.
- `[무공]`: 무공서에서 현재 해금된 기술.
- `[절초]`: 기본 절초 또는 무공서 10성 절초.

최신 승인 기초 행동은 총 10개다.

1. 이동
2. 보법
3. 막기
4. 회피
5. 속공
6. 강공
7. 관찰
8. 명상
9. 준비
10. 장풍

`준비`는 기존 `태세`의 최신 표시명이다. `장풍`은 2수·내력1·사거리1~3의 저위력 공격이며 동일 조건의 속공보다 피해가 낮다.

현재 main의 `data/cards/basic_cards.json`과 ActionSelectionDock은 다음 8개를 제공한다.

- 이동·보법·막기·회피·속공·강공·명상·준비

따라서 `[관찰]`과 `장풍`이 없는 현재 구현은 `IMPLEMENTED_LEGACY`다. 별도 Build 승인 전 런타임 데이터·UI를 자동 수정하지 않는다.

## 6. 기술 작성 분류

기술은 아래 층을 분리한다.

1. 행동 구조·비용
2. 승인 태그
3. 고정 기본치
4. 주·보조 스테이터스 참조와 배수
5. 5·9성 기본 강화·임계 효과

고정 전용 효과:

- 관찰량
- 이동·보법 거리
- 회피 횟수·권한
- 준비 기본 강화

그 외 연속 수치 효과는 최소 1개의 스테이터스를 참조한다. 태그·고정치·능력치 배수는 별도 ledger 항목이다.

능력치 배수 가격 기준:

- 밸런스 기준 스테이터스 4
- 초기 스테이터스 설계 중심 4 전후
- 배수 작성 단위 0.25
- 주·보조 같은 가격, 보조 할인 없음
- `배수 틱 = 올림(효과 1점 가격 × 배수 × 4)`
- 실제 정수값은 고정치와 모든 능력치 항을 합산한 뒤 한 번 내림

## 7. 권위 상태

| `authority_status` | 의미 |
|---|---|
| `CURRENT_APPROVED_PLANNING` | 사용자 승인 현재 기획 정본 |
| `POC_HYPOTHESIS` | 비교·편집·검증용 가설 |
| `IMPLEMENTED_LEGACY` | 작동하지만 최신 기획과 다른 구현 |
| `SUPERSEDED` | 후속 Decision으로 대체 |
| `HOLD` | 별도 승인 전 활성 작업 제외 |

`CURRENT`, `PARTIAL`, `PLANNED` 같은 단독 모호 상태는 신규 정본에서 사용하지 않는다.

## 8. 콘텐츠 범위 상태

| `scope_status` | 의미 |
|---|---|
| `CURRENT_T0` | 현재 기술 PoC·레거시 실행 범위 |
| `POC_PRIMARY` | 데모 주요 비무 1~5 |
| `PLANNED_T1` | 사람 PoC 뒤 검토할 최소 세로 슬라이스 |
| `POC_EXPANSION` | 정식 주요 비무 6~10 |
| `FUTURE_FINALE` | 천하제일인전 |
| `FUTURE_ONLINE` | 챔피언 배틀·시즌 랭킹 |
| `T2_PLUS_HYPOTHESIS` | 장기 확장 가설 |

권위·범위·구현·검증을 한 문자열로 합치지 않는다.

## 9. 구현 상태

- `NOT_STARTED`
- `IN_PROGRESS`
- `IMPLEMENTED_LEGACY`
- `IMPLEMENTED_CURRENT`
- `BLOCKED_NOT_AUTHORIZED`
- `DEFERRED`

기획 승인은 구현 승인이 아니다.

## 10. 검증 상태

- `PASS`
- `PARTIAL`
- `FAIL`
- `NOT_RUN`
- `BLOCKED`
- `UNVERIFIED`

정적·자동·Godot·Windows·네트워크·접근성·사람 검증을 각각 기록한다.

## 11. 권위 우선순위

1. 최신 사용자 승인 Decision과 approved planning JSON.
2. `docs/01~11` 책임 원본.
3. Active Context·Roadmap·Google Sheet 요약.
4. 실제 구현. 최신 기획과 다르면 `IMPLEMENTED_LEGACY`.
5. 과거 PR·Issue·백업·역사 문서.

## 12. 개발 태그 노출 경계

- AI archetype·fixture·개발용 상대 태그를 사용자에게 직접 노출하지 않는다.
- 사용자 화면에는 무림식 이름·객관 정보·규칙 키워드를 사용한다.
- UI는 새 태그 의미나 전투 판정을 만들지 않는다.

## 13. 갱신 체크리스트

- 기존 태그로 표현 가능한가.
- 행동 종류·판정 키워드·범위·상태 중 어느 축인가.
- 동일 의미의 다른 이름이 있는가.
- GitHub Decision·책임 원본·planning JSON·Sheet가 일치하는가.
- 미구현·미검증 내용을 완료로 표시하지 않았는가.
- 개발용 태그가 사용자 화면에 노출되지 않는가.

플레이 판단을 바꾸는 새 태그·규칙은 GrillMe 승인 Decision이 필요하다. 단순 명칭 정규화·구형 참조 제거는 유지보수로 처리한다.
