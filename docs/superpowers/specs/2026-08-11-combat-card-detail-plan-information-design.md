# 전투 카드 본체·상세창·계획판 정보 설계

- 작성일: 2026-08-11
- 상태: USER_APPROVED_DIRECTION / WRITTEN_SPEC_FOR_REVIEW
- 현재 권위 Decision: `TEN-DEC-20260811-COMBAT-UI-INFORMATION-HIERARCHY-01`
- 부모 Decision: `TEN-DEC-20260808-COMBAT-PLANNING-UI-CARD-TIMELINE-01`
- 제품 구현 권한: 없음 (`PLANNING_ONLY`)
- 이미지 생성: 기획완료 → 검수완료 뒤 별도 재개

## 1. 목적

전투에서 플레이어가 카드를 읽는 순간, 상세를 확인하는 순간, 계획판에 배치하는 순간의 정보량을 분리한다.

목표는 다음 네 가지다.

1. 카드 본체는 선택 판단에 필요한 정보만 빠르게 읽힌다.
2. 상세창은 정확한 공식·조건·해결 규칙을 필요할 때 확장한다.
3. 계획판은 `3수 → 3수 → 4수`의 시간 구조, `[전조]`, 실제 실행 종류, 잠금 상태를 오독 없이 보여 준다.
4. `[관찰]`은 상대 행동의 종류만 제한적으로 공개하고 기술명·수치·비용을 정답처럼 노출하지 않는다.

이 문서는 새 전투 규칙을 만들지 않는다. `docs/02_COMBAT_RULES.md`, `docs/07_COMBAT_UI_SPEC.md`, 승인 Decision/contract의 현재 값을 UI 정보 계약으로 정리한다.

## 2. 선행 벤치마킹에서 가져오는 요소만

외부 사례를 통째로 복제하지 않는다.

### 참고 요소

- *Fights in Tight Spaces*: 행동 선택과 위치 판단을 동시에 읽어야 하는 전술 정보 밀도만 참고한다.
- *Your Only Move Is HUSTLE*: 행동 확정 전에 현재 맥락과 결과 관계를 이해하게 하는 계획형 격투의 정보 분리를 참고한다.
- Android 접근성 실무: 터치 조작 대상은 48dp 수준의 충분한 터치 영역을 확보하는 원칙을 참고한다.
- Xbox 접근성 실무: 색만으로 상태를 전달하지 않고 텍스트·아이콘·형태를 함께 사용하는 원칙을 참고한다.

### 가져오지 않는 요소

- 덱/드로우/핸드 관리 구조
- 격투게임 프레임 데이터 체계
- 외부 게임의 피해·사거리·자원 수치
- 외부 게임의 적 의도 공개 범위
- 외부 UI 배치를 그대로 복제하는 것

프로젝트 고유 코어 `3/3/4 비공개 계획 + 공개 단서 추론 + 1대1 거리 결투`가 항상 우선한다.

## 3. 검토한 UI 접근 3안

### A안 — 계층 분리형: 카드 본체 → 상세창 → 계획판

- 카드 본체: 즉시 선택 판단
- 상세창: 정확한 규칙·공식·조건
- 계획판: 시간·전조·실행·잠금

장점: 작은 화면에서도 정보 과밀을 줄이고, Windows/Android가 동일한 정보 의미를 유지하기 쉽다.
단점: 상세 규칙은 한 번 더 열어야 한다.

**권장안이며 사용자 승인 방향이다.**

### B안 — 카드 본체에 거의 모든 정보 표시

장점: 한 화면에서 많은 내용을 확인한다.
단점: 비공격에도 불필요한 필드가 늘고, 긴 한국어·모바일 화면에서 카드가 과도하게 커진다.

채택하지 않는다.

### C안 — 카드에는 이름/아이콘만 두고 상세 의존

장점: 매우 간결하다.
단점: 비용·슬롯·핵심 효과를 비교할 때 상세창을 반복해서 열어야 해 계획 편집 속도를 해친다.

채택하지 않는다.

## 4. 카드 본체 정보 계약

### 4.1 항상 표시

카드 본체에는 다음만 기본 표시한다.

1. 행동명
2. 출처 + 행동 종류
3. 슬롯 수
4. 실제 자원 비용 또는 `비용 없음`
5. 핵심 효과

### 4.2 조건부 표시

- `사거리`: **`[공격]` 행동에만 표시**한다.
- `조건`: 실제 조건이 있는 행동에만 표시한다.
- 적용되지 않는 정보는 `사거리 -`, `조건 없음`, `대상 없음` 같은 빈 행으로 만들지 않는다.
- 내부 밸런스 틱·작성 예산은 플레이어 카드에 표시하지 않는다.

### 4.3 카드 예시

#### 이동

```text
[기초] [이동]          1수
이동
비용 없음
[이동] 1
```

- `사거리` 행 없음.
- `대상: 자신` 같은 자명한 행도 기본 카드에는 넣지 않는다.

#### 회피

```text
[기초] [회피]          1수
회피
기력 1
[회피] 1
```

- `사거리` 행 없음.

#### 관찰

```text
[기초] [관찰]          1수
관찰
비용 없음
[관찰] 1
```

- `사거리` 행 없음.
- 카드 본체에서는 핵심 효과만 보여 주고 공개 범위 설명은 상세창으로 보낸다.

#### 속공 — 외공 4 예시

```text
[기초] [공격]          1수
속공
기력 1
사거리 1
공격 5
```

- 현재 계산값을 빠르게 읽게 한다.
- 정확한 공식 `floor(3 + 외공 × 0.50)`은 상세창에 둔다.

#### 강공 — 현재 정본 예시

```text
[기초] [공격]          2수
강공
기력 1 / 내력 2
사거리 1~2
공격: floor(7 + 외공 × 1.00)
```

계획판에서는 카드의 `2수`를 그대로 한 칸에 압축하지 않고 `[전조] → [공격]`으로 풀어 보여 준다.

## 5. 상세창 정보 계약

상세창은 카드 본체보다 정확한 규칙을 제공한다. 그러나 상세창도 적용되지 않는 필드는 만들지 않는다.

### 표시 가능한 정보

- 정확한 피해·방어·회복 공식과 참조 스테이터스
- 실제 자원 비용 세부
- 대상·방향이 있는 경우 그 규칙
- 전체 효과 설명
- trigger / scope
- 연격·전조·실행·중단 규칙
- 실제 조건
- `[공격]` 행동의 사거리

### 표시하지 않는 정보

- 비공격 행동의 `사거리 -`
- 내부 밸런스 틱
- 아직 공개되지 않은 상대 정보
- 확률형 `예상 명중률`
- 현재 승인되지 않은 `[기절]`

### 상세 예시 — 관찰

```text
관찰
[기초] [관찰] / 1수
비용 없음

효과
[관찰] 1을 얻는다.

공개 규칙
상대가 다음 적용 대상 묶음을 먼저 잠근 뒤,
앞 수부터 관찰량만큼 행동 종류만 공개한다.

숨김
기술명 / 무공서명 / 비용 / 방향 / 이동거리 /
공격 사거리 / 피해 / 대상 / AI 가중치
```

### 상세 예시 — 속공

```text
속공
[기초] [공격] / 1수
기력 1
사거리 1

피해
floor(3 + 외공 × 0.50)

현재 외공 4
→ 공격 5
```

## 6. 계획판 정보 계약

### 6.1 기본 구조

전체 라운드의 논리 위치는 항상 `3 | 3 | 4`로 식별 가능해야 한다.

플레이어는 현재 묶음만 편집한다.

예:

```text
1수        2수        3수
[이동]     [방어]     [공격]
이동       막기       속공

[행동계획 잠금]
```

### 6.2 다중 슬롯 행동

2슬롯 행동은 내부적으로:

```text
1수 [전조] → 2수 [실행]
```

계획판에서는 마지막 실행 슬롯을 추상적인 `[실행]`으로 끝내지 않고 실제 행동 종류를 보여 준다.

2슬롯 공격 예:

```text
1수                  2수
[전조]        →       [공격]
강공                  강공
```

표기 형식 예시용 가상 기술을 사용할 경우:

```text
1수 [전조] → 2수 [공격] 비연검
```

`비연검`은 UI 표기 예시일 뿐 제품 콘텐츠 승인 이름이 아니다.

3슬롯 공격 예:

```text
1수 [전조] → 2수 [전조] → 3수 [공격] 기술명
```

다중 슬롯 행동은 하나의 연결 블록으로 취급하고 일부 슬롯만 독립 이동·삭제하지 않는다.

### 6.3 잠금 상태

잠금 전:

- 현재 묶음 행동 제거
- 재배치
- 대상/방향 수정

을 허용한다.

플레이어가:

```text
[행동계획 잠금]
```

을 실행한 뒤에는 해당 묶음을 편집하지 않는다.

잠금 여부는 색만으로 표시하지 않고 텍스트·형태·포커스 상태로 함께 식별한다.

## 7. `[관찰]`과 계획판의 결합

관찰은 상대 기술의 정답을 공개하지 않는다.

현재 공개 가능한 행동 종류:

- `[전조]`
- `[이동]`
- `[공격]`
- `[방어]`
- `[회피]`
- `[준비]`
- `[자원]`
- `[관찰]`

상대의 실제 잠금 계획이 예를 들어:

```text
1수 [전조] 비연검
2수 [공격] 비연검
3수 [이동] 이동
```

이라면 플레이어 화면은:

```text
관찰량 0: ?       / ?       / ?
관찰량 1: [전조]  / ?       / ?
관찰량 2: [전조]  / [공격]  / ?
관찰량 3: [전조]  / [공격]  / [이동]
```

까지만 보여 준다.

관찰로 공개된 상대 슬롯에는 `비연검`, 정확한 비용, 피해, 방향, 사거리를 표시하지 않는다.

## 8. 거리·결정론적 판정과 카드 정보의 관계

- 기본 전투 화면은 번호 발판을 상시 표시하지 않고 `거리 N`을 사용한다.
- 시작 공개 거리는 `2`다.
- 거리 0은 `[밀착]`이다.
- 공격 카드의 사거리는 현재 `거리 N`과 비교하는 판단 정보다.
- 이동·방어·회피·관찰·자원 행동은 사거리 필드를 가지지 않는다.
- 프로젝트에는 `% 명중률`이 없다.
- `적중`, `사거리 실패`, `방향 실패`, `회피`, `방어도 적용`은 결정론적 사건이다.

## 9. Windows / Android 반응형 원칙

핵심 정보의 **의미는 동일하게 유지하고 배치만 바꾼다.**

### Windows wide

- 현재 묶음과 주변 3/3/4 위치를 넓게 표시
- 카드 목록과 상세창을 동시에 둘 수 있음
- 마우스·키보드·게임패드 동등 접근

### Android compact

- 현재 수/현재 묶음 중심 viewport
- 카드 선택 후 상세는 bottom sheet 또는 동등한 overlay 허용
- 클릭/터치 대상은 최소 48dp 수준을 목표
- drag-only / hover-only 금지
- Android back으로 상세/선택 취소 경로 제공

## 10. 접근성·오인 방지

- 색은 보조 신호일 뿐 단독 의미 전달 수단이 아니다.
- `[전조]`, `[공격]`, 잠금, 자원 부족 등 핵심 상태는 텍스트/아이콘/형태를 함께 사용한다.
- 긴 한국어 이름에서도 슬롯·비용·행동 종류가 먼저 읽혀야 한다.
- 오류는 계획을 임의 삭제하지 않고 원래 계획을 보존한 채 이유를 표시한다.
- `행동계획 잠금`은 실행 결과가 아니라 편집 종료/확정 조작이라는 맥락을 사전에 이해할 수 있어야 한다.

## 11. 금지 사항

- 비공격 행동의 사거리 표시
- `사거리 -` 같은 placeholder 행
- `[기절]`
- `예상 명중률` / `% 명중률`
- 관찰을 통한 기술명·비용·피해·사거리 정답 공개
- 현행 기초 행동에 없는 임의 카드 추가
- 덱/손패 UI를 십보강호의 행동 선택 구조로 오인시키는 표현
- 이미지 시안에서 나온 임의 규칙을 정본보다 우선하는 것
