## 1. 목적

이 PoC는 전체 게임의 재미·성장·강호행로를 검증하는 버티컬 슬라이스가 아니다.

가장 먼저 검증할 질문은 다음 하나다.

> 플레이어와 공개 상태 기반 AI가 여섯 무공의 기술1을 모두 사용할 때, 각 기술의 슬롯·비용·공식·이동·조건·판정·후속 효과·UX·모션이 최신 승인 기획과 일치하는가?

승패와 기술 간 최종 밸런스는 보조 관찰값이다. 구현 계약과 다른 결과가 발생하면 전투에서 이겨도 해당 기술은 `FAIL`이다.

## 2. 권위와 적용 우선순위

구현은 다음 순서로 권위를 해석한다.

1. 최신 사용자 승인 Decision
2. 최신 approved planning JSON
3. `docs/02_COMBAT_RULES.md`
4. 연결된 Google Sheet의 `CURRENT_APPROVED_PLANNING`

## 4. 고정 검증 상태

성장과 해금 과정을 제거하고 기술 자체만 비교하기 위해 양측을 동일하게 고정한다.

```yaml
stats:
  외공: 4
  근골: 4
  신법: 4
  내공: 4
  심안: 4
health: [30, 30]
stamina: [5, 5]
internal: [4, 4]
ultimate_momentum: [0, 5]
defense: 0
evade_charges: 0
fortitude: 0
observation:
  player: 0
  enemy: disabled
position:
  player: 4
  enemy: 7
defense_cap: 10
```

- 기력 최대값은 5다.
- 내력 최대값은 4다.
- 라운드 시작 시 기력 +1, 내력은 자연 회복하지 않는다.
- 방어도는 피격으로 소모되지 않고 피해 단위마다 고정 감산하며 라운드 종료 시 0이 된다.
- 방어도는 10을 넘지 않는다.

## 5. 행동 선택 구조

```text
[기초]
[무공] → 무공서 6종 → 기술1
[절초] → 기본 절초 3종
```

무공서는 성장·분류 단위이며 타임라인에 직접 배치하지 않는다. 실제 배치 대상은 기술이다. 덱·손패·드로우·장착 제한을 사용하지 않는다.

### 5.1 기초 행동 10종

| 행동 | 슬롯 | 비용 | 효과 |
|---|---:|---|---|
| 이동 | 1 | 없음 | 선택한 방향으로 고정 1칸 |
| 보법 | 1 | 내력1 | 선택한 방향으로 1~2칸 |
| 막기 | 1 | 기력1 | 기준 스탯4 PoC 방어도5 획득 |
| 회피 | 1 | 기력1 | 가장 먼저 도달한 회피 가능 피해 단위 1개 제거 |
| 속공 | 1 | 기력1 | 거리1, `floor(3 + 외공×0.50)` = 5 |
| 강공 | 2 | 기력1·내력1 | `[전조]→[실행]`, 거리1~2, `floor(7 + 외공×1.00)` = 11 |
| 관찰 | 1 | 없음 | 플레이어 전용, 관찰량 +1 |
| 명상 | 1 | 없음 | 기력 +1·내력 +1 |
| 준비 | 1 | 내력1 | 다음 비이동 행동까지 강화 |
| 장풍 | 2 | 내력1 | `[전조]→[실행]`, 거리1~3, `floor(3 + 내공×0.75)` = 6 |

`막기 방어도5`는 현행 PoC 기준값을 사용한다. 최신 근골 계수 자체를 새 정본으로 확정하지 않으며 검증 보고서에 `POC_REFERENCE_VALUE`로 표시한다.

### 5.2 `[전조]`와 `[준비]`

- `[전조]`는 다중 수 행동의 실행 전 점유 표시이며 독립 효과가 없다.
- 비용은 첫 전조에서 전액 선지불한다.
- 중단·사거리 실패·방향 실패에도 비용과 슬롯을 환불하지 않는다.
- `[준비]`는 독립 1수 행동이다.
- 이동·보법은 준비를 소비하지 않는다.
- 다음 공격은 원공격력 +2와 강건1을 얻고 준비를 소비한다.
- 다음 명상은 기력·내력 회복에 절초기세 +1을 더하고 준비를 소비한다.
- 막기·회피·기타 비이동 행동은 처리 또는 유효 시도 뒤 준비를 소비한다.
- 새 준비는 기존 준비를 교체한다.

## 6. 여섯 기술1 구현 계약

양측 모두 아래 여섯 기술을 처음부터 사용한다. UI에는 canonical ID와 한국어 이름을 함께 연결하며 역사 alias는 데이터 마이그레이션에만 남긴다.

### 6.1 유운검결 — 유운삼첩

```yaml
manual_id: flowing_cloud_sword
technique_id: flowing_cloud_triple
slots: 2
cost: {stamina: 1, internal: 1}
range: 1
hits:
  - floor(3 + 외공*0.25) # 4
  - floor(2 + 외공*0.25) # 3
  - floor(2 + 외공*0.25) # 3
```

검증:

- 첫 슬롯 전조·둘째 슬롯 실행
- 비용은 첫 전조에서 선지불
- 세 피해 단위를 합산하지 않고 `4→3→3` 순서로 별도 판정
- 상대 연격과 충돌하면 현재 순번 피해 단위끼리 합
- 체력 피해로 중단되면 미실행 후속타 취소
- 강건이 중단을 막으면 후속타 지속

### 6.2 금강호체공 — 금강가세

```yaml

technique_id: vajra_guard
slots: 1
cost: {stamina: 1, internal: 1}
target: self
```

검증:

- 방어도5와 강건1을 함께 부여
- 방어도는 매 피해 단위에 적용되지만 자원 자체는 감소하지 않음
- 강건은 유효 중단 1회만 방지하고 피해·상태·KO를 되돌리지 않음
- 방어도 총합은 10 상한

### 6.3 태극유전검 — 운수회신

- 회피 실패·공격 부재·필중 공격이면 후속 효과 없음
- 후퇴 방향은 적에게서 멀어지는 방향으로 고정
- 경계에서는 가능한 거리까지만 이동

### 6.6 무영십보 — 철각유영


- 경계·점유 시 가능한 거리까지만 이동

## 7. 절초기세와 절초

### 7.1 자원 계약

```yaml
resource_id: ultimate_momentum
display_name: 절초기세
range: 0..5
```

획득:

- 합 승리 시 공격 행동당 전투원별 최대 +1
- 한 연격 행동에서 여러 피해 단위의 합을 이겨도 총 +1
- 사거리 밖 합 승리도 정상 합 승리이므로 +1
- `[준비]`가 적용된 `[명상]` 실행 시 +1
- 상한5 초과 금지

금지:

- 묶음 시작 자동 +1 금지
- 막기 성공 자동 +1 금지
- 회피 성공 자동 +1 금지
- 단독 `기세`라는 이름 금지
- 기력·내력과 합쳐서 표시 금지

### 7.2 예약·환불

- 절초는 별도 `[절초]` 탭에서 선택한다.
- 기세5와 필요한 연속 빈 슬롯이 모두 있어야 배치 가능하다.
- 배치 성공 즉시 기세5를 예약·차감한다.
- 배치 실패 시 계획과 기세를 변경하지 않는다.
- 진행 전 제거하면 기세5를 환불한다.
- 진행 전 다른 유효 위치로 이동하면 기존 예약을 환불하고 새 위치에 재예약한다.
- 묶음 확정 뒤 중단·사거리 실패·방향 실패에는 환불하지 않는다.

### 7.3 PoC에서 사용할 기본 절초

여섯 무공의 10성 고유 절초는 아직 미승인이므로 임의 제작하지 않는다. 절초기세 획득·예약·환불·실행을 검증하기 위해 현행 런타임의 기본 절초 3종만 별도 `LEGACY_SYSTEM_FIXTURE`로 제공한다.

| ID | 이름 | 슬롯 | 역할 |
|---|---|---:|---|
| `ultimate_ten_paces_wave` | 십보 유파 | 1 | 전진 후 근거리 속공 절초 |
| `ultimate_cleave_peak` | 단악결 | 2 | 거리2 중량 절초 |
| `ultimate_void_sword_qi` | 파공검기 | 3 | 거리3 필중 절초 |

- 기존 런타임의 고정 공격력8 기반 수치를 그대로 테스트 fixture로 사용한다.
- 절초 수치·밸런스는 기술1 PASS/FAIL과 분리한다.
- 결과 화면에는 `절초기세 시스템: PASS/FAIL`과 `기본 절초 fixture: LEGACY`를 명확히 구분한다.

## 8. 계획·관찰·AI

### 8.1 묶음 순서

```text
직전 묶음 종료 상태 정산
→ AI가 공개 상태만으로 현재 묶음 계획 확정·잠금
→ 보유 관찰량만큼 앞 수의 행동 종류 공개
→ 플레이어가 현재 묶음 계획
→ 플레이어 확정
→ 양측 해결
→ 묶음 복기
```

AI는 미래 묶음을 미리 생성하지 않는다. 관찰 공개 뒤 현재 묶음을 교체하지 않는다.

### 8.2 관찰

- 플레이어 `[관찰]` 1회는 관찰량1 획득
- 다음에 AI가 확정하는 묶음의 앞 수부터 사용
- 공개·저장 상한 없음
- 남은 양은 묶음·라운드 경계를 넘어 이월
- 공개 태그: `[전조]`, `[이동]`, `[공격]`, `[방어]`, `[회피]`, `[준비]`, `[자원]`, `[관찰]`
- 복합 기술은 `[이동+공격]`처럼 실제 종류를 모두 표시
- 기술명·무공서명·정확한 비용·방향·거리·피해·대상·AI 가중치는 숨김
- AI는 관찰 행동을 사용하지 않음

### 8.3 검증형 AI

AI ID는 `public_state_ai_technique1_coverage`로 둔다.

허용 입력:

- 현재 공개 전투 상태
- 자신의 자원·위치·상태
- 양측이 보유한 공개 기술 정보
- 이전에 해결된 행동·결과
- 고정 seed
- 이번 전투에서 아직 충분히 검증되지 않은 자신의 기술 목록

금지 입력:

- 플레이어의 미확정 슬롯
- 플레이어의 미확정 대상·방향
- hover·focus·포인터 위치
- 관찰로 아직 공개되지 않은 현재 계획

행동 정책:

- 불법 행동은 후보에서 제거
- 아직 실행되지 않은 기술1에 범위 내 가중치 추가
- 자원이 부족하면 명상·청심조식 고려
- 거리가 맞지 않으면 이동·보법·철각유영·추풍일섬으로 합법 상태 형성
- 상대 공격 가능성이 높으면 운수회신·금강가세 고려
- 기세5면 기본 절초도 후보에 포함
- 최종 선택은 공개 상태와 seed로 결정

AI는 한 전투에서 모든 기술을 반드시 사용하도록 규칙을 속이지 않는다. 미검증 기술은 `NOT_TESTED`로 남기며 동일 seed 재시작과 새 seed 실행으로 추가 검증한다.

## 9. 판정 엔진 계약

### 9.1 위치·거리

- 타일1~10
- 같은 빈 목적지와 정지 상대 칸 진입 허용
- 같은 타일은 `[밀착]`, 거리0
- 자리 교환·상대 통과·전장 밖 이동 금지
- 공간 부족 잔여 이동은 피해·절초기세·다른 효과로 변환하지 않음

### 9.2 해결 순서

```text
대응 상태 준비
→ 속공 단계·위치 확정
→ 행동 시작 효과
→ 공격 행동별 피해 단위 생성
→ 현재 순번 피해 단위 합
→ 합 승리 효과·절초기세
→ 사거리·방향
→ 회피
→ 방어도 고정 감산
→ 체력 피해
→ ON_HIT·ON_HEALTH_DAMAGE
→ 중단·강건
→ 다음 순번 합 또는 잔여 단독 타격
→ 공격 종료 효과
→ 이동·비공격 행동
```

연출 속도는 판정 결과를 바꾸지 않는다. 모든 UI/VFX/SFX는 엔진이 만든 사건을 소비만 한다.

### 9.3 합·연격

- 같은 수의 양측 유효 공격은 현재 순번 피해 단위끼리 비교
- 높은 피해 단위가 승리하고 차이가 승자의 현재 원피해
- 패자의 현재 피해 단위만 취소
- 동점은 양측 현재 피해 단위만 상쇄
- 양측 체력 피해0, 양측 공격 유지, 양측 다음 피해 단위 존재 시 다음 순번 합
- 한쪽만 남으면 상대 잔여 피해 단위는 단독 해결
- 실제 체력 피해로 공격 행동이 중단되면 미실행 후속타 취소
- 강건이 중단을 막으면 다음 순번을 계속할 수 있음

### 9.4 사거리 밖 합

- 사거리 밖이어도 합 비교는 먼저 진행
- 합 승리·절초기세·`ON_CLASH_WIN`은 정상 발생
- 사거리·방향이 무효면 해당 피해 단위 체력 피해·`ON_HIT`·`ON_HEALTH_DAMAGE`는 발생하지 않음
- 공격들이 유지되면 다음 순번 합 계속

### 9.5 방어·회피·중단

```text
체력 피해 = max(0, 원피해 - 현재 방어도)
```

- 방어도는 피해 단위마다 적용, 피격으로 감소하지 않음
- 회피1은 가장 먼저 도달한 회피 가능 피해 단위1개 제거
- 필중은 회피만 무시하고 합·방어·거리·방향·중단·KO는 무시하지 않음
- 유효 체력 피해가 발생하면 진행 중 공격 행동을 중단
- 강건1은 중단1회만 방지하고 소모
- 체력0이면 남은 피해 단위와 비필수 후속 효과 생략

### 9.6 결착 압력

1~3라운드는 정상 규칙이다. 4라운드 종료부터 세 번째 묶음 정산과 승패 확인 뒤 생존 중인 양측에 동시에 적용한다.

```text
결착 피해 = 최대 체력의 10% + 5 × (라운드 - 3)
```

- 방어·회피·강건을 무시
- 동시 KO: 직전 체력 비율 → 해당 라운드 유효 체력 피해 → 무승부

### 10.2 행동 배치

- 행동 선택 즉시 현재 묶음의 가장 앞 유효 연속 빈 구간에 자동 배치
- 2수 행동은 하나의 연결 블록으로 `[전조]→[실행]` 표시
- 현재 묶음만 편집
- 전체 10수는 항상 표시
- 확정 전 연결 블록 이동·제거 가능
- 무효 Drop은 원래 배치 유지
- 배치 실패는 계획·자원·기세를 변경하지 않고 이유 표시
- 비어 있는 수는 명시적 `[대기]`로 확정 가능
- 대상·방향이 필요한 기초 행동은 확정 전 지정
- 무공 기술의 고정 전진·후퇴·후속 효과는 확정 후 추가 입력 없음
- 확정 뒤 모든 선택 UI 잠금

### 10.3 카드·상세

- 출처: 기초/무공/절초

- 사거리 또는 이동 거리

상세 패널:

- 확정 뒤 예약 상태를 소비 상태로 전환

## 11. 연출·모션·오디오

### 11.1 아트 방향

현재 승인 에셋 방향을 유지한다.

- 수묵 석양의 결투 전장
- 세피아·먹색·절제된 번트 오렌지
- 플레이어: 숯색·청회색·작은 금빛 강조
- AI: 먹색·어두운 적색 강조
- 낮은 대비 배경과 선명한 전투 정보
- 무공 계보는 무기·자세·형태 언어로 구분
- 특정 IP·작가 화풍 표면 복제 금지
- 가짜 한글·장식용 무의미 문자 금지

HTML에서는 승인된 배경·전신 RGBA 캐릭터·절초 먹금 VFX를 재사용하고, 기술1의 세부 궤적·잔상·방어막은 SVG/CSS로 구성한다. 에셋이 로드되지 않아도 도형·텍스트 fallback으로 판정 정보를 유지한다.

### 11.2 사건 기반 연출

엔진은 다음과 같은 불변 사건을 생성한다.

```text
action_start
movement_start / movement_end
telegraph / execute
clash_start / clash_win / clash_tie
range_check / direction_check
evade_success / evade_fail
defense_apply / health_damage
trigger_on_hit / trigger_on_health_damage
interrupt / fortitude_consumed
action_end
momentum_gain / momentum_reserve / momentum_refund / ultimate_use
```

VFX·모션·오디오는 사건 순서를 재생하며 계산을 다시 만들지 않는다.

### 11.3 기술별 모션

#### 유운삼첩

```text
준비 자세
→ 1타 검광·피해 숫자·짧은 hit stop
→ 2타 반대 궤적·개별 합/피해
→ 3타 마무리 궤적·개별 합/피해
→ 자세 복귀
```

- 세 타격을 한 숫자로 합치지 않음
- 후속타 취소 시 남은 궤적을 재생하지 않고 타임라인에 취소선

#### 금강가세

```text
중심을 낮춤
→ 먹금 원형 방어막 확산
→ 방어도 +5
→ 강건 인장 점등
```

- 피해 숫자는 `방어로 감산된 값`과 `체력 피해`를 구분
- 강건 소모 시 인장이 갈라지고 후속타 지속을 표시

#### 운수회신

```text
공격 도달
→ 물 흐르듯 잔상 회피
→ MISS/회피 표시
→ 성공한 경우만 후퇴1
→ 내력 입자가 HUD로 이동
```

- 공격이 없거나 회피 실패면 후퇴·회수 모션 없음

#### 추풍일섬

```text
적 방향 전진1
→ 창을 낮추는 준비
→ 직선 찌르기 궤적
→ 거리·방향 결과
→ 적중/사거리 실패
```

- 전진과 공격을 순간이동 한 번으로 합치지 않음
- 전진 불가 시 경계 피드백 뒤 현재 위치 공격

#### 청심조식

```text
호흡 자세
→ 완만한 원형 파동
→ 기력 +1
→ 내력 +1
→ 방어도 +2
```

- 카드에 이번 묶음 사용 완료 인장 표시
- 최대치 초과분은 회색 `상한` 텍스트로 표시

#### 철각유영

```text
후퇴 1보
→ 잔상
→ 후퇴 2보
→ 잔상·회피 인장 점등
```

- 경계에서는 실제 이동 가능한 보폭만 재생
- 이동0이어도 회피 부여 여부를 별도 사건으로 표시

### 11.4 공통 전투 연출

- 합: 현재 피해 단위 궤적을 중앙에서 충돌
- 합 승리: 승자 쪽 방향성 충격·패자 현재타 소거
- 사거리 밖 합 승리: 궤적이 목표 전 끊기고 `피해0`, 기세 분절은 점등
- 회피: 잔상 + `회피/MISS`, 색만으로 표시하지 않음
- 방어: 방패/원형 아이콘 + 감산 숫자
- 체력 피해: 별도 숫자와 체력바 충격
- 중단: 진행 중 행동 프레임 파열, 미실행 후속타 취소선
- 필중: 회피 아이콘 관통 표시, 합·방어는 정상 재생
- 이동 전후 타일을 도형과 번호로 강조
- 절초: 승인된 먹금 VFX, 일반 기술보다 긴 선행 프레임과 명확한 기세 소비

### 11.5 재생·접근성

- 재생/일시정지
- 사건 한 단계 진행
- 1배속/2배속
- 현재 묶음 연출 건너뛰기
- 모션 감소
- 음소거·볼륨
- 키보드 focus outline
- hover 없이 클릭·포커스로 동일 정보 접근
- 색 외 텍스트·아이콘·형태로 모든 상태 구분

모션 감소 시:

- 카메라 흔들림·긴 잔상·parallax·hit stop 제거
- 위치는 짧은 페이드 또는 즉시 변경
- 핵심 사건 텍스트·아이콘·숫자는 유지

오디오는 합·연격·방어·회피·절초를 구분하지만 음향만으로 정보를 전달하지 않는다.

각 기술은 전투 사건을 기반으로 아래 항목을 판정한다.

```yaml
identity:

  technique_id: MATCH
placement:
  slots: MATCH
  contiguous: MATCH
  telegraph_execute: MATCH
cost:
  paid_at_first_telegraph: MATCH
  stamina: MATCH
  internal: MATCH
formula:
  stat_inputs: MATCH
  packet_values: MATCH
resolution:
  phase: MATCH_OR_POC_MAPPING
  movement: MATCH
  range: MATCH
  hit_count: MATCH
  clash_packets: MATCH
  trigger_conditions: MATCH

  required_events_emitted: MATCH
```

판정 의미:

- `PASS`: 필수 규칙·수치·사건·모션을 모두 확인
- `PARTIAL`: 기술은 정상 실행했지만 조건부 후속 효과를 이번 전투에서 만들지 못함
- `FAIL`: 슬롯·비용·공식·이동·조건·판정·필수 연출 중 하나 이상 불일치
- `NOT_TESTED`: 이번 전투에서 실행되지 않음

### 12.1 기술별 최소 PASS 조건

| 기술 | 최소 조건 |

| 철각유영 | 고정 후퇴 최대2·경계 축소·회피1 |

## 13. 기록·재현

각 전투는 다음을 저장하거나 다운로드할 수 있어야 한다.

- seed
- 초기 상태
- 양측 확정 계획
- 관찰 공개 스냅샷
- 판정 사건 전체
- 프레젠테이션 사건 전체
- 기술별 검증표
- 시스템 검증표
- 최종 원자료: 회피 성공, 합 승리, 플레이어 체력 손실, 라운드 수, 절초 사용 횟수

형식:

- 사람이 읽는 HTML 복기
- 기계 검증용 JSON replay

S/A/B/C 등급은 산식을 임의로 만들지 않고 원자료만 표시한다.

## 14. 구현 구조 원칙

Codex 구현은 빌드 도구 없이 로컬 정적 서버에서 실행되는 단일 페이지 앱으로 만든다.

권장 경계:

```text
web-poc/technique1-validation/
├─ index.html
├─ styles/
├─ src/
│  ├─ data/
│  ├─ engine/
│  ├─ ai/
│  ├─ presentation/
│  ├─ ui/
│  └─ validation/
├─ assets/
└─ tests/
```

- 판정 엔진은 DOM을 참조하지 않는다.
- AI는 플레이어 UI 상태를 참조하지 않는다.
- 프레젠테이션은 판정 사건만 소비한다.
- 검증기는 같은 사건으로 계약 일치 여부를 판정한다.
- 같은 seed·입력 계획은 같은 결과와 사건 순서를 만든다.
- 외부 CDN·상용 라이브러리·네트워크 연결 없이 실행한다.
- 최신 승인 계약을 별도 데이터 모듈로 두고 UI 문자열에 수치를 중복 작성하지 않는다.

## 15. 적대적 검토 결과

### 위험 1: 검증형 AI가 플레이어 계획을 읽어 기술 조건을 억지로 만든다

대응: AI 계획을 플레이어 편집 전에 확정·해시하고, 확정 뒤 변경 시 시스템 `FAIL` 처리한다.

### 위험 2: 여섯 기술을 한 판에 모두 쓰게 하느라 불법 행동을 선택한다

대응: 미검증 기술은 합법 후보 안에서만 가중한다. 사용되지 않은 기술은 정직하게 `NOT_TESTED`로 남긴다.

### 위험 3: 연출 코드가 피해나 위치를 다시 계산해 엔진과 달라진다

대응: 엔진의 사건과 최종 상태만 연출 입력으로 허용한다. 프레젠테이션 레이어는 상태 변경 권한이 없다.

### 위험 4: 기존 Godot의 레거시 절초기세 획득을 그대로 복제한다

대응: 묶음·막기·회피 기세 획득 금지 테스트를 필수화한다.

### 위험 5: 미승인 10성 절초를 임의 설계한다

대응: 기본 절초 3종을 `LEGACY_SYSTEM_FIXTURE`로만 사용하고 무공 고유 절초는 제외한다.

### 위험 6: 기술 검증 화면이 개발자 로그로 과밀해 게임 UX를 평가할 수 없다

대응: 전장·타임라인·행동 선택을 우선 배치하고 검증표는 접을 수 있는 하단 패널로 둔다.

### 위험 7: 모션이 화려하지만 규칙을 이해하기 어렵다

대응: 모든 모션에 텍스트·아이콘·타임라인 상태를 병기하고 모션 감소에서도 정보가 동일하게 남도록 한다.

### 위험 8: 기술1과 시스템 전체를 한꺼번에 구현해 원인 추적이 어렵다

대응: 테스트는 판정 엔진 → 기초 시스템 → 기술별 계약 → AI → UX → 프레젠테이션 순서로 층을 분리한다.

## 16. 완료 기준

PoC는 다음 조건을 모두 만족해야 완료로 판정한다.

1. 브라우저에서 플레이어 대 공개 상태 기반 AI 전투를 시작하고 종료할 수 있다.
2. 양측이 여섯 기술1과 허용된 기초 행동·기본 절초를 합법적으로 사용할 수 있다.
3. 전체 10수와 현재 3/3/4 묶음이 동시에 보인다.
4. 관찰·AI 잠금·복기에서 미확정 계획 누출이 없다.
5. 여섯 기술의 공식·비용·슬롯·고정 이동·조건이 데이터 계약과 일치한다.
6. 순차 합·사거리 밖 합·방어·회피·중단·강건이 기술 사건과 연결된다.
7. 절초기세가 승인된 경로로만 증가하고 예약·환불·확정 규칙을 지킨다.
8. 각 기술의 필수 모션과 모션 감소 fallback이 있다.
9. 기술별 `PASS/PARTIAL/FAIL/NOT_TESTED` 근거를 확인할 수 있다.
10. 같은 seed와 계획으로 결과를 재현하고 JSON replay를 내보낼 수 있다.
11. 자동 테스트가 최신 기획과 확인된 레거시 충돌을 보호한다.
12. 실제 사람 검증 전에는 재미·가독성·접근성을 `PASS`로 주장하지 않는다.

## 17. 구현 후 별도 사람 검증

- 여섯 기술의 역할 차이를 모션만 보고 구분할 수 있는가
- 유운삼첩의 세 타격과 순차 합을 이해하는가
- 방어도 비소모와 강건 소모를 구분하는가
- 운수회신의 후속 효과가 회피 성공 조건임을 이해하는가
- 추풍일섬의 전진→공격 순서를 이해하는가
- 청심조식의 묶음당 제한을 이해하는가
- 철각유영의 경계 축소 이동을 이해하는가
- 사거리 밖 합 승리의 `합 승리지만 피해0`를 납득하는가
- 절초기세 획득·예약·환불을 설명할 수 있는가
- 모션 감소 모드에서도 같은 판정 정보를 얻는가

자동 테스트 통과는 위 사람 이해도와 전투 재미를 증명하지 않는다.
