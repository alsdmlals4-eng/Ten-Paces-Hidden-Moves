# 십보강호 행동 선택 Dock 제품 UX 설계

> Spec ID: `TEN-SIT-SPEC-20260801-ACTION-SELECTION-DOCK-01`  
> Decision dependency: `TEN-DEC-20260801-MARTIAL-TECHNIQUE-UX-01`  
> Status: `IMPLEMENTED_BUILD_PR_VALIDATION_PENDING`  
> Runtime authority: `IMPLEMENTATION_CONTRACT`  
> Work mode: `BUILD`

## 1. 목적

현재 Godot 전투 PoC가 이미 구현한 다음 기능을 보존하면서 제품용 행동 선택 계층을 추가한다.

- 1대1 10칸 전장
- 라운드 `3/3/4` 수 타임라인
- 현재 묶음만 편집
- 기초카드 8종
- 선택 즉시 가장 앞의 유효 연속 수에 자동 배치
- 이동 목적지·공격 방향 지정
- 다중 수 행동의 연속 점유
- 절초기세 5 예약과 진행 전 취소 환불
- 카드 상세·로그·복기

제품 UX는 기존 평면 `BasicCardTray`와 독립 절초 목록을 다음 계층으로 재구성한다.

```text
행동 선택
├─ 기초
├─ 무공
│  └─ 무공서 → 해금 기술
└─ 절초
```

이 Spec은 행동 선택과 수 배치 표현을 정의한다. 전투 판정 수치, 무공 밸런스, 강호행로, 저장·회차 구조는 변경하지 않는다.

## 2. 기준 구현

### 2.1 현재 실행 진입점

- `project.godot`
- `res://scenes/combat/combat_board_preview.tscn`
- `res://src/combat/combat_board_preview_auto.gd`

현재 Scene은 `CombatBoardPreview`를 루트로 사용하고 Script가 HUD·전장·수 타임라인·기초카드·절초·상세·로그·복기 컴포넌트를 동적으로 조립한다.

### 2.2 재사용 대상

| 기존 요소 | 판정 | 제품 처리 |
|---|---|---|
| `ActionTimingPanel` | 유지 | 전체 10수와 현재 묶음 편집 기반 |
| `ActionTimingSlot` | 수정 | 다중 수를 하나의 연결 블록으로 표현 |
| `BasicCardTray` | 유지·축소 | `기초` 패널의 8종 행동 공급자 |
| 자동 배치 함수 | 유지·공용화 | 세 행동 출처가 동일 경로 사용 |
| 절초 예약·환불 | 유지 | `절초` 패널로 이동 |
| `CardDetailPanel` | 유지·확장 | `ActionDetailPanel` 역할로 확장 |
| `CombatBoardPreview` | 점진 분리 | UI 조립 책임을 `ActionSelectionDock`으로 이관 |
| `태세+대응` 가상 카드 | 제품 P0 제외 | `[준비]` 독립 행동으로 정리 |

## 3. 정보 구조

```text
ActionSelectionDock
├─ ActionSourceTabs
│  ├─ BASIC
│  ├─ MARTIAL
│  └─ ULTIMATE
├─ BasicActionPanel
├─ MartialActionPanel
│  ├─ OwnedManualList
│  └─ UnlockedTechniqueList
├─ UltimateActionPanel
└─ ActionDetailPanel
```

세 출처는 다른 탐색 구조를 가지지만, 선택 이후 동일한 배치 Controller를 사용한다.

```text
행동 선택
→ 가장 앞 유효 연속 수 탐색
→ 배치
→ 대상·방향 지정
→ 자원·조건 검증
→ 진행 전 제거·재배치
→ 진행 후 잠금
```

## 4. 화면 배치

```text
┌──────────────────────────────────────────────────────────────┐
│ 양측 상태 · 절초기세 · 라운드/현재 묶음                    │
├──────────────────────────────────────────────────────────────┤
│                    1대1 10칸 전장                            │
├──────────────────────────────────────────────────────────────┤
│ 전체 10수 및 현재 묶음 확대 편집                  [진행]    │
├──────────────────────────────────────────────────────────────┤
│ [기초] [무공] [절초]                                         │
├──────────────────────────────────────────────────────────────┤
│ 선택 출처 콘텐츠                              행동 상세      │
└──────────────────────────────────────────────────────────────┘
```

### 4.1 원칙

- 타임라인은 행동 선택 Dock보다 위에 둔다.
- 중앙 전장 크기를 줄이지 않는다.
- 상세 패널은 전장을 상시 가리지 않는다.
- 탭 전환은 이미 배치한 계획을 변경하지 않는다.
- 대상 선택 중에는 다른 행동 선택과 탭 전환을 잠근다.

## 5. ActionSourceTabs

### 5.1 탭

```text
[기초] [무공] [절초]
```

### 5.2 상태

- 새 전투 진입: `기초`
- 같은 전투의 다음 묶음: 마지막 탭 유지
- 해결·복기 중: 비활성
- 대상 지정 중: 비활성
- 계획 확정 후: 비활성

### 5.3 접근성

- 텍스트와 아이콘을 함께 사용한다.
- 색만으로 선택 상태를 구분하지 않는다.
- 키보드·게임패드 Focus가 탭 → 목록 → 상세 → 타임라인 → 진행 순서로 예측 가능해야 한다.

## 7. 무공 패널

### 7.1 선택 흐름

```text
보유 무공서 선택
→ 해당 무공서의 해금 기술 표시
→ 기술 선택
→ 자동 배치
```

무공서 자체는 수 슬롯에 배치할 수 없다.

### 7.2 보유 무공서 목록

첫 PoC는 시작 무공서 4권을 한 화면에 모두 표시한다.

무공서 항목 최소 정보:

- 무공서명
- 현재 성급
- 대표 역할 또는 계통
- 해금 기술 수
- 절초 해금 여부
- 현재 선택 상태

### 7.3 기술 목록

해금 기술은 선택 가능 상태로 표시한다.

기술 항목 최소 정보:

- 기술명
- 수 점유
- 전조→실행 구조
- 기력·내력
- 사거리
- 연격·이동·필중 등 핵심 태그 최대 2개

### 7.4 잠긴 기술

잠긴 기술은 선택할 수 없지만 다음 성장 목표를 보여준다.

- 기술명
- 해금 성급
- 현재 성급

효과 전문은 기본 목록에 표시하지 않는다.

### 7.5 성급 계보

상세 패널에서만 전체 계보를 표시한다.

```text
1성 패시브
3성 기술 1
5성 기술 1 강화
7성 기술 2
9성 기술 2 강화
10성 절초 또는 진의
```

## 8. 절초 패널

### 8.1 구성

- 기본 절초 3종
- 무공서 10성 해금 절초
- 공유 절초기세 `0~5`

### 8.2 상태

| 상태 | 표현 |
|---|---|
| 사용 가능 | 정상 선택 가능 |
| 기세 부족 | `현재/필요` 표시, 선택 불가 |
| 성급 잠금 | 해금 성급·현재 성급 표시 |
| 예약됨 | 예약 수 범위와 임시 차감 표시 |
| 확정됨 | 편집 불가·환불 불가 |

### 8.3 예약 계약

- 선택 및 배치 성공 시 기세 5 예약
- 진행 전 배치 제거 시 기세 5 반환
- 묶음 확정 이후 환불 없음
- 배치 실패 시 기세를 변경하지 않음

## 9. 자동 배치

### 9.1 기본 규칙

세 출처의 행동은 선택 즉시 현재 묶음에서 가장 앞의 유효 연속 빈 수에 배치한다.

```text
1수 행동 → 첫 빈 수
2수 행동 → 첫 연속 빈 수 2개
3수 행동 → 첫 연속 빈 수 3개
```

### 9.2 실패 규칙

배치 실패 시:

- 기존 계획 유지
- 자원·절초기세 유지
- 선택 상태 해제
- 실패 원인을 로그와 토스트에 표시

오류 코드 예:

- `NO_CONTIGUOUS_TIMINGS`
- `MOMENTUM_INSUFFICIENT`
- `CURRENT_BUNDLE_LOCKED`
- `TARGETING_IN_PROGRESS`

## 10. 자동 배치 후 재배치

### 10.1 P0 기본

배치된 행동은 진행 전 연결 블록 단위로 이동할 수 있다.

### 10.2 마우스

- 행동 블록 Drag
- 유효 연속 범위 강조
- 유효 범위 Drop 시 이동
- 무효 Drop 시 원위치 복귀

### 10.3 키보드·게임패드

행동 블록 선택 후 다음 명령을 제공한다.

- 한 수 앞
- 한 수 뒤
- 제거

### 10.4 제한

- 묶음 경계 통과 금지
- 다른 행동과 중첩 금지
- 과거 수 이동 금지
- 대상 지정 중 이동 금지
- 확정 이후 이동 금지

재배치 후 자원·대상·절초 예약을 다시 검증한다.

## 11. 다중 수 행동 표시

다중 수 행동은 여러 장의 중복 카드가 아니라 하나의 연결 블록이다.

```text
┌──────────── 유운삼첩 ────────────┐
│ 5수 · 전조   →   6수 · 실행      │
└───────────────────────────────────┘
```

### 11.1 표시 규칙

- 하나의 외곽선
- 시작 수에 기술명과 출처
- 중간 수에 `[전조]`
- 마지막 수에 `[실행]`
- 블록 전체 Hover·Focus·Drag
- 블록 일부 제거 금지

### 11.2 용어

- 기초 행동 `[준비]`: 독립 행동 이름
- 다중 수 행동 선행 점유: `[전조]`

두 용어를 혼용하지 않는다.

## 13. `[준비]+대응` 가상 카드

제품 P0에서는 `태세+막기`, `태세+회피` 같은 가상 카드 생성을 사용하지 않는다.

- `[준비]`는 독립적인 1수 행동으로 유지
- 후속 비이동 행동이 준비 상태를 소비
- 강화된 막기·회피가 필요하면 판정 상태로 처리
- 한 수에 두 행동을 합치는 예외 UX를 만들지 않음

기존 PoC의 가상 조합 코드는 제품 경로에서 비활성화하되, 구현 계획 단계에서 회귀 테스트에 미치는 영향을 별도 확인한다.

## 14. 상태 전환

```text
PLANNING
→ ACTION_SOURCE_SELECTED
→ ACTION_SELECTED
→ AUTO_PLACED
→ TARGETING(optional)
→ PLAN_VALIDATED
→ COMMITTED
→ RESOLVING
→ REVIEW
→ NEXT_BUNDLE_READY 또는 COMBAT_ENDED
```

### 14.1 잠금 규칙

- `TARGETING`: 다른 행동 선택 잠금
- `COMMITTED`: 모든 편집 잠금
- `RESOLVING`: Dock 숨김 또는 비활성
- `REVIEW`: Dock 비활성
- `NEXT_BUNDLE_READY`: 마지막 탭과 무공서 선택 복원

## 16. 접근성·입력

- 마우스 없이 전체 기능 사용 가능
- Drag 없이 재배치 가능
- 색만으로 상태를 전달하지 않음
- 최소 44px 상호작용 크기 권장
- 긴 기술명 2줄 허용
- 1280×800과 1440×900에서 스크롤 없는 기초 패널 보장
- 화면 읽기용 이름에 출처·잠금·비용 상태 포함
- 모션 감소에서도 선택·배치·예약 피드백 유지

## 17. 오류 처리

### 17.1 사용자 오류

- 연속 수 부족
- 기세 부족
- 자원 부족
- 대상 미지정
- 잠긴 기술 선택
- 확정 후 편집 시도

각 오류는:

1. 해당 항목 상태
2. 타임라인 또는 Dock 요약
3. 로그

세 위치 중 최소 두 곳에 표시한다.

### 17.2 데이터 오류

- 무공서가 있으나 해금 기술 목록 없음
- 기술에 `action_slots` 없음
- 잠금 사유 없음
- 절초인데 기세 비용 없음

데이터 오류는 사용자에게 빈 카드로 노출하지 않고 개발 로그와 fallback 문구를 사용한다.

## 19. 테스트 계약

### 19.1 구조

- 전투 진입 시 `기초` 활성
- 다음 묶음에서 마지막 탭 유지
- 기초 8종 모두 접근 가능

- 잠긴 기술은 선택 불가

### 19.2 배치

- 1수 행동 가장 앞 배치
- 2수·3수 연속 범위 배치
- 연속 수 부족 시 계획 불변
- 재배치 성공·실패
- 다중 수 일부 제거 금지
- 묶음 경계 통과 금지

### 19.3 절초

- 기세 5일 때 예약
- 기세 부족 시 선택 불가
- 진행 전 제거 시 환불
- 진행 후 환불 불가
- 배치 실패 시 기세 불변

### 19.4 접근성

- 키보드 전용
- 게임패드 전용
- Drag 없는 재배치
- Focus 순서
- 화면 읽기 이름
- 색각 비의존 상태 판독
- 모션 감소

### 19.5 회귀

## 20. 완료 기준

- 플레이어가 `기초 / 무공 / 절초` 출처를 즉시 구분한다.
- 무공서와 실제 배치 기술의 관계를 혼동하지 않는다.
- 2수·3수 기술이 하나의 행동으로 보인다.
- 자동 배치 위치와 실패 원인을 이해할 수 있다.
- 마우스 Drag 없이도 재배치할 수 있다.
- 절초기세 예약·환불 상태를 오해하지 않는다.
- 기존 Godot PoC 판정과 복기 결과를 변경하지 않는다.
