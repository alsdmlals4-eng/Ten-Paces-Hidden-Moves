## 2. 현행 전투 계약과 연결 원칙

- 전투 행동은 `기초 행동 + 현재 해금된 무공 기술`로 구성한다.
- 무공서 자체를 전투 수에 배치하지 않는다.
- 기술은 전술 역할·구조와 비용·고정 효과·능력치 연결·5/9성 patch를 분리한다.
- 모든 기술이 주·보조 능력치를 자동으로 동시에 배수에 사용하는 것은 아니다.
- 주 능력치는 기술의 핵심 효과에 연결한다.
- 보조 능력치는 주 효과와 구분되는 보조 효과가 있을 때만 선택적으로 연결한다.
- 같은 `effect_id` 또는 같은 결과값에 주·보조 배수를 동시에 더하지 않는다.
- 이동거리·사거리·관찰량·행동 슬롯·타격 횟수·회피 횟수·전조 수 같은 구조값은 능력치 1점마다 연속 증가하지 않는다.
- 성장 수치는 거리·순서·대응·자원 계획을 확장해야 하며 잘못된 계획을 자동으로 구제하면 안 된다.

공용 필드:

```text
action_slots
stamina_cost
internal_cost
range
move_range
hits
effects
sure_hit
category
resolution_phase
targeting_mode
skill_milestone
```

효과 scope는 `PER_HIT|ONCE_PER_ACTION`, trigger는 `ON_ACTION_START|ON_ACTION_RESOLVE|ON_CLASH_WIN|ON_EVADE_SUCCESS|ON_HIT|ON_HEALTH_DAMAGE|ON_ACTION_END` 중 하나를 명시한다.

## 4. 장기 보유 구조 가설

- 한 회차에 여러 무공을 익힐 수 있다.
- 해금 기술은 덱·손패·장착 제한 없이 사용 후보다.
- 배운 무공 수의 하드캡보다 수련포인트·회차 길이·해금 요구치로 실제 기술 수를 제한한다.
- 정확한 장기 보유 한도는 T1 이후 결정한다.
- 중복 습득은 같은 무공 지정 수련으로 변환하고 성취 보너스를 재지급하지 않는다.
- 영구 메타 해금은 시작 선택지·도감·서사·외형·편의 중심이며 회차 전투 스테이터스를 그대로 보존하지 않는다.

## 6. 시작 규칙과 영구 스테이터스

```text
기본 2 × 5종 = 10
+ 자유 분배 6 = 16
+ 선택 시작 무공 4개의 2성 주 능력치 +1 = 20
```

- 최종 시작 총합20·평균4다.
- 직접 분배 단계의 각 능력치는2~6이며 이후 무공 보너스는6에서 잘리지 않는다.
- 후보6개 중4개를3성으로 선택한다.
- `[추천 배분]`은 네 첫 기술의 최소 해금 기준선을 보여주되 강제하지 않는다.
- 일부 기술을 잠근 전문화 배분은 경고 뒤 허용한다.

| 능력치 | 역할 |
|---|---|
| 외공 `EXTERNAL` | 외가 공격·강공·무기 위력·방어 파괴 |
| 근골 `CONSTITUTION` | 최대 체력·방어도·강건·버티기 |
| 신법 `MOVEMENT` | 이동·보법·회피·위치 조정 |
| 내공 `INTERNAL` | 최대 내력·내가 효과·호신·회복 |
| 심안 `INSIGHT` | 관찰·간파·반격·전조 대응 |

핵심 스테이터스에는 디자인 하드캡이 없다. 기존1~15는 초기 검증 구간이며 합법적인15 초과값을 절단·소실·재분배하지 않는다. 실제 영구값을 요구치와 공식에 사용한다.

## 8. 기본 절초·10성 절초·진의

- 공용 절초 3종은 기술 계보 보존 대상으로 무공 성급과 독립적으로 시작부터 사용 후보다.
- 10성 보상은 해당 무공의 고유 `[절초]`다.
- 10성 절초는 해당 무공의 주 영구 능력치12를 요구한다.
- 보조 요구는 없고 임시 능력치는 해금 판정에 사용하지 않는다.
- 미달 시 절초만 `LOCKED_STAT_REQUIREMENT`가 되며 무공서·기존 패시브·기술·성장 보너스는 유지한다.
- 영구 주 능력치12 도달 시 추가 비용 없이 자동 활성화한다.
- 한번 활성화된 절초는 전투 중 임시 감소로 다시 잠기지 않는다.
- 과거 `진의` 선택 구조는 사용하지 않는다.
- 각 무공 고유 절초의 실제 효과·행동 수·자원·효과 예산은 별도 승인 전 `TBD`다.

## 9. 습득·중복·저장 계약

- 시작 선택 무공과 회차 중 신규 습득 무공은3성으로 시작한다.
- 1성 패시브와2성 주+1은 회차당 최초 1회만 적용한다.
- 이미 보유한 무공의3성 습득 보상은 같은 무공 지정 수련10으로 변환한다.
- 중복 습득·저장 재로드·수련 변환으로 성취 보너스를 재지급하지 않는다.
- idempotent 키는 `회차ID + 무공ID + 성취 milestone`이다.
- 각3·5·7·9·10성 전환점은 안정 필드 `skill_milestone`으로 기록한다.

## 10. 기술 역할·배수·성취 patch 계약

기술 작성 순서:

```text
전술 역할·대응 관계
→ 행동 구조·비용
→ 고정 효과
→ 주 능력치 핵심 효과
→ 선택적 보조 능력치의 구분된 효과
→ 5성 역할 강화
→ 9성 수읽기 조건부 분기
```

공통 규칙:

- 기술 하나의 능력치 참조는 주1종과 선택적 보조1종, 최대2종이다.
- 주 능력치는 기술의 핵심 효과에 연결한다.
- 보조 능력치는 주 효과와 다른 `effect_id`가 있을 때만 연결한다.
- 같은 효과·같은 출력값에 주·보조 계수를 동시에 적용하지 않는다.
- 보조 효과가 필요하지 않으면 보조 배수를 생략한다.
- 피해·방어·호신·회복·자원 회복량은 연속 배수 후보가 될 수 있다.
- 이동거리·사거리·관찰량·행동 슬롯·타격 횟수·회피 횟수·합/중단/반격 허용·확정 명중·비용 면제는 임계·성취 전용이다.
- 구조값은 능력치 1점마다 연속 증가하지 않는다.
- 슬롯 기술 예산은1수20틱·2수50틱·3수80틱, 기본 허용 편차는±5틱이다.
- 최대 사거리 총비용은 사거리1=0틱·2=10틱·3=25틱·4=40틱이다.
- 배수 기준 스테이터스는4, 작성 단위는0.25다.

## 11. `[의료]`와 중간 노드

`[의료]`는 회복·상태 안정·장기 체력 관리 역할이다. 영구 능력치와 수련포인트 공급을 자동으로 겸하지 않는다.

중간 노드 보상은 회복·수련포인트·영구 스테이터스·상대 정보·사건·재화를 분리한다.

영구 스테이터스 노드 계약:

- 데모 회차 중 최대2개 보상 기회.
- 같은 구간에는 최대1개만 제시.
- 각 노드는 서로 다른 핵심 능력치2종을 공개하고 플레이어가1종을 골라 +1.
- 제시 후보는 현재 빌드의 기술 요구치와 다음 상대의 공개 위협을 함께 참고하되 비공개 계획·AI 가중치를 사용하지 않음.
- +1은 현재 회차의 실제 영구 능력치로 즉시 적용되며 3·7·10성 요구치와 승인 공식에 사용.
- 회차 종료 시 초기화하며 메타 영구 성장으로 이월하지 않음.
- 회복·수련·추가 정보·재화를 자동으로 함께 지급하지 않음.
- 보상 적용 키는 `run_id + gap_index + node_id + reward_instance_id`이며 저장 재로드로 재지급하지 않음.

책임 Decision은 `TEN-DEC-20260803-INTERMEDIATE-NODE-PERMANENT-STAT-REWARDS-01`이다.

## 13. 검증 기준

1. 시작 총합이 모든 4무공 조합에서20인지 확인한다.
2. 2·4·6·8성 지급이 최초 1회만 적용되는지 확인한다.
3. 3/7/10성 요구가 각각 주4/8/12인지 확인한다.
4. 보조 능력치나 임시 버프가 해금 요구로 오인되지 않는지 확인한다.
5. 잠금 상태에서도 무공 수련과 기존 보상이 보존되는지 확인한다.
6. 영구 요구치 충족 시 추가 비용 없이 자동 활성화되는지 확인한다.
7. 무공별 주·보조 벡터와 planning JSON이 일치하는지 확인한다.
8. 데모 회차에서 노드 영구 스테이터스 총합이 +2를 넘지 않는지 확인한다.
9. 노드마다 두 능력치 중 하나만 지급하고 저장 재로드로 중복 지급하지 않는지 확인한다.
10. 노드 선택지가 비공개 적 계획을 사용하지 않고 경로 확정 전에 공개되는지 확인한다.
11. 모든 기술에 주·보조 배수가 자동 적용되지 않는지 확인한다.
12. 같은 효과에 주·보조 계수가 중복되지 않는지 확인한다.
13. 이동거리·사거리·관찰량·행동 슬롯·타격/회피 횟수가 점당 연속 증가하지 않는지 확인한다.
14. 기술2가 기술1을 전 상황에서 대체하지 않는지 확인한다.
15. 5성 patch가 새 역할이나 무조건 피해 증가만 추가하지 않는지 확인한다.
16. 9성 patch가 공개 정보에 기반한 수읽기 조건을 요구하는지 확인한다.
17. 능력치4·15·현재 합법 최대값에서 잘못된 계획 구제율을 사람 검증한다.
18. 영구 스테이터스 노드 선택률이 다른 노드를 지배하지 않는지 사람 검증한다.
19. 같은 Schema로 두 번째 무공·기술을 반복 제작할 수 있는지 확인한다.
20. 실행하지 않은 Godot·Windows·접근성·사람 검증은 `NOT_RUN`으로 유지한다.

자동·정적 검증은 실제 Windows Godot·접근성·성능·사람 플레이를 대체하지 않는다.
