# 현재 화면 흐름 · 출사표와 10초 행동 설계

책임: 현재 화면의 진입·선택·복귀를 설명하는 사람용 owner. 규칙과 문구의 원본은 [승인 결정](../decisions/2026-09-25_FRAME_TIMELINE_AND_PROLOGUE.md), [시간 데이터](../../data/combat/frame_timeline.json), [도입 데이터](../../data/run/frame_intro.json)이다. HTML은 이 원본과 실제 파일에서 파생한다.

새 게임은 **메인 → 출사표 → 삽화 시작 무공 → 규칙 익히기 → 첫 비전투 행로 → 비무 브리핑 → 행동 설계 → 전투 진행 → 비무 결과**로 이어진다. 결과에서 복기를 따로 열 수 있다. 시작 무공은 후보 6권 중 4권을 각 3성으로 선택한다. 첫 행로는 사건 1회이며 이후의 비무·성장·행로 자료는 기존 구조를 재사용한다.

| 화면 | 사람이 확인하고 선택하는 내용 | 다음 흐름 |
|---|---|---|
| 메인 | 새 게임, 이어하기, 도감, 설정, 종료 | 새 게임은 출사표 |
| 출사표 | 주인공이 강호로 나서는 이유와 첫 목표 | 시작 무공 |
| 시작 무공 | 삽화·기술·효과를 보고 6권 중 4권 선택 | 규칙 익히기 |
| 규칙 익히기 | 10초 시간축, 선딜·발동·후딜, 관찰과 배치 연습 | 첫 행로 |
| 첫 행로 | 상황과 능력치 판정 또는 안전 선택 | 결과 적용 후 브리핑 |
| 브리핑 | 내 상태, 대치, 공개 상대 정보와 삽화 제약 | 전투 준비 |
| 행동 설계 | 현재 해금 기술을 시간축에 배치·수정·확정 | 전투 진행 |
| 전투 진행 | 같은 사건의 인물 동작·먹 효과·시간축과 큰 결과 표시 | 다음 10초 또는 비무 결과 |
| 비무 결과 | 승패, 실제 지급 결과, 계속·종료 | 복기 또는 다음 행로 |
| 복기 | 이미 해결된 사건을 다시 읽기 | 결과로 복귀 |

한 계획 창은 10초, 100논리 틱이며 한 눈금은 0.1초다. 렌더링 프레임과 논리 틱은 별개다. 선딜은 준비, 발동은 효과가 실제로 유효한 구간, 후딜은 마무리다. 같은 인물의 동작은 겹치지 않으며 창을 넘어 남은 동작은 다음 창으로 이어진다. 시간과 자원 비용은 서로 다른 값이다.

관찰은 **동작 완료 시점부터** 1단계 3초, 2단계 6초, 3단계 9초의 확정된 적 행동만 확인한다. 적은 플레이어의 편집 중 계획을 읽지 않고 먼저 확정하며 관찰 뒤 잠긴 계획을 바꾸지 않는다. 확인 범위 밖은 미확인이다. 결과 재생은 판정과 보상을 다시 실행하지 않는다.

그림은 세 역할로 구분한다. `evidence/frame-approved/`의 7개 파일은 승인한 화면 배치 참고이며 박힌 글자·수치·버튼은 실제 게임의 상태가 아니다. `assets/ui/ink_frame/`의 3개 배경은 인터페이스를 제거한 그림 레이어이고 실제 상태·조작은 게임 UI가 표시한다. `evidence/frame-runtime-20260925/`에는 촬영 확인서 `capture-receipt.json`의 PASS와 개별 파일 해시가 일치하는 실제 실행 캡처만 연결한다. 파일만 있는 화면은 `CAPTURE_PENDING_VALIDATION`, 없는 화면은 `NOT_RUN`이다. 첫 행로는 `first_journey.png`, 후속 노드 행로는 `journey.png`로 나눈다. 정지 화면의 존재를 완주·재미·Android·출시 검증으로 확대하지 않는다.

현재 진행 영상은 같은 폴더의 `walkthrough.mp4`를 사용하며 `clip-receipt.json`의 PASS, 지정 경로, SHA256, 유효한 재생 길이를 확인한 뒤 HTML의 현재 영상 영역에 표시한다. 첫 전투 10초는 정상 속도로 읽고 이후 진행 배속은 촬영 기록에서 확인한다. 영상 파일만 있거나 검증 중이면 공개하지 않는다. 이전 슬롯 규칙의 녹화는 별도의 접힌 역사 자료 목록과 기존 링크로 보존한다.

승리와 후속 행로는 `capture-win-receipt.json`의 별도 PASS·파일 해시로 검증한다. 기본 결과·복기는 `victory.png`와 `victory-review.png`, 후속 행로는 실제 JIANGHU 상태의 `journey.png`를 사용한다. 패배 결과·복기와 첫 사건·후속 사건은 각 단계의 추가 화면으로 연결한다. 두 촬영에서 얻은 사례를 한 번의 연속 플레이 기록으로 합치지 않는다.

기존 페이지 ID와 이미지 표시 번호, 사용자 코멘트·폐기 이력은 유지한다. 이전 슬롯 규칙과 촬영·승인 PDF는 역사 자료로 보존하며 새 10초 규칙의 현재 실행 증거로 표시하지 않는다. 기존 저장은 별도 버전 경계와 복구 규칙을 따르고 무검증으로 새 규칙에 변환하지 않는다.
