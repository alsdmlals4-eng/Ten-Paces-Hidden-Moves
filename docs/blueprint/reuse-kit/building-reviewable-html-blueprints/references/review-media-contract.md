# 리뷰·미디어 계약

## 항목 모델

`item_id`는 영구 식별자, `display_number`는 사용자 전달용 번호다. 한 항목에 `kind / subgroup / usage / intent / source_path / source_revision / source_hash / media_kind / review_status`를 연결한다. 이미지가 아닌 기능도 같은 리뷰 구조를 쓸 수 있다. 실제 수치와 규칙은 원본 데이터를 가져오며 HTML에서 다시 계산하지 않는다.

같은 자산과 여러 화면의 사용처를 구별한다. 자산 전체에 관한 코멘트와 “휴식 화면에서 전투 그림이 보임” 같은 사용처 코멘트의 범위를 명시한다. 미검토·수정 요청·승인·폐기 요청과 실제 승인 자산/런타임 연결 상태는 서로 다른 정보다.

## 저장 계약

- 편집은 프로젝트와 항목 ID에 묶는다. 표시 번호·현재 배열 인덱스·일시 포트로 저장 키를 만들지 않는다.
- 입력 즉시 임시 초안, 조합 종료/유휴 후 순차 파일 저장. 성공 응답과 해당 편집 내용이 일치할 때만 초안을 제거한다.
- 응답이 늦게 도착해도 새 입력을 덮지 않는다. 다른 항목 revision 충돌은 최신 상태 확인 후 제한된 재시도, 같은 항목 충돌은 사용자에게 양쪽 내용을 보여준다.
- 오류에도 작성 내용과 스크롤/초점을 유지한다. 실패를 숨기거나 무한 재시도하지 않는다.
- 파일 저장은 원자적 교체와 작업별 잠금, 기존 user review 파일 보호를 고려한다. 새 발행이 리뷰 파일을 초기화해서는 안 된다.
- 배포 예시는 localStorage만 사용하므로 “브라우저에 보관됨”이라고 표시한다. 서버 영구 저장 완료라고 표시하지 않는다.

## 폐기 계약

요청 ID → 실제 경로와 해시 일치 → 기획/코드/동적 로딩/파생 미리보기 사용처 확인 → 권한 범위의 참조 정리 및 삭제/이동 → 누락 링크 재검사 순으로 처리한다. 리포트에는 무엇을 실제 처리했고 무엇이 아직 사용 중인지 기록한다. 미참조라는 추측이나 오래된 파일명만으로 삭제하지 않는다. 사용자의 명시적 삭제와 해당 환경의 안전 규칙을 우선한다.

## 발행·미디어 계약

영구 주소가 필요한지 로컬 미리보기인지 먼저 구별한다. 로컬은 127.0.0.1에만 연결하고 명시적 파일 목록·경로 정규화·해시로 제공 범위를 제한한다. 저장 API는 프로젝트/요청 출처와 revision을 검증한다. 임의 저장소 전체나 비밀 파일을 웹 루트로 노출하지 않는다.

HTML과 manifest는 같은 발행본이어야 한다. 죽은 서버의 주소를 재사용하지 않는다. 링크가 만료됐다면 현재 발행본을 여는 실행 경로로 복구하고 해당 항목의 앵커를 유지한다.

영상은 정상 GET/HEAD, bytes Range 206/416, Content-Type, CSP media-src를 점검한다. GIF는 프레임 수·총 길이·서로 다른 전장 프레임, MP4는 디코딩과 실제 플레이어 currentTime 진행을 확인한다. 글자만 바뀌는 영상으로 전투 움직임을 입증하지 않는다.

## 확인할 상황

1. 목록 아래쪽 항목에 한글 입력 → 다른 칸으로 이동 → 자동 저장 뒤 같은 위치와 내용 유지.
2. 재발행/재정렬/새 포트 후 같은 ID/번호/코멘트 연결; 실제 영구 저장 여부 명시.
3. 저장 실패/오프라인/늦은 응답/동시 탭에서 새 입력 유실 없음.
4. 종류·하위 용도·그림이 일치; 전체 atlas와 특정 셀을 명확하게 구별.
5. 원본 확대, GIF 재생, MP4 일시정지/탐색, 깨진 파일 안내가 실제 동작.
6. 좁은 화면, 키보드 탐색, 긴 한글, 표 내부 스크롤, 모션 줄이기에서 정보 유지.
7. 폐기 요청만 한 파일이 삭제 완료로 보이지 않음; 실제 삭제 후 참조/미리보기/번호 기록 일치.
8. 저장된 HTML에 사용자 코멘트를 넣을 때 textContent/escaping 사용; 입력을 HTML로 실행하지 않음.

검사 항목은 위험에 맞게 고른다. 실제 사람의 가독성·재미 평가를 자동 테스트 PASS에 포함하지 않는다.
