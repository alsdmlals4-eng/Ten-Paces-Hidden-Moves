## 결정

1. 첫 Vertical Slice의 15명 후보는 `5개 기계 슬롯 × 3개 읽기 변주`로 만든다.
2. 후보마다 신규 전투 시스템을 만들지 않는다. 최소 차별화는 `읽을 습관 + 반례/모호성 + 공개 정보 + 짧은 인물성`으로 제한한다.
3. 8개 Route 노드는 기존 `성장/회복 → 정보/대비` 2노드 구조를 유지한다.
4. 정보 노드는 `공개 사실 / 과거 사례 / 정성 습관`만 제공하며 잠금 계획·AI 가중치·정답 대응을 제공하지 않는다.
5. Briefing은 가능성을 좁히고, Combat Review는 발생한 인과를 설명하며, Duel Result는 승패·등급·보상·짧은 캐릭터 반응만 담당한다.
6. Review는 다음 행동을 추천하지 않는다.
7. 반복 인물은 4회 짧게 등장하며 전투보다 강한 서사 축으로 확대하지 않는다.
8. 완주 요약은 결과와 의사결정 흔적을 되돌려주되 플레이 스타일을 AI가 단정하거나 정답 빌드를 추천하지 않는다.

## 벤치마킹 적용

- Yomi: 캐릭터 차이를 상대 성향 읽기와 선택 압력으로 체감시키는 원리 채택.
- Into the Breach: 해결 뒤 인과관계를 명확하게 보여주는 원리 채택.
- Phantom Brigade: 전투 전 비교 가능한 공개 정보와 전투 후 debrief 역할 분리 원리 채택.

복제하지 않는 것:
- 적 미래 행동 완전 공개.
- 카드/덱 구조.
- 확률 기반 정답 추천.

## 적대적 검토

5회 전체 루프 결과:
- 콘텐츠 폭증: 공유 슬롯 + 최소 필드로 차단.
- 튜토리얼 체크리스트화: 후보 습관/반례와 감정 질문으로 완화.
- 정보 정답화: 내부 수치/계획 비공개.
- Route 가짜 선택: 상태·성장·정보 중 실제 변화 필수.
- 비전투 UX 과밀: 화면 시간 예산, Review 1~3건, 반복 인물 4회 제한.

`MUST_FIX_REMAINING: 0` for this planning-detail scope.
